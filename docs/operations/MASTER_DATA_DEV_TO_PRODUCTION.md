# 开发环境业务主数据迁移到正式环境

## 用途

将开发环境中的客户、商品、价格、原料、生产配置和业务基础配置合并到正式环境。开发环境同业务键数据覆盖正式环境，开发独有数据新增，正式独有数据保留。

## 安全边界

- 不迁移订单、库存流水、生产执行、财务、员工权限、登录会话和客户账号绑定。
- 原料库存数量和批次号不会被开发数据覆盖。
- 销售单印章附件不会被开发数据覆盖。
- 客户按名称合并；商品优先按 SKU 编码合并，无 SKU 时按客户、名称和规格组合合并。
- 工具默认是回滚式预演；只有显式增加 `--apply` 才提交。

## 执行顺序

1. 记录两套数据库版本、主数据数量和正式环境排除表数量。
2. 对正式 PostgreSQL 执行完整 `pg_dump -Fc`，保存 SHA-256。
3. 设置 `SOURCE_DATABASE_URL` 和 `TARGET_DATABASE_URL`，运行：

   ```bash
   go run ./cmd/master-data-migrate --report /tmp/master-data-dry-run.json
   ```

4. 检查报告中的新增、覆盖、正式保留、冲突和跳过数量。
5. 预演通过后运行：

   ```bash
   go run ./cmd/master-data-migrate --apply --report /tmp/master-data-apply.json
   ```

6. 回读数量、孤儿引用和排除表摘要，并执行客户、商品、原料、BOM、生产配置和订单选品 API 验证。

## 回滚

发生不可接受结果时，停止写入，保留迁移日志，使用迁移前的自定义格式备份恢复正式数据库。恢复属于全库覆盖操作，执行前必须再次确认备份路径和目标容器。
