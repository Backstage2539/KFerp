# 客户账号类型与客户门户绑定设计

日期：2026-05-12

## 背景

客户岩师傅已在履约运营台绑定 ERP 账号 `13800138065`，账号登录后能进入岩师傅客户页，但客户门户配置未显示该绑定，且账号进入的是“代加工工作台”。这暴露了两个边界混在一起：

- 用户权限页把内部员工角色和客户账号能力放在一起配置。
- 客户门户配置、履约绑定和客户档案的客户类型没有统一约束。

## 目标

- 系统账号区分 `internal_employee` 内部员工和 `channel_customer` 渠道客户账号。
- 用户权限页只给内部员工配置功能权限；渠道客户账号只允许启停和设置/重置密码。
- 用户权限页不再展示“公共SKU代发客户”“代加工客户”这类客户业务角色。
- 客户 ERP 账号绑定移动到客户门户配置页，保存后展示绑定账号名称和手机号。
- 一个客户只能绑定一个 ERP 账号，一个 ERP 账号也只能绑定一个客户。
- 客户档案增加客户类型；历史客户默认 `retail` 零售客户。
- 只有 `wholesale` 批发客户出现在客户门户配置列表。
- `retail` 零售客户和 `ecommerce` 电商客户默认开启商城能力。
- 能力模板新增零售商城模板，允许商城下单和商城内订单记录查看。

## 非目标

- 不重做客户小程序登录流程。
- 不迁移历史订单来源、订单类型或商城商品模型。
- 不移除数据库里历史客户角色种子；本次只保证用户权限界面和新授权逻辑不再依赖它们。

## 数据模型

### customers

新增：

- `customer_type TEXT NOT NULL DEFAULT 'retail'`

合法值：

- `retail`：零售客户，默认开启商城。
- `ecommerce`：电商客户，默认开启商城。
- `wholesale`：批发客户，可进入客户门户配置。

应用层归一化非法值为 `retail`，以保证历史数据和导入数据安全落地。

### company_employees

新增：

- `account_type TEXT NOT NULL DEFAULT 'internal_employee'`

合法值：

- `internal_employee`
- `channel_customer`

历史账号默认内部员工。渠道客户账号不靠员工角色决定客户能力，而是通过一对一客户绑定和客户能力模板决定。

### customer_erp_user_bindings

绑定关系保持在现有表中，但约束升级：

- 每个 `customer_id` 同一时间只能绑定一个账号。
- 每个 `employee_id` 同一时间只能绑定一个客户。
- 绑定接口只允许绑定 `account_type='channel_customer'` 的账号。

## API 合同

客户档案接口返回和接收 `customer_type`。

用户权限账号列表返回 `account_type`，并新增账号类型更新接口：

```json
{
  "employee_id": 123,
  "account_type": "channel_customer"
}
```

客户门户后台列表只返回批发客户，并返回 ERP 绑定摘要：

```json
{
  "id": 149,
  "name": "岩师傅",
  "customer_type": "wholesale",
  "erp_binding": {
    "employee_id": 88,
    "employee_name": "岩师傅",
    "phone": "13800138065",
    "status": "active"
  }
}
```

客户门户后台新增绑定保存接口，语义为“替换当前客户绑定”：

```json
{
  "employee_id": 88,
  "status": "active"
}
```

## 业务规则

- 批发客户：出现在客户门户配置页，由运营选择客户能力模板、主题、首页模式和 ERP 账号绑定。
- 零售/电商客户：不出现在客户门户配置列表，默认启用商城能力与商城首页。
- 内部员工：可以在用户权限页选择功能角色。
- 渠道客户账号：用户权限页不显示角色复选框，只保留账号启停、账号类型和密码操作。
- 客户账号登录后通过 `employee_id -> customer_id` 一对一绑定拿到客户上下文；代发、代加工、商城等入口由客户能力决定。

## 测试计划

- 客户档案 API 创建/更新/读取 `customer_type`，空值默认 `retail`。
- 客户门户后台列表源码和测试保证只取 `wholesale` 客户。
- 零售模板 `retail_mall` 出现在模板 API，并能启用商城下单与订单记录。
- 用户权限角色列表不展示客户业务角色。
- 渠道客户账号只允许密码/启停，不允许角色保存。
- ERP 绑定只接受渠道客户账号，并保证客户与账号一对一。
- 操作手册和验收清单覆盖客户类型、账号类型、门户绑定和零售商城模板。
