# 2026-05-12 消息中心与订单通知设计

## 背景
客户履约运营台需要只选择有履约绑定的批发客户。批发客户通过客户门户提交代发/代加工发货订单后，ERP 运营人员需要在订单列表和客户履约账户中快速找到订单，并收到全局新订单通知。

## 目标
- 全局通知抽象为消息中心底座，统一保存消息事件、渠道投递和 ERP 已读状态。
- 首期支持 ERP 平台顶部通知，预留小程序推送、客户短信推送、ERP 平台推送等渠道扩展。
- 订单列表支持“全部订单 / 我的订单 / 履约客户订单”范围切换。
- 新订单通知点击后进入订单列表，自动切换对应范围并高亮订单。
- 订单行按状态着色：新订单绿色、未生产完成黄色、未发货蓝色、未付款红色。
- 客户履约账户选择客户时，只展示有活跃 ERP 履约绑定的批发客户；客户门户代发订单也进入客户履约账户代发列表。

## 设计
- `message_events` 保存业务事件，使用 `event_key` 支持幂等发布。
- `message_deliveries` 保存渠道投递记录，第一阶段渠道为 `erp_platform`，目标可按权限表达，例如 `orders.read`。
- `message_reads` 保存 ERP 员工已读状态，避免刷新后重复提醒。
- 订单保存、小程序商城下单和客户门户履约下单均发布 `order.created` 事件。
- 通知 payload 携带 `order_id`、`order_no`、`orders_scope` 和 `highlight_order_id`，前端点击后带入订单列表参数。
- 订单查询新增 `scope`：`mine` 按当前员工负责人过滤，`fulfillment` 限定批发客户、活跃 ERP 绑定和客户门户履约来源。
- 客户履约账户代发列表合并导入代发订单和客户门户履约订单，避免客户门户下单后运营台看不到。

## 非目标
- 本次不实现短信网关、小程序模板消息或第三方推送供应商，只保留渠道模型和投递表。
- 本次不做复杂个人订阅偏好，首期按订单读取权限投递 ERP 平台通知。
