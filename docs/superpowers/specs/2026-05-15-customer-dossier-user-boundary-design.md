# 客户档案抽屉与用户边界调整设计

日期：2026-05-15

## 背景

客户档案、员工维护和用户权限目前存在两个问题。

第一，客户档案列表仍以“操作-编辑”作为主入口，编辑表单直接展开在列表上方。进入单个客户后页面底部还会再次出现只包含当前客户的一行列表和编辑入口，信息重复，容易让运营误以为存在第二套客户编辑界面。

第二，系统早期为了支持客户登录，把外部客户账号放进 `company_employees`，并用 `account_type='channel_customer'` 区分。这样导致外部用户同时出现在员工维护、用户权限和客户门户配置附近。产品逻辑已经明确调整为：系统只有内部用户和外部用户两类；内部用户才需要员工维护和用户权限；外部用户如果需要系统访问，统一在履约运营台管理，并通过客户绑定和能力模板决定可见能力。

## 目标

- 客户档案列表去掉“编辑”操作列，客户名称成为打开详情/编辑的主入口。
- 客户详情和编辑使用右侧抽屉弹出，不再把表单展开到列表上方。
- 删除详情底部重复出现的当前客户单行列表/编辑入口。
- 员工维护只维护内部员工，不展示外部用户。
- 用户权限只面向内部用户，不展示外部用户账号类型切换，也不管理外部用户角色。
- 履约运营台成为外部用户账号管理入口，支持外部用户创建、启停、重置密码和绑定履约客户。
- 客户门户配置聚焦客户能力模板、主题、商城/履约能力和 ERP 工作台开放状态；外部账号绑定由履约运营台承接，门户配置只展示绑定摘要或提供跳转入口。

## 非目标

- 本次不立即把 `channel_customer` 从 `company_employees` 迁移到新表。
- 本次不重做登录会话、密码哈希和小程序密码登录底层协议。
- 本次不改变客户能力模板实时引用规则。
- 本次不改变客户履约订单、结算、代发、代加工等业务数据模型。

## 产品模型

### 客户档案

客户档案是业务主体资料，不是系统用户管理入口。

客户档案继续维护客户名、客户类型、公司信息、联系人、电话、地址、默认来源、默认订单类型、启停状态和附件。客户类型仍是业务分类：

- 零售客户
- 电商客户
- 批发客户

客户类型不等于系统用户类型。客户可以没有任何外部登录账号。

### 内部用户

内部用户是企业内部员工，进入后台管理系统工作。

内部用户由员工维护创建和停用。用户权限页只给内部用户分配角色、菜单和 API 权限。内部用户可以是销售、生产、仓库、财务、商品、系统管理员等角色。

### 外部用户

外部用户是客户侧或渠道侧需要进入系统的人。外部用户不属于员工维护，不进入内部用户权限配置。

外部用户如果需要访问系统，由履约运营台创建或绑定账号。外部用户能访问什么，不靠内部角色勾选决定，而靠：

- 绑定的客户
- 客户是否为有效批发履约客户
- 客户能力模板是否开放 ERP 工作台
- 客户模板包含的外部可用页面和权限
- 账号是否启用

## 页面设计

### 客户档案

列表保留搜索、分页、新增客户和刷新。

表格调整：

- 删除“操作”列。
- 客户名渲染为可点击文本按钮。
- 点击客户名打开右侧抽屉。
- 当前行可高亮，但不在列表区域展开编辑表单。

抽屉内容：

- 顶部：客户名称、状态、关闭按钮。
- 基础信息表单：客户名、原始名称、客户类型、公司名称、联系电话、联系人、电话、地址、默认来源、默认订单类型、启用状态。
- 客户概览：订单数、未收款、未发货、生产中、发货中、已完成。
- 附件区：上传标签正面、标签反面、豆袋、挂耳盒、印刷需求，支持删除。
- 底部操作：保存、关闭。

新增客户复用同一个抽屉，标题为“新增客户”。保存成功后保持抽屉打开并切换为编辑状态。

URL 行为：

- `/vue-shell?view=customers&edit_id=123` 自动打开客户抽屉。
- `/vue-shell?view=customers&mode=new` 自动打开新增抽屉。
- 关闭抽屉时移除 `edit_id` 和 `mode`，保留搜索和页码。

### 员工维护

员工维护只展示 `internal_employee`。

新增员工默认创建内部用户。页面不出现外部用户、渠道客户账号或账号类型选择。停用员工继续按现有员工停用逻辑处理。

### 用户权限

用户权限页只加载内部用户。

页面调整：

- 删除“账号类型”列。
- 删除“账号启停/密码”列中用于外部账号的语义混杂说明。
- 保留内部用户登录启停和密码重置能力；如果当前系统仍用同一套登录密码表，页面文案明确为“后台登录账号”。
- 角色勾选只对内部用户开放。
- 角色列表继续隐藏历史客户业务角色。

后端约束：

- `AssignEmployeeRoles` 继续拒绝给外部用户分配角色。
- 用户权限页使用 `/api/auth/internal-accounts`，该接口只返回内部用户。
- 外部账号不会因为历史角色残留获得内部菜单。

### 履约运营台

履约运营台新增“外部用户”管理区。该区与当前选中客户结合工作。

能力：

- 查看当前客户已绑定外部用户。
- 创建外部用户账号，填写名称、手机号、初始密码。
- 绑定已有外部用户到当前客户。
- 启用或停用外部用户登录。
- 重置外部用户密码。
- 解绑或停用当前客户的外部用户绑定。

边界：

- 只有客户为批发客户，且能力模板开放 ERP 工作台时，才允许绑定外部用户。
- 一个外部用户同一时间只能 active 绑定一个客户。
- 一个客户同一时间只保留一个 active ERP 工作台账号，除非后续明确要支持多外部用户。
- 账号停用后，小程序密码登录、客户工作台和履约订单范围都按无有效绑定处理。

第一阶段实现可以继续复用 `company_employees.account_type='channel_customer'` 存储外部账号，但所有外部账号创建、查询、启停和绑定 API 都从履约运营台暴露，不再通过员工维护和用户权限暴露。

### 客户门户配置

客户门户配置继续负责客户级能力：

- 显示名
- 代加工仓库
- 默认寄件人
- 能力模板
- 门户启停
- 模板摘要
- 小程序入口和主题继承

ERP 账号区域调整为绑定摘要：

- 展示当前有效外部用户名称和手机号。
- 如果需要变更，提供带当前 `customer_id` 的“去履约运营台管理”入口。
- 不再从用户权限账号列表中直接选择渠道客户账号。

## API 设计

### 客户档案 API

继续复用：

- `GET /api/customers`
- `GET /api/customers/:id`
- `POST /api/customers`
- `PUT /api/customers/:id`
- `POST /customers/:id/assets/upload`
- `POST /customers/:id/assets/delete`

接口字段不需要新增。前端交互从页面展开表单改为抽屉。

### 内部用户权限 API

新增内部账号列表接口，避免用户权限页继续消费混合账号：

- `GET /api/auth/internal-accounts`

返回 active 内部用户、登录状态、是否已设置密码和当前角色。

`GET /api/auth/accounts` 和 `POST /api/auth/account-type` 保留兼容历史，但不作为用户权限页的产品入口。

### 外部用户 API

履约运营台新增外部用户管理 API，第一阶段可在后端内部映射到现有员工表和登录密码表：

- `GET /api/customer-fulfillment/:customer_id/external-users`
- `POST /api/customer-fulfillment/:customer_id/external-users`
- `POST /api/customer-fulfillment/:customer_id/external-users/:employee_id/bind`
- `POST /api/customer-fulfillment/:customer_id/external-users/:employee_id/login-state`
- `POST /api/customer-fulfillment/:customer_id/external-users/:employee_id/password-reset`
- `POST /api/customer-fulfillment/:customer_id/external-users/:employee_id/unbind`

命名中的 `employee_id` 是第一阶段兼容字段。前端和文档统一称为外部用户 ID 或账号 ID，避免继续把客户账号叫员工。

## 数据策略

第一阶段不做物理拆表，降低风险。

现有数据继续使用：

- `company_employees.account_type='internal_employee'`：内部用户
- `company_employees.account_type='channel_customer'`：外部用户兼容存储
- `employee_login_passwords`：登录密码和停用状态
- `customer_erp_user_bindings`：客户与外部用户绑定

所有新 UI 和新 API 边界按产品模型命名。后续可以单独做迁移：

- `external_users`
- `external_user_login_passwords`
- `customer_external_user_bindings`

迁移时保持旧字段兼容一段时间，再移除 `channel_customer` 对员工表的依赖。

## 权限与安全

- 员工维护和用户权限需要内部 `company.manage` / `auth.manage`。
- 履约运营台外部用户管理第一阶段复用现有履约运营台写权限；后续如果拆出独立权限，再新增 `customer_fulfillment.manage_external_users`。
- 外部用户登录后不获得内部角色。
- 外部用户可用页面和接口必须继续由有效客户绑定、登录启用状态和能力模板 ERP 工作台边界控制。
- 禁用外部用户登录后，客户工作台、履约订单列表、小程序密码登录都必须拒绝继续访问。

## 测试计划

单元测试：

- 客户档案 Vue 逻辑：点击客户名打开抽屉，关闭抽屉清理 URL，新增/编辑复用抽屉。
- 客户档案源码测试：不再渲染“操作”列和列表内编辑按钮。
- 用户权限前端测试：页面不出现账号类型切换，不出现渠道客户选项，只加载内部账号接口。
- 履约运营台前端测试：外部用户区只在有效客户和 ERP 工作台模板下允许绑定。

API 测试：

- 内部账号列表只返回内部用户。
- 给外部用户分配内部角色仍返回错误。
- 外部用户创建接口写入兼容存储并默认 `account_type='channel_customer'`。
- 外部用户绑定接口继续校验批发客户、启用账号、能力模板开放 ERP 工作台和一对一绑定。
- 外部用户停用后，小程序密码登录和客户工作台上下文拒绝访问。

集成/验收：

- 客户档案打开后不再看到底部当前客户单行列表。
- 员工维护不显示外部用户。
- 用户权限不显示外部用户和账号类型切换。
- 履约运营台可以创建外部用户并绑定到批发履约客户。
- 客户门户配置只展示账号绑定摘要，变更入口指向履约运营台。

## 验收口径

- 客户档案列表没有“编辑”操作列。
- 点击客户名称后右侧抽屉打开，能查看和保存客户资料、上传/删除附件。
- 客户详情页面底部不再出现当前客户自己的单行列表和第二个编辑入口。
- 员工维护只显示内部用户。
- 用户权限只显示内部用户，不能把账号切换成渠道客户。
- 外部用户账号创建、启停、重置密码、绑定客户在履约运营台完成。
- 客户门户配置不再承担外部账号选择和绑定主流程。
- 外部用户不能获得内部角色或内部菜单。
- 外部用户访问仍受客户绑定、启用状态和能力模板 ERP 工作台边界控制。
