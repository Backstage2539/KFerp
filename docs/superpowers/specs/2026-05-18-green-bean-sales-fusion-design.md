# 生豆销售融合设计

## 背景

当前系统的产品、BOM、成本试算、豆单、录单、客户履约和小程序商城主要围绕熟豆销售建立。生豆销售已经可以在部分入口用 `green_bean` 类型区分，但价格来源、SKU 维护、豆单展示、质检信息、客户下单和库存流程还没有形成闭环。

本次设计的目标是把生豆销售并入现有产品体系：生豆是产品的一种销售形态，不另起一套产品主数据；但生豆价格、质检和库存流程不硬套熟豆的完整烘焙成本逻辑。

基线分支：`origin/develop@16f9419ab87f70694b08cfab3fafc837da011b85`。

## 目标

- 录单可选择生豆产品，并且规格既可从常用规格选择，也可直接输入克数。
- 订单列表、订单详情、履约和小程序订单中能一眼区分生豆和熟豆产品。
- 豆单能导出生豆豆单，并展示生豆销售价和质检信息。
- 小程序履约客户能下单生豆产品。
- 小程序商城能上架和下单生豆产品。
- 客户 SKU 列表和公共 SKU 选择支持形态过滤、名称搜索、一级分类过滤、二级分类过滤。
- 公共 SKU 不再维护销售价；熟豆和生豆都通过阶梯模板/发布价格计算豆单售价和交易售价。
- 新增 SKU 时，熟豆不需要默认价，生豆也不需要售价。
- 生豆 SKU 增加单品/拼配属性。
- 原料入库增加产季、产地、产家风味描述。
- 原料入库需要入库质检，并沿用现有质检框架。
- 入库质检增加工厂风味描述、水分、密度。
- 豆单展示最新一条通过质检的记录。

## 非目标

- 不新增一套独立的生豆产品表或生豆订单表。
- 不让生豆 SKU 直接绑定原料；原料关系仍由 BOM 表达。
- 不把入库质检作为生豆豆单的质检来源。
- 不在公共 SKU、客户 SKU 或商城商品上人工维护最终销售价。
- 不改写历史订单价格快照。

## 核心口径

### 产品融合边界

产品仍使用同一套 `products`、分类、客户 SKU、BOM 和价格发布体系。新增或补齐的字段只表达生豆销售的差异：

- `product_kind` 区分 `roasted` 和 `green_bean`。
- 生豆 SKU 增加 `green_bean_type`：`single_origin` 或 `blend`。
- 生豆 SKU 绑定一个熟豆 BOM 载体。实现上优先绑定熟豆产品 ID，因为现有 BOM 已通过熟豆产品承载原料配方。

生豆 SKU 不直接绑定原料。无论单品还是拼配，豆单和价格计算都通过绑定的熟豆产品找到 BOM。

### 质检来源

生豆豆单质检信息统一取绑定熟豆 BOM 载体对应的生产质检，不再区分单品或拼配：

- 熟豆豆单：取本产品最新一条通过的生产质检。
- 生豆豆单：取绑定熟豆产品最新一条通过的生产质检。
- 最新通过：`result = 'pass'`，按 `created_at DESC, id DESC` 取第一条。
- 展示字段：工厂风味描述、水分、密度、质检时间和质检来源编号。

入库质检仍然必须存在，但它是原料入库流程要求，不参与豆单质检展示，也不参与 BOM 关系。

## 数据模型

### 产品

在 `products` 上补齐生豆销售字段：

- `green_bean_type text`：仅 `product_kind='green_bean'` 时有效，值为 `single_origin` 或 `blend`。
- `green_bean_bom_product_id bigint`：仅 `product_kind='green_bean'` 时有效，引用承载 BOM 的熟豆产品。

约束建议：

- 生豆产品必须绑定一个有效熟豆产品，才能发布生豆豆单或进入交易。
- 绑定目标必须是非生豆产品，避免生豆链到生豆。
- 生豆产品允许有自己的名称、分类、可见性、客户 SKU 归属和豆单展示信息。
- `default_price` 保留数据库兼容，但新 UI 不展示、不要求填写，后端不再把它作为生豆售价来源。

### 原料入库

在原料收货/批次上补齐批次属性：

- `crop_season`：产季。
- `origin`：产地。
- `producer_flavor_description`：产家风味描述。

这些字段是原料批次信息，跟生豆 SKU 和 BOM 不直接关联。

### 质检

继续复用 `quality_inspections`：

- 生产质检继续使用 `scope='work_order'` 或 `scope='finished_batch'`。
- 入库质检使用 `scope='raw_material'` 或 `scope='material_batch'`。
- 入库质检的结构化指标写入 `metrics_json`：
  - `factory_flavor_description`
  - `moisture`
  - `density`

为方便前端和豆单消费，API 层提供规范化字段，不要求前端解析任意 JSON 文案。

## 价格模型

### 熟豆

熟豆继续使用现有 BOM、出成率、快速成本参数、梯度模板和价格发布逻辑。

### 生豆

生豆价格不使用熟豆烘焙成本试算中的出成率、烘焙生产成本、熟豆损耗等逻辑，也不使用原料仓库的入库价直接作为销售价。

生豆价格来源分三层：

1. 生豆 SKU 绑定熟豆产品。
2. 通过绑定熟豆产品的 BOM 计算原料成本。
3. 使用二级分类绑定的阶梯模板计算生豆销售价格。

因此生豆销售价是“BOM 原料成本 + 阶梯模板利润/规则”形成的销售报价。交易仍以已发布价格为准；未发布试算只用于预览。

若绑定熟豆产品没有有效 BOM、分类没有模板、或没有已发布价格，录单和小程序下单应给出明确错误，不静默使用 `default_price`。

## 功能设计

### 产品设置

公共 SKU/客户 SKU 列表增加筛选：

- 形态：全部、熟豆、生豆。
- 名称搜索。
- 一级分类。
- 二级分类。

公共 SKU 列表调整：

- 去掉销售价列。
- 去掉生豆销售价编辑。
- 展示产品形态、生豆类型、绑定熟豆 BOM、一级分类、二级分类和状态。

新增 SKU 调整：

- 熟豆不需要默认价。
- 生豆不需要售价。
- 生豆需要选择单品/拼配。
- 生豆需要绑定熟豆 BOM 载体。
- 生豆可以归入自己的产品分类，用于豆单和梯度模板。

### 录单

录单产品选择器支持生豆产品，并显示形态标识。

规格输入统一为两种方式：

- 选择常用规格。
- 直接输入克数。

录单价格仍由后端按已发布价格和阶梯规则计算。前端不能把手填克数对应价格自行写死。

订单行、订单详情、打印/导出和履约视图展示产品形态：

- 熟豆。
- 生豆。

### 豆单

豆单类型支持：

- 熟豆零售豆单。
- 熟豆商用豆单。
- 生豆豆单。

生豆豆单内容：

- 只展示 `product_kind='green_bean'` 且可见/可发布的产品。
- 价格来自生豆价格发布快照。
- 质检信息来自绑定熟豆产品的最新通过生产质检。
- 导出 PDF/公开页/小程序豆单需要保持一致。

质检信息为空时，豆单展示“暂无通过质检记录”或同等空状态；发布策略建议阻止正式发布，避免客户看到无质检依据的生豆豆单。

### 小程序履约客户

履约客户的可下单 SKU 来源继续走客户 SKU/公共 SKU 体系。

调整点：

- 可筛选或识别生豆产品。
- 生豆价格走已发布阶梯价。
- 下单提交时服务端重新计算价格。
- 订单和履约状态展示生豆标识。

### 小程序商城

商城商品可以关联生豆产品。

调整点：

- 商城后台不再人工录入最终售价。
- 商品展示价由关联产品、规格和已发布价格计算。
- 小程序下单提交时服务端重新计算价格，不信任前端购物车价格。
- `mall_products.unit_price` 可保留数据库兼容，但不再作为生豆或熟豆的权威交易价。

## 入库质检流程

原料入库新增字段随收货批次保存。

入库后默认进入待质检状态。入库质检通过后，批次变为可用；不通过或待处理时不能进入生产领用。

兼容策略需要在实现时确认：

- 新入库批次强制要求通过质检后可用。
- 老批次没有质检记录时，是否按历史可用处理，还是一次性补做质检。建议第一版只对新批次强制，老批次保留兼容并在库存页提示质检状态缺失。

## API 设计

需要补齐或调整的 API：

- `GET /api/product-settings`：返回生豆类型、绑定熟豆 BOM、分类筛选所需数据和公共 SKU 筛选字段。
- `POST/PUT /api/products`：保存生豆类型和绑定熟豆 BOM，忽略前端售价字段。
- `GET /api/order-entry/products`：返回产品形态、可用规格、可手输规格标识和已发布价格信息。
- `POST /api/orders`：支持生豆产品和手输规格克数，服务端计算价格。
- `GET /api/costing/bean-list`：生豆豆单返回价格、绑定 BOM 信息和最新通过生产质检。
- `GET /api/costing/public-bean-list`：公开豆单支持生豆标题、标签、质检字段和 PDF 导出。
- `POST /api/material-receipts`：保存产季、产地、产家风味描述。
- `POST /api/quality-inspections`：支持入库质检结构化字段。
- `GET /api/customer-portal/skus`：返回生豆产品、筛选字段和已发布价格。
- `POST /api/customer-portal/orders`：服务端支持生豆阶梯价格。
- `GET/POST /api/customer-portal/mall/*`：商城商品关联生豆并由服务端计算价格。

- 生豆 SKU 必须绑定熟豆产品。

- 手输规格克数能匹配正确阶梯。

- 生豆豆单从绑定熟豆产品取生产质检。

- 产品设置保存生豆类型和绑定熟豆 BOM。

## 风险与待确认

- 老原料批次是否强制补做入库质检。建议第一版只强制新入库批次，老批次兼容并提示缺失。
- 生豆豆单无最新通过生产质检时，是阻止发布还是允许发布空状态。建议阻止正式发布。
- 商城现有 `unit_price` 历史数据需要保留展示兼容，但交易应改为服务端实时按发布价格计算。
- 生豆绑定的熟豆产品如果 BOM 后续变化，未发布试算可以变化；已发布豆单和历史订单必须保留快照。
