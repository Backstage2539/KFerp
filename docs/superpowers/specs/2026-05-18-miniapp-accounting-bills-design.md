# Miniapp Accounting Bills Design

## Goal

小程序底部“账单”页改成账目视角，而不是复制订单页。客户应先看到指定账期内的应收、已付款、未付款金额和未付款订单数，再通过订单号跳到订单页查看订单详情。

## Confirmed Scope

- 账期筛选按订单日期计算，不引入独立付款流水时间。
- 支持本周、本月、本年、自定义开始/结束日期。
- 账单页默认进入本月。
- 账单页列表只展示账目必要信息：订单号、订单日期、应收金额、付款状态、收款方式。
- 点击订单号跳转订单页，并用订单号作为查询关键词定位该订单。
- 不在账单页展示收件人、商品明细、物流、销售单、出库单按钮。

## Architecture

- 后端继续复用 `/api/mini/services/settlement`，让 settlement 服务页支持订单日期、付款状态和关键字过滤。
- settlement 响应在 `summary` 中返回账目汇总：应收总额、未付款金额、未付款订单、已付款金额。
- `CustomerOrderSummary` 增加 `payment_method`，账单页可以直接展示付款方式。
- 小程序服务页根据 `serviceKey === 'settlement'` 走账单专用过滤和账单列表渲染；订单页保留现有完整订单信息。

## Acceptance

- 岩师傅这类有订单但未付款的客户，进入账单页能看到未付款金额和未付款订单数。
- 切换本周、本月、本年或自定义日期，会重新请求 settlement 接口并按订单日期过滤。
- 账单页订单号可跳到订单页，订单页带关键词筛选对应订单。
- 账单页不显示商品明细、收件人、物流、销售单或出库单按钮。
- 接口和页面仍保持当前客户隔离。
