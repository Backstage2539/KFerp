# KFerp 通用制造模型设计方案

日期：2026-05-26
需求：PR-375-PROCESS-BOM-WORKORDER-SKU-MODEL

## 目标

把现有偏咖啡烘焙的 SKU、BOM、出品率、工单、工序卡抽象为通用制造模型。系统侧保留 `product_bom.yield_rate` 兼容既有生产和成本计算，用户侧优先表达为“预期损耗率”，并把工序卡作为实际投入、实际产出、实际损耗的执行记录。

该模型必须能同时解释：

- 咖啡：生豆投入、烘焙损耗、熟豆产出。
- 服装：布料投入、裁剪损耗、成衣产出。
- 鲜果加工：鲜果投入、去皮/挑选损耗、净果或成品产出。

## 当前系统审计

### SKU

现有 SKU 设置承担销售、库存、生产对象配置，已有公共 SKU、客户 SKU、产品形态、客户上下文、梯度模板、BOM 入口、烘焙度和 BOM 出品率相关概念。风险是“烘焙度”和“出品率”容易被理解为咖啡专属字段，后续服装、鲜果加工会出现“布料损耗”“去皮损耗”等同类业务但无法自然命名。

设计边界：SKU 仍是销售、库存、生产对象。公共 SKU 和客户 SKU 保留，产品形态保留，行业字段模板留到三期处理。SKU 不直接承载实际损耗。

### BOM

现有 `product_bom.yield_rate` 保存配方的理论出成率，BOM 版本 `bom_versions.yield_rate` 会快照该值。生产计划、成本核算和生产中投料建议依赖该产出率计算计划投料。

设计边界：BOM 定义物料组成和理论投入产出关系。用户侧主字段为“预期损耗率”，系统换算 `expected_yield_rate = yield_rate = 1 - expected_loss_rate`。一期不新增物理字段，保留 `yield_rate` 作为兼容存储；API 暴露 `expected_loss_rate` 和 `expected_yield_rate`。

### 工单与工序卡

现有 `work_orders` 已经记录 running item、BOM 原料快照、WIP 占用和工单状态。现有 `job_cards` 只有工序、工位、状态、开始/完成时间和操作人，默认硬编码为 `roast/roaster`，缺少实际投入、实际产出和实际损耗。

设计边界：工单冻结生产任务当时的 SKU、BOM、计划投料和后续工艺/工序快照；工序卡记录执行事实。现阶段扩展工序卡实际损耗字段，后续二期再引入工艺模板和工艺路线。

### 生产日志、库存、成本

生产日志已有计划投入、实际产出、实际产出率、物料消耗摘要；成品批次和库存追溯依赖生产完成流程。成本核算依赖 BOM 产出率做理论成本换算。

设计边界：生产日志汇总整单实际结果；成品批次记录最终库存和追溯链；成本核算区分理论成本、计划成本、实际成本。

## 通用模型

### SKU

SKU 是销售、库存和生产对象，包含：

- 公共 SKU / 客户 SKU。
- 产品形态，例如熟豆、生豆、挂耳、速溶、服装成品、净果。
- 行业字段模板引用，三期增加。
- BOM 入口与工艺模板入口。

SKU 不保存批次实际损耗，避免把一次生产结果污染成商品属性。

### BOM

BOM 是物料组成和理论投入产出关系，包含：

- 成品 SKU。
- 物料组件或成品组件。
- 版本。
- `yield_rate` 兼容字段。
- API/界面口径：`expected_loss_rate = 1 - yield_rate`，`expected_yield_rate = yield_rate`。

BOM 用于报价、理论成本、计划投料和版本快照。

### 工艺模板

工艺模板是“产品如何制造”的方案，二期新增：

- 绑定 SKU 和 BOM 版本。
- 包含工艺路线、默认设备、默认工时、关键参数。
- 可按行业模板展示参数字段。
- 可覆盖默认损耗，例如不同烘焙度、裁剪方式、去皮方式对应不同预期损耗。

工艺模板不替代工序；它组织工序。

### 工序

工序是工艺路线中的步骤，例如烘焙、裁剪、缝制、去皮、包装。工序定义是否记录损耗、默认设备、默认工位和参数字段。

### 工序参数

工序参数必须可配置，不硬编码咖啡字段。结构化通用字段保存设备、人员、投入、产出、损耗、质检和异常原因；行业差异字段通过 JSON/动态字段模板保存。

### 工单

工单是一次生产任务。创建时冻结：

- SKU 快照。
- BOM 版本和预期损耗/预期产出。
- 计划投料、预计产出。
- 后续二期冻结工艺模板、工艺路线和关键参数。

历史工单不受后续 BOM 或模板修改影响。

### 工序卡

工序卡是工单内单个工序的执行记录，记录：

- 计划投入。
- 实际投入。
- 实际产出。
- 实际损耗。
- 实际损耗率。
- 设备、人员、质检、异常原因。
- `metrics_json` 保存行业或工序扩展参数。

### 生产批次 / 成品批次

生产批次记录生产执行过程；成品批次记录最终入库和追溯链。它们引用工单、工序卡和生产日志，形成从销售需求到物料消耗、成品库存的链路。

## 损耗和产出率口径

- BOM 层：预期损耗率 / 预期产出率，用于报价、理论成本和计划投料。
- 工艺模板层：可按制造条件覆盖默认损耗，例如烘焙度、裁剪方式、去皮方式。
- 工序层：定义是否需要记录损耗。
- 工序卡层：记录实际投入、实际产出、实际损耗和异常原因。
- 工单 / 生产日志层：汇总整单实际损耗和实际产出。
- 成本核算层：理论成本取 BOM 预期产出率；计划成本取工单快照；实际成本取生产日志和工序卡的实际消耗及实际产出。

## UI 信息架构

### SKU 设置

SKU 设置保留公共 SKU、客户 SKU、产品形态和梯度模板。BOM 入口继续存在，字段文案避免只写咖啡“烘焙出品率”。行业字段模板三期新增。

### BOM 配方维护

一期在 BOM 页面直接维护“预期损耗率”，同步显示换算后的“预期产出率”。版本列表展示预期损耗率和预期产出率。二期在 BOM 页面增加关联工艺模板入口，但不把完整工艺模板编辑塞进 BOM 表单。

### 工艺模板页面

二期新增独立“工艺模板”页面，建议放在“商品与配方”或“生产管理”。一期不新增该页面，避免把流程改大。

### 工序卡页面

工序卡表格补充计划投入、实际投入、实际产出、实际损耗、实际损耗率、异常原因，并提供保存实际数据入口。

### 工单页面

工单页面展示冻结的 BOM 预期损耗、预期产出率、计划投料、预计产出、BOM 原料快照和工序实际损耗汇总。打印工单同步展示这些快照口径。

## 数据结构建议

### 一期扩展

继续保留 `product_bom.yield_rate`，新增 API 层字段：

- `expected_loss_rate`
- `expected_yield_rate`
- `yield_rate`

扩展 `job_cards`：

- `planned_input_qty NUMERIC(14,3)`
- `actual_input_qty NUMERIC(14,3)`
- `actual_output_qty NUMERIC(14,3)`
- `actual_loss_qty NUMERIC(14,3)`
- `actual_loss_rate NUMERIC(10,4)`
- `exception_reason TEXT`
- `metrics_json JSONB`

扩展工单 API：

- `expected_loss_rate`
- `expected_yield_rate`
- `bom_version_id`
- `process_template_id`
- `process_snapshot_json`
- `operation_summary_json`

一期可先由现有数据实时汇总填充，后续再物理快照化。

### 二期新增

- `process_templates`
- `process_template_operations`

工单创建时冻结工艺模板和工序路线到 `work_orders.process_snapshot_json`。

### 三期新增

- 行业字段模板定义表。
- 工艺模板参数值和工序卡参数值通过 JSON 保存。
- 通用字段保持结构化，行业差异字段走动态模板。

### 快照规则

必须快照化：

- BOM 版本、预期损耗率、预期产出率。
- 工艺模板版本、工艺路线、关键参数。
- 工单计划投料和预计产出。
- 工序卡实际投入、实际产出、实际损耗。

可实时引用：

- 当前 SKU 名称用于列表辅助展示，但工单历史明细应保留创建时名称。
- 操作手册、模板说明。

## 兼容迁移

不删除 `product_bom.yield_rate`，也不改变成本引擎的底层输入。写入 `expected_loss_rate` 时换算为 `yield_rate = 1 - expected_loss_rate`。读取时同时返回兼容字段和新字段。旧前端或旧成本逻辑继续读 `yield_rate`。

## 风险

- 现有烘焙度默认得率可能覆盖 BOM 显式产出率，需要改成“BOM 显式值优先、烘焙度仅作为缺省参考”。
- 工序卡实际损耗需要和生产完成自动回填协调，避免人工录入和完工回写互相覆盖。
- 后续工艺模板上线后，工单快照字段必须保护历史，不可实时引用模板。
- 行业字段模板需要权限和字段校验，否则 JSON 字段会变成不可治理的自由文本。
