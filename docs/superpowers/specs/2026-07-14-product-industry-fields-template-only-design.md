# 商品行业字段仅来源于模板设计

日期：2026-07-14
范围：`商品 → 商品档案 → 商品档案配置 → 行业字段`

## 问题

商品档案当前会展示并保存没有行业字段模板引用的历史字段。根因不是行业字段模板预置，而是旧兼容链路：

- 启动回填把 `products.roast_level` 和 `products.special_attrs_json` 转成 `product_production_config_fields`。
- 前端在找不到行业字段模板时原样展示历史 `fields`，选择“不使用行业字段模板”也不会清空。
- 后端允许 `industry_field_template_id=0` 时继续保存任意字段。
- 复制商品会复制字段，但不会同步复制行业字段模板引用，因此能继续制造“有字段、无模板”的记录。

这与新业务规则冲突：商品行业字段定义和值必须依附于商品明确引用的行业字段模板。

## 目标

- 商品未引用行业字段模板时，商品列表和配置抽屉均不展示行业字段，保存结果的字段数组必须为空。
- 商品引用行业字段模板时，只展示和保存该模板当前定义的字段。
- 删除历史无模板字段，以及已选模板之外混入的旧字段。
- 停止旧商品属性再次生成行业字段。
- 商品正常保存仍写现有 `save_product_production_config` 操作日志，并记录模板 ID 与清理后的字段数量。

## 非目标

- 不删除行业字段模板或模板字段定义。
- 不删除 `products.roast_level` 列，也不清空整个 `products.special_attrs_json`；这些旧属性继续作为历史兼容数据存在，但不得再被转换或展示成商品行业字段。
- 不改写已发布价格表、历史订单或历史工单中已经冻结的字段快照。
- 不新增行业字段、模板默认值或自动推断规则。
- 本次不部署；合并到 `develop` 后，由后续明确的部署任务在目标环境执行清理。

## 方案选择

### 采用：前端、后端与数据清理三层收敛

前端只投影所选模板字段，后端强制执行同一约束，启动迁移幂等清理存量错误数据。这样列表、编辑、保存及下游读取都得到同一结果，也不会在服务重启后复发。

### 不采用：只在前端隐藏

旧字段仍会存储并被价格表、销售和生产查询读取，且下一次打开或其他客户端保存时可能再次出现。

### 不采用：仅执行一次手工 SQL

当前启动回填和 API 仍允许无模板字段，清理后服务重启或复制商品会重新制造同类数据。

## 数据契约

设商品生产配置为 `config`，当前模板定义集合为 `template.fields`：

1. `config.industry_field_template_id <= 0` 时，`config.fields` 必须为 `[]`。
2. `config.industry_field_template_id > 0` 时，每个保存字段的 `template_field_key` 或 `field_key` 必须精确匹配该模板的 `field_key`。
3. 模板字段的名称、类型、单位、必填、选项和排序均以模板定义为准；商品只保存字段值和价格表展示开关。
4. 只保留同一模板键的既有值，不再使用 `烘焙度 ↔ roast_level` 等旧别名自动迁移值。
5. 模板没有字段定义时，商品字段为空。

## 后端与数据清理

### 保存约束

- `normalizeProductProductionConfigFieldsAgainstTemplateTx` 在模板 ID 为 0 时直接返回空数组，不再透传请求字段。
- 有模板时继续按模板键校验并用模板元数据覆盖请求中的字段定义。
- 保存仓储继续先删除当前商品字段，再插入规范化后的字段，因此取消模板会物理清空该商品字段。

### 启动迁移

保留旧商品生产配置、BOM 引用和损耗率的回填，但删除 `special_attrs_json → product_production_config_fields` 的字段回填。随后执行幂等清理：

- 删除不存在商品生产配置主记录的孤儿字段。
- 删除 `industry_field_template_id <= 0` 的全部商品配置字段。
- 对已引用模板的商品，删除其模板当前字段定义中不存在的配置字段。

该清理只影响 `product_production_config_fields`，不会删除模板定义或旧商品属性。部署到某个环境时只清理该环境数据库；执行部署前必须先做数据库备份。

### 商品复制

当前复制商品流程没有复制行业字段模板引用，因此不再单独复制 `product_production_config_fields`。未来若要复制行业字段，必须作为“模板引用 + 模板内字段值”的完整功能另行设计，不能只复制值。

## 前端行为

- `productProductionConfigFieldsFromTemplate` 没有有效模板时返回空数组。
- 有模板时只按模板字段键生成表单行，并只保留精确同键的历史值。
- 商品列表“行业字段”列先确认商品引用的模板，再显示模板内且允许价格表展示的字段；无模板显示 `-`。
- 配置抽屉打开时，在模板数据加载完成后按当前模板重新构建字段表单。
- 选择“不使用行业字段模板”立即清空字段表单。
- 保存前再次按当前模板投影字段；无模板强制发送 `fields: []`，防止绕过界面残留回写。

## 错误处理与兼容

- 前端加载不到模板时采用安全结果：不展示、不提交历史行业字段。
- 后端是最终约束；即使旧客户端携带无模板字段，保存结果仍为空。
- 已停用但仍被历史商品引用的模板可以按其现存字段定义读取；用户主动取消或改选模板后，按新选择重新投影。
- 已删除或不存在定义的模板不会保留孤立字段值。

## 测试与验收

### 前端 RED/GREEN

- 无模板且配置中存在 `roast_level` 等历史字段时，表单字段结果必须为空。
- 模板存在时，只保留模板键完全匹配的字段，不再通过旧别名继承值。
- 选择“不使用行业字段模板”立即清空字段。
- 商品列表不展示无模板历史字段。
- 保存无模板商品时 payload 的 `fields` 必须为空。

### 后端 RED/GREEN

- 反转“无模板允许旧字段保存”的旧测试，验证模板 ID 为 0 时字段被清空。
- API 请求携带模板 ID 0 和任意字段时，仓储命令与响应字段均为空。
- schema 测试确认不再从 `jsonb_each_text(special_attrs_json)` 生成商品行业字段，并包含幂等清理 SQL。
- 商品复制测试确认不再复制孤立行业字段。
