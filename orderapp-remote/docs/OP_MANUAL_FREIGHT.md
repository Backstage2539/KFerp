# 运费模板与实际运费出账手册（PR-705）

适用：管理员／员工配置与出账，客户查看预估和账单。覆盖普通发货录单、库存代发、无库存代发；购货留厂不发生物流、不收运费。生产／库存规则沿用原订单，不因导入账单再次执行。

## 入口与准备

1. 员工进入“设置 → 业务设置 → 物流设置”，先维护启用的物流公司和物流产品。
2. 在“运费模板”新增模板、选择物流公司及产品，填写每票包装附加重量。
3. 系统默认：在“设置 → 业务设置 → 物流设置”的“普通发货录单运费配置（系统默认）”选择模板、每票附加运费及默认包邮，点击“保存系统默认配置”。该配置用于所有录单，不需要选择客户。
   客户专用：进入“客户档案 → 编辑客户 → 客户普通运费配置”，单独选择模板、附加运费或客户包邮，点击“保存客户运费配置”。新客户先保存档案，再编辑运费。原先按客户保存的普通运费配置继续保留在此处。选择“使用系统默认”、取消包邮并将附加运费填 0 后保存，可恢复继承。
4. 库存代发／无库存代发：在客户门户配置展开“一件代发履约设置”，开启所需场景，在该场景内维护运费模板、附加运费、包邮及服务费；库存代发还需客户成品仓。点击“保存履约设置”一次保存两种场景，任何一项错误都不会部分保存。包邮不减免服务费。
5. 未开启的代发场景不要求配置；关闭保留已保存内容，重新开启后核对再保存。版本冲突或保存失败时输入保留，请核对最新配置后重试。代发有专用模板时无需配置普通运费；选择“继承客户档案／系统默认”、取消包邮并将附加运费填 0，可恢复继承。

## 地区分组和重量价格

- 每个模板单独维护分组，可命名为一区、二区等；选择整省、全市或区县，选择区支持名称、简称、全拼、首字母和代码搜索，并显示已选摘要。
- 地区目录固定为 `@vant/area-data@2.2.0`，来源、MIT许可及归档校验值保存在源码中。这是本地固定版本，不代表最新官方全量行政区划。
- 市／区县例外价比省级价优先；同一层级的同一地区不能重复属于两个分组。复制分组复制价格后需选择新地区，避免重叠。
- “重量档位＋末档续重”：整单商品净重合计，加一次包装附加重，按第一个覆盖计费重量的档位收费。超过末档，以末档价格加续重费，不足一个续重单位向上取整。
- 可添加更多档位，也可明确选择首重／续重模式。历史文本首续重模板保留，不自动改价。
- 模板列表支持复制、启停。每次保存增加版本；历史版本只读，可复制为新模板。已提交订单保留当时快照，不随模板或政策修改而改变。
- “尚未整省覆盖”用于提醒检查，配置了个别市区不代表全省覆盖。未配置地区不自动套其他地区价格。截图中的顺丰价格只作为独立开发验收模板，西藏及港澳台没有提供报价。

## 下单：预估不收取

本节的“待出账”语义适用于客户自助、代发及仍使用旧延期协议的普通录单客户端。员工网页和小程序普通录单已在 PR-720 改为自动报价计入本单应收，详见本手册后文。

1. ERP或小程序选择客户、商品规格、数量及收件地址；无法从旧文本唯一识别地区时，明确选择省市区，不做模糊收费匹配。
2. 系统按“代发录单模板 > 客户档案模板 > 系统默认模板”自动核算；普通录单仅按“客户档案 > 系统默认”取值。所选层级的模板、附加费及包邮一起生效；库存代发和无库存代发分别取自己的配置，包邮不等于缺配置。未选模板才回退，已选模板停用或缺地区费率时报错，不自动改价。系统默认尚未配置时必须由管理员明确选择，不自动将某个客户的模板提升为全局默认。客户自助入口不能换模板、附加费或包邮。员工普通销售录单使用下文 PR-709 的直接运费与包邮操作；其他代发费用调整继续沿用原权限和原因要求。
3. 适用本节的订单显示“预估运费 ¥… · 待出账”。预估基础运费和附加费只供参考，不计当前订单应付／应收。货款及需要立即收取的代发服务费照常。
4. 包邮免基础运费和附加运费；内部快递成本无法估算时显示“待核”，不能当作零成本。
5. 缺少非包邮模板、地区、重量或费率时保留草稿，修正配置后重新核算。已失效报价不能提交。旧客户端不能确认待出账规则时提示更新。
6. 购货留厂没有物流计费，允许不填收件信息。客户小程序已开通代发时首页隐藏“商品下单”，库存代发页“商品下单”补库存按钮保留，往返保留原草稿。

## Excel实际运费核对与出账

1. “物流设置 → 实际运费账单”选择承运商，上传 `.xlsx`，选择工作表，映射“运单号”和“每票最终实际运费（元）”两列。首行为列标题，每次最多10000行；公式请先转换为最终数值／文本。
2. 运单号用文本保存，保留前导零；超过Excel数字精度的长运单号不得使用数字单元格。
3. 点“解析并预览”，逐行核对客户、订单、实际费用、下单冻结的附加费、应收目标及本次差额。
4. 按承运商＋运单号精确匹配。未匹配、多订单歧义、单个订单多票、作废订单、同文件重复／冲突、已结算金额修订均留待处理，不猜配、不均摊。
5. 确认有效行后，生成关联原订单的**独立运费应收**，在客户统一账单的独立费用中可查；不再增加原销售单运费。包邮仅保存实际成本，不新增客户运费应收。历史已计费订单默认只核对实际成本。
   - 客户履约运营台“费用”页中，成功匹配并确认入账的运费显示“已确认”，可选入月结；订单上按模板计算的预估运费继续显示“待出账”，不当作已确认实账。代发服务费在代发单提交成功后显示“已确认”。费用确认状态与月结状态分开展示。
6. 部分确认的批次保留未处理行；在历史账单中可查看。处理好匹配问题后重新上传同一文件解析，已经确认的行不重放。
7. 同文件重复确认不再入账；不同文件相同运单、实际总额未变，不新增费用。修订实际总额只生成差额，例如预估10＋附加10、实际12确认出账22；实际修订13只追加1元。
8. “撤销来源”填写原因，生成反向费用并保留原记录。只能撤销最新来源，后续修订需先撤销；已结算或关账来源不得覆盖或撤销，先处理原结算。
9. 预览后订单或账单版本变化时，确认会被拒绝；重新解析预览，不能沿用旧金额。

## 校验与常见问题

- 在订单查看“待出账／已出账／包邮”；当前订单货款、服务费和实际运费独立费用不要相互重复累计。
- 系统默认保存后查操作日志 `system_shipping_policy / save`；客户与代发政策查 `shipping_policy / save`，均保留修改前后及操作人。保存冲突时刷新后核对最新配置再提交。
- 账单确认后查操作日志的 `freight_import / confirm`；政策、模板、冻结和撤销也有来源记录。
- 导入只改变实际成本与客户独立运费应收，不触发发货、库存扣减、生产需求或付款流水。实际快递付款仍走原财务流程。
- 没有商品或价格表时，客户首页仍按独立能力信息显示入口；缺货客户可在库存代发页补购，不消耗其他客户库存。
- 客户无法更换运费政策时，联系员工维护后台；未覆盖地区或未知净重需补配置，不能输入“0”绕过。

## PR-709 员工录单：自动、手填和包邮

适用入口：ERP“销售订单 → 录单”和员工小程序“录单”；新建、复制及原有规则允许编辑的普通销售订单。客户自助、库存代发和无库存代发继续使用原场景政策。

1. 选择客户后，系统从当前收件地址识别省市区；尚无商品时显示“添加商品后自动计算”。商品规格、数量齐全后自动核算，后续修改商品或地址会重新核算。
2. 地区无法唯一识别时搜索选择，支持名称、简称、拼音或行政代码。例如搜索“孟连县”，选择完整路径后补齐云南省／普洱市／孟连傣族拉祜族佤族自治县。同名区县根据完整路径选择，不自动猜配。
3. 自动模式按启用模板和当前报价规则计算，运费计入本单应收。普通员工网页及小程序还可为本单切换其他启用模板；旧客户端仍按旧延期协议处理。
4. 输入金额（包括明确输入0）：金额作为本单确定运费，计入本单应付。例如商品60元、运费20元，应付80元；后续导入实际快递成本12元、修订13元或撤销成本记录，不再新增客户运费应收。后台附加费不再叠加到这笔手填总运费。
5. 打开“包邮”：本单运费为0，无需写原因，金额输入暂时禁用并保留原值。关闭包邮恢复原手填金额；原本留空则恢复自动。包邮不减免其他服务费，也不代表快递成本为零。
6. 草稿保留地区、手填金额与包邮，恢复时重新核算；复制保留收费选择，清除旧报价、收款和实际账单关联。
7. 已保存订单沿用生产／发货编辑限制。未出账时可明确调整运费；已有实际费用确认记录或运费账单后锁定。未改动计费依据时保留历史快照；变更数量等依据按原冻结政策和单位物流重量重算。
   - 确认实际运费后，普通销售订单的整单编辑也停止保存，不能通过改优惠或省略运费字段绕过锁定。登记后续收款使用员工小程序订单详情顶部“编辑付款与发货状态”；该入口保留商品和运费快照。
8. 待确认订单的运费与商品一起生效；确认前保持原已接受版本的应收，拒绝新版本保留原运费。
9. 已有真实收款和凭证不会随运费调整清空。减费造成超收或需要重新分摊收款时，先在原财务流程核对处理；增费形成尚未收取的余额，不能当作已收。
   - 例如原已付120元，增加20元运费后，应收140元、已收120元、未收20元；原零金额或全额优惠订单新增20元运费时，20元全部未付。运费和优惠相抵、应收不变且仍结清时，保留原预付款，不把整笔已付金额改写成预付款。
   - 收齐尾款仅改付款信息时，按实际收款选择“已付款”，保留原预付款；已有凭证的实收货款与运费按累计到账填写，合计必须与结清总额一致，部分付款则须与已登记预付款一致。例如应收100元，先收到30元、再收到70元，结清时累计实收填写100元，原预付款仍保留30元。不能清空凭证来跳过核对，系统不会自动补造实收或凭证。
   - 整单编辑中同时改变运费／应收与付款状态、预付款或收款凭证时，会拒绝整次保存并提示分两次操作：先保留原付款信息，只保存费用调整；再重新打开订单，核对新应收后单独登记实际累计收款。例如原30/100加20元运费，先保存为30/120；实际收到剩余90元后，再登记已付款。有凭证时累计实收应填写120元。减费导致超收仍须先走财务核对，已确认实际费用的冻结限制仍有效；独立付款状态入口沿用原限制。
10. 手填／包邮即使暂时缺少内部成本模板、费率或物流重量，也按确定的客户运费保存，并显示成本待核。自动模式缺配置仍需修正配置；核算失败保留输入并可重试。

11. 缺少商品物流重量时，系统列出缺重商品。可填写“本单包裹总重量（克，含包装）”继续自动报价；按输入的包裹总重计价，不重复增加模板包装重量，也不回写 BOM。商品、规格或数量变化后须重新确认重量。也可手填运费或选择包邮。

12. 编辑历史订单时先保留原运费；只有选择新模板、填写运费、选择包邮或主动恢复自动后才重算。实际账单仍按当前收款与包邮状态处理：包邮或已收清运费只核成本，未收清时按现行规则处理。

结果核对：查看订单应付、收费模式及操作日志。自动模式的实际运费在独立账单；手填／包邮的快递导入只留成本。账单预览后调整订单会使旧预览失效，需要重新预览。
