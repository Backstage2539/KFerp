# 订单处理手册

> PR-749 分三批开放。本手册说明当前已实现的操作；未开放选项在页面列出原因，并随对应验收证据更新。真实订单由现场按实际业务选择并提交。

## 入口与角色

订单列表每行、订单详情、履约客户运营台均使用“订单处理”。批量选择仍使用列表原有复选框，进入后逐单核对，不统一代选钱、货、生产和关联单据的处理方式。

销售发起处理；生产负责人确认生产处置，仓库人员确认库存与货权，财务确认费用、账务和资金。历史账期更正还需要月结权限。客户账号不能使用内部处理接口。

## 选择操作

| 操作 | 使用情况 | 核对结果 |
| --- | --- | --- |
| 暂停／恢复 | 临时停止新增履约 | 原数量和账款保留，恢复不会撤销关闭或退款 |
| 关闭剩余履约 | 客户不再需要未履约数量 | 原数量、已交付量、已关闭量分开显示 |
| 重新开启 | 恢复指定已关闭数量 | 重新校验应收与关联事实；已退款、余额、抵扣记录保留 |
| 取消原单 | 整单录错或重复，且关联业务可撤销 | 保留取消记录；有已交付、已收款或已完成生产时不能直接取消 |
| 取消并修订 | 原单错误，需要重新开单 | 原单取消，产生关联草稿；新单重新审核，不继承收款、发货记录 |
| 退货／金额冲减 | 已交付或已形成应收需更正 | 实物、应收和实际付款分别核对，不重复入库或退钱 |

允许直接修改的订单日期等资料，继续使用正常编辑入口。关闭后保存日期会保留原商品行、规格、计量和冻结价格；商品变更须走重新开启或更正。

当前开发版本已实现基础处理、部分关闭／重开、未开工计划取消、公司货权继续备货、逐包裹取消代发、待入库预订换货源、预留释放、独立费用减免、账单调整与人工资金登记。停工余料处置、生产转供、实物退货和客户货权退回仍显示禁用原因；已收独立费用的原收款、冲减和资金去向分开保存。未完成的选项不能由管理员配置强行启用。

旧“失效”和旧代发一键取消接口会引导使用订单处理；不会替用户默认免除费用或同时取消其他包裹。小程序旧取消操作需交由内部员工在 ERP 逐单处理。


## 标准操作

1. 打开订单处理，核对原订单号、商品、原数量、已交付或已入客户仓数量、已关闭量。
2. 选择操作、原因和范围。选择“其他”时填写说明；指定数量不得超过本次可处理余额。
3. 逐笔查看关联生产、代发、库存和费用，明确选择处置。已取消代发仍展示历史；共享生产不能整体取消而影响其他订单。
4. 选择先停止新增履约后清算，或完成处置清算后最终关闭。处理中会阻止重复新增履约。
5. 选择开票／外部入账情况、开放账期或历史更正，以及记账日期。待核实的情况保留财务待办。
6. 点击“预览处理影响”，核对数量、应收变化、后续待办，再提交处理单。可先保存草稿，保存草稿不变更订单。
7. 各岗位从处理记录打开自己的待办，核对后提交。无权限时页面显示对应负责人。
8. 同时核对订单状态和清算进度。“已关闭”不等于资金已处理完成。

整单折扣按冻结商品金额分摊，按累计关闭数量计算尾差。运费与其他已发生费用需要单独处置；不能因商品关闭而隐式减免。已入客户仓是已履约事实，不能当作尚未交付数量关闭。

全部剩余履约关闭后，订单不再计入待发货和缺收件信息待办。留厂累计购货扣除已关闭的未履约数量，已入库历史保留；暂停不会清空累计购货或入库记录。已交付未收款继续显示有效应收。

## 库存预留、生产与代发

普通订单有库存预留时，逐批显示商品、批次、未发货预留数量和单位。明确选择保留，或填写本批释放数量，由仓库确认。实际释放与最终订单变更同一笔保存；保留原预留快照，不减少实物库存。部分关闭后，剩余预留和发货不得超过可继续履约量。

代发按当前包裹处理。关联订单可点开查看，并从左上角返回原订单。取消一个包裹只释放其未发货预订；同申请的其他包裹、费用和库存分别保留。包裹已发货或已有运单时，须先核对原发货事实。取消留厂购货原单前，关联代发的费用及资金要逐笔明确处理。

要保留关联代发，可在原购货订单选择“保留并更换货源”。每笔待入库预订分别选择替代购货权益，并填写该笔完整待入库数量；货源和数量初始留空。候选货源须属于同一客户，商品、冻结规格版本、仓库一致且有可用数量。预览列出原包裹、所选货源和数量，由仓库确认。新预订建立与旧预订释放同时保存，原预订和操作日志保留；目标货源不足、包裹已发货、身份不一致或保存失败时全部回滚。同一代发同时含已入库和待入库数量时，页面分别列出原批次及两部分数量。用户须明确选择已入库部分“保留原批次预留，继续用于本笔代发”，再选择待入库部分的新货源；此选项初始留空。已入库的客户权益、实物批次、仓库和原预留保持不变，仅释放旧货源的待入库预订。实际库存不足、批次身份不符、已发货或实物预留自预览后变化时不能提交；刷新后必须重新确认。已入库部分需退回或另行处置时，使用对应业务流程，不在换货源时自动处理。

未完成生产选择“继续生产作为公司备货”后，由生产负责人确认；含客户货权的物料或生产不能直接转公司备货。共享生产及原订单关联保留。已经完成的生产不可删除或整体撤销，选择保留公司库存时仍检查货权。生产单上的客户编号是需求归属，库存货权按实际仓库、物料、加工、投入与出入库记录核对。

## 修订与撤回

取消并修订后，在处理记录点击“打开关联修订草稿”。新草稿保留原单关联，保存时重新校验当前商品、价格和规格，再进入审核。原单、处理单与修订单可分别追溯。

只有尚未执行任何分项处置、尚未应用订单影响的处理单能撤回，须填写原因。已有退款、库存或其他处置结果时，不能以撤回抹除历史。

## 管理员配置与方案更新

有设置权限的员工可在处理抽屉展开“订单处理配置”，选择停用选项和各操作的额外审批岗位。保存时校验配置版本，冲突时先重新加载核对。配置不能放宽数量、货权和已发生业务校验；配置不是为业务单据预选处置。

待处理方案遇到新收款、关联单据或审批要求变化时，点击“刷新当前方案”，重新核对新增项目并预览，使用“确认更新处理方案”保存。更换待确认货源、数量或审批方案会产生新的岗位确认，不能沿用旧确认。旧方案和已执行结果保留追溯；已有分项结果后不能更改商品范围或冲减金额。订单影响已经执行的处理单继续完成清算，不再改写原方案。

费用保留、全部减免、部分减免或协商须明确选择。部分减免填“本次减免金额”；协商填“协商后保留收费”。零金额须明确输入，留空不会视为减免。确认前查看预览中的减免和保留金额，财务待办完成后生效。

订单已经关闭后，继续协商费用可选择“金额冲减 → 仅调整费用（商品履约保持原状）”。逐项选择保留、减免或协商，并明确填写记账日期和财务核对结果。这一范围不重新开启商品数量，也不改变生产、库存或暂停状态；费用确认及资金清算完成后生效。

实际运单费用按运单与原订单关联展示。订单内商品、运费的费用副本不会重复减免；独立服务费和实际运费分别计算。只有历史“已结算”标记而缺少可核对收款时，减免选项显示原因，由财务先核实收款来源；正常已出账未收款费用仍可按审批流程调整。

## 资金核对

可退金额以已确认收款、有效应收、已退款、保留余额及已抵扣金额计算，服务端提交时重新校验。可分次选择实际退款、保留客户余额、抵扣指定应收。

- 实际退款：先完成付款，再登记金额、实际付款账户、付款凭据、日期和说明。登记不代为转账。
- 保留客户余额：由财务明确选择金额，保留来源处理记录。
- 抵扣应收：明确选择同客户目标及金额，不得超过其待收金额，不修改原现金收款凭据。
- 重新开启：已转出的资金不会自动回到原订单；恢复的履约义务按实时资金情况形成待收。

商品款和每项独立费用分别计算可退余额。费用减免后，先保留满足剩余费用应收的已收款，超出的部分才进入资金待办。原收款金额、累计费用冲减和已处置资金在账单与客户账款中分别展示；减免不改写原付款凭据，已用于冲减清算的原收款不能从旧账单入口再次撤销。

已保留的客户余额在“客户余额”区域单独显示来源和可用金额。后续由财务选择实际退款或抵扣同客户的具体应收，填写金额及凭据；每次重新校验可用余额，重复提交不重复扣减。

已出账单保留原始出账金额，另列“订单处理调整”和当前待收；财务确认更正时填写核对凭据。重新开启产生新的待收后可以追加收款，原收款与退款记录均保留。

撤销追加收款只撤销最近一笔有效登记，保留更早的收款。登记后若订单账款已再次变化，须先核对，不能用撤销收款抹除后续更正。重复提交同一登记不会重复收款或撤销。

首版不提供自动调用支付渠道退款。

## 历史账期更正

选择历史账期后产生财务审批待办，确认人还须具有月结权限，并填写批准依据。审批本身不解锁账期、不改写月结快照。所需处置完成后，订单调整、月结重算、更正前后快照和操作日志同时保存。若审批后月结快照已变化，本次变更回滚，更新方案后重新审批。

经营统计将独立费用计入发生月份，将费用冲减计入用户选择的记账月份；订单已包含的商品与运费不重复计入，退款、余额留存及抵扣不再次冲减收入。原始月结快照不会因本次查询或费用更正被直接抹除。历史月份的当前计算与早期快照如有口径差异，由财务选择开放账期调整或经审批更正历史账期。

月结与相关收入、独立费用和税票保存依次完成。即使页面打开时账期尚未关闭，费用或税票提交时也会重新检查强锁账期；已结账时按提示选择开放账期或办理财务更正。

## 常见异常

- 预览过期：订单或关联业务已变化，重新读取并预览，不能沿用旧页面直接提交。
- 没有可处理数量：核对已交付、客户仓入库、关闭及退货记录，选择符合实际业务的操作。
- 共享生产不可取消：查看其他订单及已发生生产，不能删除工单解除限制。
- 账期已结：选择开放账期，或由财务走历史更正审批；取消页面不能直接解锁账期。
- 网络失败：先查看处理记录；原内容重试使用同一提交标识。改变金额或去向后须重新确认。
- 登记失败：待办显示失败原因及历史记录；表示本次 ERP 登记未保存，不代表银行转账失败。已实际付款时先核对凭据，重试登记不得再次付款。
- 日志或数据保存失败：本次关联写入回滚，不把失败标记成已退款或已完成。

## 结果与审计

按处理单号核对原订单、逐行数量、应收调整、分项确认及操作日志。库存和生产处置须核对原批次、仓库、货权及来源；历史库存与账款通过可追溯记录更正。不得通过删除关联单据让订单“能够取消”。
