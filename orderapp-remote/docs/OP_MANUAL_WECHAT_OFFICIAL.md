# 公众号价格表入口与订单查询

适用：PR-684、PR-685。入口：ERP「系统设置 → 公众号管理」；价格表页面的「价格表入口」快捷操作会打开该商品类型的两个配置项。页签中的「操作说明」打开本手册，返回时恢复「系统设置 → 公众号管理」。

## 一、按商品类型配置价格表入口

入口由「稳定商品类型 × 用途」组成，每个已识别的商品类型固定有「批发」和「一件代发」两个入口。例如咖啡豆、挂耳咖啡、速溶咖啡共有六个入口。入口对应的是商品类型，不是某张具体价格表；同一类型下增加价格表、复制价格表或发布新版都不会增加入口。商品类型名称可修改，稳定类型标识不变，因此小程序路径也不变。

1. 打开「系统设置 → 公众号管理 → 价格表入口」。也可在价格表页面点击「价格表入口」，快速定位该类型的两个用途。
2. 为「批发」和「一件代发」分别选择同一商品类型下任意一张已发布价格表和版本。两个用途可以选择相同或不同的价格表。系统不会根据名称或“是否支持代发”自动猜测用途。
3. 首次配置时入口为“待配置”、默认认证后可见且停用；必须选定目标版本并保存后才能启用。配置一个入口不会自动配置另一个用途。
4. 公开浏览仅适用于公共价格表。客户专属价格表只能认证后查看，并且访问客户必须与该表归属一致。认证浏览沿用豆单及商品下单权限。
5. 保存后可预览已保存内容、启停入口或复制完整路径。公众号菜单只可新选已配置、已启用且版本有效的入口。

固定路径格式为 `pages/price-list/price-list?entry=固定标识`。菜单目标中的价格表或版本可在 ERP 手动切换，路径保持不变。每次小程序打开都会重新检查入口和客户权限。停用、撤回版本或删除快照后显示不可用提示，不回退到其他版本。

迁移前生成的按具体价格表入口仍可由原路径访问，并继续执行原有认证和归属检查；它们只为历史链接兼容保留，不出现在新入口列表或新菜单选择器中。导入旧公众号菜单时会保留这类路径，只有管理员主动选择新入口才会改变目标。

新版本发布后不会自动切换入口，需在 ERP 手动切换。版本变化不改变路径。停用入口、撤回版本或删除快照后，小程序再次进入会清空旧展示并重新校验；不可用时显示提示，不替换为其他价格表。价格、规格、梯度和版本信息来自选定快照，不修改历史发布内容。

## 二、客户认证与绑定

公众号和小程序属于同一开放平台、并经运维开启跨平台识别后，可使用微信服务器返回的 UnionID 识别已有有效客户。OpenID 在不同 AppID 下不同，不能直接互换，也不能凭姓名或自行填写的手机号匹配订单。[微信官方身份说明](https://pay.wechatpay.cn/doc/v3/merchant/4012068676)

无法自动识别时：

1. 客户打开小程序并登录，完成现有客户认证。
2. 在个人中心选择要查询的客户，打开「公众号订单查询」。
3. 获取一次性绑定码，点击「复制绑定指令」，把指令发送给公众号。
4. 收到绑定成功后，点击「最近一次」或「最近三次」。

绑定码有效期 5 分钟，仅能使用一次；重新获取后旧码失效。同一公众号用户 5 分钟最多尝试 5 次。请勿向他人转发绑定码。自动识别遇到多个客户不会擅自选择；客户需在个人中心的「公众号查询客户」选择一个已认证客户。绑定码关联生成时选定的客户，后续可切换。

个人中心可解除绑定，管理员也可在 ERP「客户绑定」解除。解绑后立即停止查询，不会被自动识别恢复；重新绑定需新的一次性绑定码。取消关注同样使关联失效。待审核、停用、失去订单权限、客户归属已解除的账号不返回订单内容。

## 三、查询订单

- 全部订单：路径 `pages/service/service?key=orders&source=official`。未登录先认证，成功后回到此页。每页 20 条，用上一页、下一页查看更早记录；代加工客户也使用完整订单列表。
- 最近一次：菜单动作「回复最近一次订单」，事件键 `ORDERS_RECENT_1`。
- 最近三次：菜单动作「回复最近三次订单」，事件键 `ORDERS_RECENT_3`。
- 摘要含客户名、订单号、日期、商品规格数量、订单金额、付款、生产、发货状态及已有运单号。每单最多两条商品明细，超出提示查看全部订单。无订单回复「暂无订单」。
- 排序和作废过滤沿用当前客户订单列表；包括 ERP 录入及小程序创建的订单。每次查询检查当前账号、客户归属及订单权限。重复回调仍重新检查权限，已解绑后不会从历史回复缓存返回订单。

## 四、公众号菜单

首次接入可读取微信现有菜单为草稿；系统不会自动发布。支持 3 个一级菜单、每组最多 5 个子菜单，可配置固定豆单、全部订单、最近一次、最近三次、下单、小程序首页及网页动作。导入的素材动作保留；无法处理的旧自定义动作会明确校验失败，需要编辑后发布。

1. 「读取公众号现有菜单」保留当前菜单快照。
2. 编辑菜单名称、动作与目标；可保存菜单草稿。
3. 点击「预览完整菜单与变化」，对照当前和准备发布的完整菜单及目标路径。
4. 接入核对及正式小程序发布完成后，运维启用菜单发布开关。
5. 点击「发布此菜单」。预览有效期 5 分钟；草稿或微信当前菜单变化后必须重新预览。
6. 发布记录保留发布前菜单、发布请求和结果。恢复时载入历史版，预览后发布；载入本身不改变微信菜单。

微信接收成功不代表每部手机已刷新，须在公众号手机端核对菜单及跳转。不要同时在第三方平台或微信后台维护菜单，以免相互覆盖。

## 五、服务端接入与上线顺序

管理页只显示配置是否齐全，不显示密钥。密钥写入目标服务器 stack 的 `.env`，由现有发布脚本传入服务端容器；不放进前端、小程序或仓库。

| 服务端配置 | 用途 / 默认 |
| --- | --- |
| WECHAT_OFFICIAL_ENABLED | 1 启用，默认 0 |
| WECHAT_OFFICIAL_APP_ID | 已认证服务号 AppID |
| WECHAT_OFFICIAL_APP_SECRET | 服务号 AppSecret |
| WECHAT_OFFICIAL_TOKEN | 回调 Token，至少 16 字符 |
| WECHAT_OFFICIAL_AES_KEY | 微信 EncodingAESKey，43 字符，安全模式 |
| WECHAT_MINI_APP_ID | 已关联小程序 AppID，沿用现有设置 |
| WECHAT_OFFICIAL_UNIONID_ENABLED | 核对同一开放平台后设 1，默认 0 |
| WECHAT_OFFICIAL_MENU_PUBLISH_ENABLED | 正式小程序发布且核对完成后设 1，默认 0 |

配置缺失时功能保持关闭，回调返回 503，不能生成绑定码或发布菜单。价格表入口可先配置；没有目标版本的入口不能启用或用于新菜单。

正式上线顺序：

1. 核对服务号实际菜单、用户信息接口权限、服务器 IP 白名单、公众号与小程序关联、开放平台绑定；确认是否存在第三方消息接管并安排切换。
2. 后端就绪，配置回调 `https://erp.qacoohee.com/app/api/wechat/official-account/callback`，选择安全模式并完成微信 URL 校验。
3. 构建生产小程序，上传、审核并发布包含新页面的版本。开发包只连接开发环境，不能代替生产版。
4. 启用公众号及菜单发布开关，导入现有菜单，配置、预览并发布。
5. 手机验证公开豆单、专属客户隔离、登录返回、全部订单分页、最近 1/3 单、绑定/解绑及多客户选择。

开发回调对应 `https://dev.qacoohee.com/app/api/wechat/official-account/callback`，仅在明确使用测试服务号时配置。当前开发交付不自动启用真实服务号、不发布微信菜单。

## 六、审计、回退及故障处理

入口修改、版本切换、绑定码生成、绑定/解绑、草稿和菜单发布均记录审计。新增表为兼容迁移，不改写历史订单或价格表快照。消息回调验证时间、签名、AES/AppID，绑定码只存散列值，订单接口不接受公众提交客户 ID 或 OpenID 查询。

- 入口提示不可用：检查启用状态、所选版本是否撤回或删除；重新选择同一表的可用版本并保存。
- 认证后仍不能查询：检查用户和客户是否启用、绑定是否批准、订单/豆单能力以及公众号查询客户。
- 微信权限或白名单错误：按管理页错误码在服务号后台核对；不要把 AppSecret 发给客户。
- 发布失败或超时：先重新读取微信当前菜单核对实际状态，再预览重试，避免重复覆盖。
- 临时停止服务：关闭公众号总开关并重启应用；已配置小程序入口仍按各入口状态控制。入口可单独停用。
- 恢复菜单：发布记录选择「发布前菜单」，载入、对照预览、重新发布。若旧菜单含 ERP 不支持的动作，可使用保留的完整原菜单在微信后台恢复，避免丢失原动作。

开发测试、部署健康检查与 Van 的业务验收分别记录；未完成微信审核发布及手机实测前，不视为正式上线。
