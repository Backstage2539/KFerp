# orderapp 业务需求（精简版）

> 范围：描述“要做什么”和业务规则；不记录修 bug 的过程。

## 1. 目标与范围
- 建一个轻量的订单/档案/审计系统（Web）。
- 核心模块：
  - 录单
  - 订单列表、订单详情
  - 订单失效（代替删除，不可恢复，可复制重建）
  - 商品档案 + 阶梯价
  - 客户档案（含默认值、快速录入、复制地址）
  - 操作审计日志（全量留痕）
- 凡用户触发的业务写操作，包括新增、修改、删除、提交、导入、发布、作废、调整、转仓、上传和状态变更，都必须写入操作审计日志，并能在操作日志页面按类型、日期或关键字查到。
- 所有涉及业务列表的 Vue/Vite 页面都必须支持分页展示，至少包含总条数/总页数、当前页、跳转到指定页、每页显示条数；服务端分页接口必须返回 `total`、`total_pages`、`page`、`limit` 等元数据。
- PR-301-CUSTOMER-ACCOUNT-WORKSPACE：ERP 必须提供“工厂总览 / 客户账户”两种页面排布。工厂总览用于工厂内部全局订单、生产、库存、财务、门户能力配置、设置、系统和需求管理；客户账户用于围绕一个客户连续处理履约、订单、库存、SKU、豆单、BOM 和客户相关财务。该模式只改变页面排布和当前客户上下文，不替代用户权限。
- 客户账户模式必须有全局“当前客户”选择器，并把 `customer_id` 复用到现有页面：履约运营台、录单、订单列表、仓库库存、SKU设置、产品价格表、BOM配方维护、费用管理、经营报告和月度结账。用户在这些页面中切换客户时，顶部当前客户也应同步更新。
- 客户账户模式下左侧菜单不得复制一套新功能，只能重排现有 Vue/Vite 页面入口；工厂总览保留原菜单。刷新后 URL 必须保留工作台模式和当前客户，方便单人连续操作。
- PR-387-VIEW-CONTEXT：ERP 顶部必须从固定“工厂总览 / 客户账户”升级为统一“当前视图”。内置视图包含工厂总览、客户、订单和外部客户固定视图；客户视图绑定 `customer_id`，订单视图绑定 `order_id/order_no` 并派生订单客户，外部客户账号只能使用绑定客户。视图上下文只负责菜单呈现、页面默认过滤、URL 保留和跨页面参数传递，不替代权限、客户隔离、商品/BOM/价格后端校验。商品管理、产品价格表、BOM、录单、订单、仓库库存、费用管理、生产计划/工单必须按 PR-386 商品模型接入：客户侧展示客户商品名，执行侧使用商品档案和生产 BOM。保存当前视图、修改保存视图、停用保存视图必须写操作日志。
- PR-392-PRODUCT-CONFIG-ENTRY-TEMPLATE-ALIAS：商品档案列表必须把商品名作为第一业务列和唯一商品生产配置入口；点击商品名打开“商品档案配置”抽屉，抽屉内维护基础信息、商品配置模板、生产 BOM 版本、工艺路线、预期损耗率、行业字段模板和值，并提供“维护当前 BOM 明细”的 Vue/Vite 内部跳转。商品配置模板由商品档案引用，不再由产品子类型/分类引用；旧分类模板只作为 legacy fallback。行业字段模板作为商品生产配置字段定义来源，以普通表单字段展示和保存，不要求用户写 JSON。客户商品名必须支持批量从商品档案创建，重复绑定自动跳过且实际创建写操作日志。生产 BOM 跳转不得使用整页刷新，不得导致左侧菜单定位丢失。
- PR-394-PRODUCT-CLASSIFICATION-VIEW-TABS：商品分类从“对象选择分类模板/配置分类抽屉”收敛为“页面启用分类模板形成 Tab”。商品档案创建、商品档案配置抽屉、客户商品名单个新增和批量添加商品档案都不得写新的 `classification_template_id` 对象引用，也不得要求选择产品类型或产品子类型。分类模板只定义全局分类结构，不配置归属客户、不配置对象归类；新建模板才打开抽屉填写名称、排序和备注，点击左侧模板后在右侧维护分类项。商品档案页固定“全部商品”Tab，客户商品名页固定“全部客户商品”Tab；启用一个分类模板就新增一个模板 Tab，Tab 内展示当前页面范围的全部对象，按分类项和“未分类”分组并支持收起/展开。对象归类通过列表勾选、当前 Tab 下选择分类项和“移动到分类”完成；同一商品在同一模板内只能归属一个分类，同一客户商品在同一客户和同一模板内只能归属一个分类。客户商品名列表不得展示“展示分类”列，也不得提供编辑生产或 BOM/生产 BOM 操作。批量添加客户商品名只按商品名称/编号搜索和多选，不提供产品类型、产品子类型或分类模板选择。生产 BOM 页面从“维护当前 BOM 明细”进入后必须显示内存态临时返回条“返回商品档案配置：{商品名}”，刷新后返回上下文消失。
- PR-302-CUSTOMER-ACCOUNT-LOCKED-VIEW：客户账户模式必须锁定当前客户视角，SKU设置、BOM配方维护、产品价格表、库存和费用管理不得再让用户在页面内切换到其他客户。SKU 和 BOM 页面只能展示公共配置与当前客户自己的配置；公共配置可作为引用，不应被误改成其他客户配置。库存页面只展示当前客户相关成品库存，不展示跨客户追溯和工厂原料库存。
- 工厂总览不再展示“客户履约账户/履约运营台”入口；履约处理统一从客户账户进入。客户账户不展示客户门户配置、能力模板、生产计划/开始生产和工作台模式手册，这些入口属于工厂总览或内部设置。
- 渠道客户账号登录 ERP 客户工作台时，不展示顶部“工厂总览 / 客户账户”和“当前客户”选择器，只能进入自己绑定客户的履约运营台和费用情况，不能看到门户与能力、工厂全局订单、生产、工作台模式手册或系统设置。
- PR-303-CUSTOMER-ACCOUNT-FINANCE-MENUS：渠道客户账号登录后，左侧必须拆成“工作台”和“费用相关”两个菜单。“工作台”只承载客户自己的履约运营台和履约订单，不再嵌入费用明细或结算单；“费用相关”必须展示当前客户的费用明细、经营报告和结账相关，系统自动使用账号绑定客户过滤，不再要求客户选择客户。客户侧费用明细和结账相关均为只读展示，不允许新增/归集费用、执行结账、结账后调整或会计交接导出；后端读接口必须按当前登录员工绑定客户派生并校验客户范围，不能信任前端传入其他 `customer_id`。
- PR-304-CUSTOMER-ACCOUNT-HIDE-PRODUCTION-MANUAL：客户账户模式不得展示生产计划/开始生产、生产管理相关入口或工作台模式手册。内部员工需要排产、开工、生产中、生产工单、生产质检或生产成本时，必须切回工厂总览；渠道客户账号也不得看到这些入口。
- PR-305-GREEN-BEAN-ORDER-LB-UNIT-PRICE：ERP 录单读取客户最新已发布生豆豆单阶梯时，梯度区间和生豆销售单价都必须跟随发布模板单位；KG 模板必须展示和入单为元/KG。产品价格表中手工修改的生豆档位价也按模板单位保存到草稿/发布快照。例如岩师傅“兰卡拼配生豆”`60kg+` 手工改为 62 后，发布内容和录单都必须展示 `60kg+ 62/kg`，不得变回成本参考价 51.75，也不得回退到旧版豆单或同名熟豆阶梯。
- PR-306-BEAN-LIST-PUBLISH-HINTS：产品价格表页面必须明确生豆“梯度按 KG、单价按元/KG”，并在生豆价格编辑区和生成抽屉提醒“生成并发布新版豆单后，录单才会使用新价格”。客户生成豆单时版本号不得沿用当前已发布或复制的官方版本，默认按上一版本递增一小步：`V1` 变 `V1.01`，`V1.01` 变 `V1.02`，`V3.0.5` 变 `V3.0.6`；用户仍可手动改版本号。
- PR-309-BEAN-LIST-VERSION-DOWNLOAD：产品价格表的“豆单版本列表”每条版本记录都必须支持下载 PDF。下载必须使用该版本发布/草稿时锁定的 `content` 和 `config` 快照，不能用当前商品实时价格、当前抽屉配置或当前筛选状态重新生成历史豆单；公共豆单、客户豆单、草稿、已发布和已撤回历史版本都可按行下载。
- PR-315-SHELL-MENU-SCROLL-TOUCH：ERP Vue 壳层左侧菜单固定在单屏视口内独立滚动，右侧功能内容独立滚动；点击任何功能菜单后功能页面回到顶部，避免上个短页面的滚动位置让新页面看似空白；手机端右滑呼出功能菜单，左滑隐藏功能菜单。
- PR-316-FORM-DRAFT-CACHE：录单、BOM配方维护、SKU设置 的未提交表单必须做浏览器会话内内存缓存；跳转到其他功能再回来时保留未提交表单，刷新浏览器后草稿清空。编辑历史订单、复制订单和保存成功后的录单不得误复用新建订单草稿。
- PR-317-BEAN-LIST-STORED-PDF-DOWNLOAD：产品价格表版本列表下载 PDF 不得调用浏览器打印/另存为；必须走与销售单、出库单一致的服务器生成思路，按该版本快照生成 PDF，写入系统 `bean_list_publication_assets` 缓存，返回系统下载地址，后续同版本下载直接复用已保存 PDF。下载接口必须按豆单归属校验公共、客户或本人草稿范围，不能让客户专属豆单跨客户下载。
- PR-318-CUSTOMER-BEAN-LIST-PUBLIC-CATEGORY-SCOPE：产品价格表在客户范围下必须遵守 SKU设置 的“是否使用公共商品分类”开关。客户关闭公共商品分类时，豆单预览、生成抽屉和客户豆单发布候选只展示该客户自己的 SKU，不得混入公共分类或公共 SKU；开启后才允许公共分类下的公共 SKU 作为只读引用进入客户豆单范围。
- PR-319-CUSTOMER-BEAN-LIST-SKU-CATEGORY-METADATA：客户范围产品价格表必须读取 SKU设置 中当前客户 SKU 的分类路径和商品排序。客户自有/客户定制熟豆即使没有旧 Excel 豆单资料，也必须进入商用批发豆单；豆单分组标题应与公共豆单逻辑一致，优先显示实际豆单分类名，例如产品子类型“定制咖啡熟豆”，不得继续落到旧公共豆单的“源产地精选”等分类或因缺少旧豆单编码而消失。
- PR-339-CUSTOMER-BEAN-LIST-UNCATEGORIZED-SKU：客户范围产品价格表中，客户 SKU 未挂到当前客户 SKU 分类时必须显示“未分类”，不得继承基础公共 SKU 的旧 Excel 分类；例如岩师傅“曲奇拼配2.0”不能显示在“精品意式拼配”下。
- PR-320-BEAN-LIST-PREVIEW-STYLE-PDF：生成豆单 PDF 必须使用生成抽屉预览的卡片视觉样式（米色底、版本/标题/类型胶囊、分类条、商品卡、绿色/蓝色报价块），不得退回文本版豆单。生成 PDF 按当前预览快照保存草稿、在后端生成并写入 `bean_list_publication_assets`；发布或保存草稿时也必须同步生成预览样式 PDF。列表下载如发现非 `bean-list-preview-style-v2` 或 `bean-list-preview-style-v3` 的旧缓存，必须按新版预览样式重新生成并覆盖缓存。
- PR-321-CUSTOMER-SKU-CATEGORY-TOGGLE-FACTORY-BEANLIST-TITLE：客户 SKU 设置中的客户自有分类不得因勾选再取消“是否使用公共商品分类”而从客户分类树消失；从客户账户切回“工厂总览”后，SKU设置必须回到公共 SKU 归属；客户产品价格表的商用批发豆单标题必须沿用公共豆单标题逻辑，客户 SKU 挂在“咖啡豆 / 定制咖啡熟豆”时标题显示为“1、定制咖啡熟豆”，并且 `芬纳定制-红酒日晒-中深烘` 必须出现在芬纳咖啡客户豆单中。
- PR-322-CUSTOMER-SKU-CATEGORY-CLEANUP-BOM-VERSION-DEACTIVATE：SKU设置保存客户公共分类开关时，不得把仍有活跃产品子类型或已挂 SKU 的客户自有产品类型当成空公共副本清理；SKU 失效时，除当前 BOM 状态变为失效外，对应 active BOM 版本也必须同步置为 disabled，历史明细和版本记录保留。
- PR-375-PROCESS-BOM-WORKORDER-SKU-MODEL：SKU、BOM、工艺、工序、工单和模板必须按通用制造模型分边界。SKU 是销售/库存/生产对象；BOM 维护预期损耗率并换算预期产出率，兼容底层 `yield_rate`；工艺模板后续承载制造方案；工序是路线步骤；工单冻结当时的 SKU、BOM 和工序快照；工序卡记录实际投入、实际产出、实际损耗、实际损耗率和异常原因。模型不得写死咖啡烘焙，必须能解释咖啡、服装布料损耗、鲜果加工去皮挑选损耗等业务。
- PR-379-CHANNEL-PORTAL-WORKBENCH-SWITCH：客户档案必须提供“开通客户门户/工作台”开关。客户默认只是 ERP 客户；只有 active、开关打开后，才创建或启用客户门户配置并进入门户配置默认列表。客户类型新增渠道客户，但权限由门户客户配置里的能力模板决定；关闭开关不删除历史配置、订单、外部账号或操作日志，只停用访问。录单价格表/豆单选择必须按商品自定义产品类型分组并自动匹配同分类客户专属最新价格表，无专属则回退公共同分类最新版本，旧 `commercial/green/drip` 只做兼容 fallback。
- PR-381-CUSTOMER-PORTAL-TEMPLATE-BOUNDARY：客户档案不绑定能力模板，不做模板推荐，也不因开关打开要求选择模板；能力模板统一在“客户门户配置/门户客户配置”中选择、校验和变更。已开通但未绑定有效模板的客户可出现在门户配置默认列表，但不得进入履约客户候选、客户工作台入口或客户侧下单能力。
- PR-323-BEAN-LIST-DOWNLOAD-MATCH-PREVIEW-TYPOGRAPHY：产品价格表下载 PDF 必须与生成抽屉预览保持同一视觉语言，包含字体大小、粗字重、卡片行列、分类标题、商品名称换行和绿色/蓝色报价块排版。已保存的 `bean-list-preview-style-v1` PDF 缓存属于旧排版，下载时必须用 `bean-list-preview-style-v2` 或 `bean-list-preview-style-v3` 重新生成后覆盖，避免图一预览和图二下载字体/排版不一致。
- PR-332-BEAN-LIST-PDF-DENSE-PAGINATION：产品价格表预览样式 PDF 必须优先减少页面空白。生成器在卡片行放不下当前页时，必须先尝试 normal/compact/dense 三档，压缩卡片内边距、字号、行距和报价块高度，并在可读范围内截断过长风味/特点文案；只有 dense 密度仍无法容纳时才换页。已保存的 `bean-list-preview-style-v2` 或 `bean-list-preview-style-v3` PDF 缓存属于旧分页密度，下载时必须用 `bean-list-preview-style-v4` 重新生成后覆盖。
- PR-333-BEAN-LIST-PDF-NO-OVERLAP：豆单 PDF 紧凑排版不得把商品卡报价块、商品文字或卡片边框绘制到分类标题区域，也不得让分类标题压住下一行卡片。生成器必须保证卡片行高度不低于该密度下的实际可渲染高度；分类标题必须与第一行商品一起预留安全高度；当前组最后一行应尽量为下一组“标题 + 第一行商品”预留最小安全高度，必要时使用 compact/dense，但不能低于安全高度。已保存的 `bean-list-preview-style-v3` 问题缓存下载时必须用 `bean-list-preview-style-v4` 重新生成覆盖。
- PR-334-ORDER-ENTRY-GLOBAL-ERROR-TOAST：录单或修改订单保存失败时，前端校验错误和接口返回错误必须在当前视口内以全局错误提示弹出，不得只渲染在页面顶部导致底部点击保存时看不到；提示必须可关闭，并且不影响客户抽屉内局部错误展示。
- PR-335-ORDER-ENTRY-MOBILE-LAYOUT：手机窄屏录单和修改订单页面不得出现横向溢出；发货物流、收款凭证等条件面板必须改为单列展示，输入框、下拉框、文件上传控件和全局错误提示必须完整显示在手机视口内。
- PR-336-MOBILE-NOTICE-STACK：手机端 ERP 顶部提示必须支持多条排列展示。新订单等绿色/信息提示最多展示 3 条并按 iPhone 通知样式层叠；录单红色错误提示必须与顶部绿色提示分开，按顶部通知高度自动下移，不得互相覆盖。

## 2. 计价与单位（关键业务规则）
### 2.1 阶梯价
- 熟豆/常规豆单阶梯价源单位：**元/磅（lb）**；生豆豆单单价单位跟随生豆梯度模板，KG 模板发布为 **元/KG**。
- 换算：**1lb = 454g**。
- 阶梯匹配：按“**单行**”的折算磅数匹配阶梯档位。
- 当商品存在所选规格的专属梯度时，优先按该规格梯度匹配；当所选规格没有专属梯度时，必须用 `规格(g) × 数量 ÷ 454` 折算出的磅数匹配该商品已有豆单梯度，并自动给出单价和小计。
- 自动价匹配成功后，梯度提示必须高亮实际命中的档位 ID；即使当前录单规格是 1000g、2.5kg 等 KG 规格，而提示档位来自 454g 磅价梯度，也必须显示命中高亮。
- 录单展示单价单位必须跟随当前规格：454g 等磅制规格显示 **元/磅**；1000g、2.5kg 等公斤规格显示 **元/kg**。从豆单磅价换算成公斤价时，单价四舍五入取整数。
- 1000g、2.5kg 等 KG 规格如果存在专属梯度，梯度区间按 `规格(g) × 数量 ÷ 1000` 的总 kg 匹配，不按包装件数匹配；曲奇拼配这类 KG 梯度产品必须按总 kg 落档。

### 2.2 录单明细输入（规格 + 件数）
- 每一行明细代表“一个商品 + 一个规格”。
- 输入字段：
  - **规格(g)**：下拉（常用规格）；选择商品后默认使用该商品第一个价格梯度的规格；常用规格包含 **36g、80g、100g、227g、454g、500g、1000g、2.5kg**。
  - **数量(件)**：只能输入整数（不允许小数）。
- 计算：
  - 总重量(g) = 规格(g) × 数量(件)
  - 总重量(lb) = 总重量(g) ÷ 454

### 2.3 行小计与合计
- 单价：默认来自自动匹配的阶梯价，并换算成当前规格对应的展示单位。
- 商品选中后必须直接展示该商品所有梯度价格，便于对照规格、数量区间和单价。
- 商品梯度提示必须区分“区间单位”和“单价单位”：普通熟豆可按当前规格换算单价单位；生豆豆单的单价单位跟随发布快照的 `price_unit`。KG 生豆模板必须显示 `/kg`，产品价格表保存/发布生豆手工价时，`green_bean_sale_tiers` 必须保留 `price_unit=kg` 和对应 `price_per_kg`，同时可保留换算后的 `price_per_lb` 供兼容读取。
- 行小计：按当前展示单位计算；元/磅时使用总重量(lb)，元/kg 时使用总重量(kg)。
- 示例：榛巧类商品只有 454g 豆单梯度时，录入 1000g × 30 袋应按 30000g ÷ 454 ≈ 66.08lb 匹配 49lb+ 档；若该档为 48 元/磅，页面显示四舍五入后的 106 元/kg，小计为 106 × 30kg = 3180。
- 低于最低档：
  - 必须提示（非阻断）
  - 仍允许下单
  - 默认按“最低档单价”计算
  - 操作员可切换手动单价覆盖；手动单价按当前规格展示单位录入。

- PR-345-ORDER-CUSTOMER-PROFILE-BEANLIST-DRAWER：录单/编辑订单的订单信息区不再编辑来源、客户类型和订单类型；这些字段以所选客户资料为准，并在订单信息中只读展示。客户资料必须维护客户类型、来源和订单类型，缺失时客户资料保存失败，订单保存也失败。豆单版本选择入口迁到商品明细区的“选择豆单”抽屉，熟豆、生豆、挂耳三类已发布豆单均可在抽屉中选择；客户没有自定义豆单时自动使用公共豆单。
- PR-346-ORDER-SALES-NOTES-VOUCHER-SKU-SORT：录单或编辑订单时，填写物流费用后页面订单合计必须包含该物流费用，并在合计旁提示货款金额和物流金额；收款凭证上传后默认收起，点击收起后的凭证摘要可打开大图预览。生成销售单时，快递费备注、订单明细备注和销售单备注必须分别独立成行显示，空值不占行。
- PR-348-ORDER-BACKFILL-CONTINUOUS-MODE：录单页“订单补录”开关打开后进入连续补录模式。普通补录一张订单时只改订单日期并点“保存订单”即可；连续补录时点“保存并继续补录”必须保留客户、双日期、物流和豆单上下文，并清空商品、单号、收款凭证和订单专属费用/备注；点“保存并查看订单”仍按普通保存进入订单结果页。
- PR-287-ORDER-LIST-FEE-KG-SUBMISSION-REPAIR：ERP 订单列表金额列必须与履约运营台订单费用结构一致；客户工作台和小程序提交曲奇拼配等 KG 梯度商品时，必须按总 KG 匹配梯度并按元/kg 展示单价落单。
- PR-288-ORDER-SOFT-VOID-SHARED-BACKBONE：ERP 订单、履约客户订单和小程序订单必须是同一张 `orders` 订单的不同展示位置；订单失效后默认不展示且不可恢复，可筛选“已失效/全部”查看并复制为新订单，支持单条和批量失效。
- 从左侧菜单进入录单必须清除其他页面遗留的 `edit_id`、搜索和分页参数，保证进入的是新建订单；只有明确从订单详情编辑入口进入时才允许带订单 `edit_id`。
- 录单每个商品条目必须支持填写“条目备注”；条目备注保存到该商品行，编辑订单时按原商品行回显，不与订单级备注混淆。
- PR-310-ORDER-ENTRY-UNIT-AMOUNT-DISCOUNT：录单每个商品条目的“商品优惠”必须支持“单价优惠”。单价优惠按当前单价单位逐单位扣减：零售按件数、挂耳按袋/盒数量、454g 等磅制批发按总磅数、1000g/2.5kg 等公斤规格按总 kg；页面小计、保存后的行优惠、订单优惠和应收金额必须一致。

### 3.2 删除/作废规则
- 订单不允许真删除。
- 通过“失效”实现撤销：
  - 作废后列表默认不显示
  - 可筛选查看作废/全部
- 订单失效必须走 `orders.is_void` 软失效，不允许为 ERP 订单、履约客户订单或小程序订单维护多套订单框架。
- 已失效订单默认不进入 ERP 正常订单列表、履约客户订单、小程序订单和小程序账单；失效后不可恢复，操作员只能从 ERP 订单列表筛选“已失效/全部”查看并复制成新订单继续处理。

### 3.3 列表快速编辑
- 订单列表支持快速修改：收款状态、发货状态、备注。
- 所有修改必须写入审计日志。
- 订单列表必须支持范围切换：全部订单、我的订单、履约客户订单；“我的订单”按当前登录员工的订单负责人过滤，“履约客户订单”只展示 active、已开通客户门户/工作台、能力模板暴露 ERP 工作台或下单能力的客户订单；历史 active ERP 绑定如果指向零售商城、其他不暴露 ERP 工作台模板、客户门户/工作台开关已关闭或登录已停用的渠道账号，不得让该客户订单进入履约客户订单范围。
- 订单列表范围参数必须 fail closed：除空值、`all`、`mine`、`fulfillment` 外的 `scope` 值必须返回 400 `invalid scope`，不能静默放宽为全部订单。
- 新订单通知点击后必须进入订单列表，并自动带入对应订单范围和高亮订单。
- 订单列表必须按优先状态着色：通知跳转的新订单为绿色；未生产完成为黄色；未发货为蓝色；未付款为红色；新订单高亮优先于其他状态色。
- ERP 订单列表金额列必须展示费用明细，结构与履约运营台订单费用一致，至少包含商品金额、运费、优惠和应收，应收需要突出显示；有快递费说明或委外费用时，必须展示快递费说明和委外合计。
- ERP 订单抽屉必须展示订单收件人快照（收件人、电话、地址、公司）和费用明细，不得只依赖嵌入编辑表单查看。

### 3.4 订单列表快递录单 Excel
- 录单保存只负责订单本身，不得触发快递录单 Excel 生成。
- 订单列表提供快递处理入口，选择生产完成的订单后，系统使用服务器快递模板生成快递录单 Excel。
- 模板文件来自服务器 `/data/ship_temp.xlsx`，部署时同步到应用持久化目录供容器使用。
- 单订单 Excel 文件名包含订单日期、客户姓名和订单号；批量生成时文件名包含日期和订单数量。
- 收件人信息来自客户档案；寄件人姓名、电话、地址、公司和业务类型来自系统“发货人设置”的默认寄件人。
- 发货人设置支持维护多个寄件人，并指定一个默认寄件人；订单列表生成快递录单时可先选择本次默认寄件人，也可对部分已勾选订单单独选择寄件人。
- 订单列表展示列必须收敛，快递信息必须合并展示寄件人和快递单号，订单状态必须合并展示收款、发货、生产和发票状态。
- 订单抽屉“快递信息”不得展示“加入本次快递录单”复选项；寄件人默认跟随顶部全局“本次寄件人”，并可在抽屉中直接改为任一寄件人。
- 点击订单号打开订单抽屉后必须可直接编辑订单并保存；订单列表和订单抽屉不得再提供独立“编辑”跳转入口。
- 单个订单快递单号必须在订单抽屉内回填，不再在订单列表顶部展示本批次单号输入框；一个订单允许维护多个快递单号，输入时可用换行、逗号或分号分隔，系统必须追加去重并保留旧单号。
- 订单快递单号必须以订单级子表保存，`orders.ship_tracking_no` 仅作为列表、小程序和旧接口兼容汇总字段；订单列表搜索必须能用任意一个快递单号命中订单。
- 包裹件数固定为 1，托寄物默认 **茶叶**，重量固定为 **0.1kg**。
- 备注填写本次订单明细，包含订单号、商品名、规格和数量，不写入单价和小计。
- 快递录单 Excel 生成失败时必须清理刚写入的文件，不会留下公开孤儿快递录单文件；排除错误后可重新生成快递录单 Excel。
- 生成快递录单 Excel 后支持上传顺丰寄件列表回传 Excel，系统读取 `运单号` 和 `备注/备注订单号/订单号` 列，从备注中的 `SO...` 订单号匹配订单并回填快递单号；同一订单多行或同一单元格多个单号必须归并到同一个订单。
- 物流单号 Excel 上传超过 20MB 时必须拒绝，不能解析超大物流回传 Excel；接口返回 `file too large` 后由操作员压缩或拆分文件再上传。

### 3.5 销售单预览与下载
- 订单销售菜单不得再提供独立“报价导出”页面；对外销售资料导出集中在销售单、出库单等订单抽屉内完成。
- 旧 `/products/print` 入口不得再打开报价导出页面，避免操作人员继续使用已下线页面。
- 订单列表每行“销售单”必须在当前订单列表中打开销售单抽屉，避免离开当前筛选和分页上下文。
- 销售单抽屉内必须提供“销售单设置”入口，可再打开设置抽屉维护收款方式、说明、收款码和公章。
- 销售单页面必须先展示预览，操作员确认后才生成正式 PDF 版本；刷新预览不得新增历史版本。
- 销售单预览、PDF 和图片导出必须在商品明细中展示每个商品条目的条目备注；空条目备注可以显示为空或 `-`，不得影响生成。
- 销售单商品名称过长时，预览、PDF 和图片导出必须在商品列内换行并按最高列内容撑高行高，不得与规格、数量、单价、小计和备注互相重叠。
- 销售单历史版本和最新版都必须支持下载，历史版本 PDF 下载 URL 必须正确解析文档 ID，不得返回 `invalid document id`。
- PR-350-COMBINED-ORDER-DOCUMENTS：订单列表必须提供“组合单据”选择列和组合销售单入口；选择同一客户至少两个订单后，可预览组合销售单 PDF 并确认生成。组合销售单必须保留各订单分组、订单日期、商品明细、小计和汇总总商品金额、优惠、运费和应收，顶部展示一个单据日期和关联订单；生成组合销售单必须写入 `combined_sales_order_document` 操作日志。
- PR-354-COMBINED-DOCUMENT-REUSE-SINGLE-UI：组合销售单入口不得打开另一套简化界面，必须打开销售单抽屉并传入所选订单；抽屉内继续显示销售单设置、客户信息、销售单备注、预览、PDF 版本和图片版本栏目，预览、生成 PDF、生成图片和历史版本内容按组合订单接口读取。
- PR-355-COMBINED-SALES-DOCUMENT-LAYOUT-PAGINATION：组合销售单预览、正式 PDF 和图片版本必须使用普通销售单标题风格；头部只展示客户信息、单据日期、关联订单和地址，不显示组合单号或订单数。订单分组标题显示订单日期，不显示订单号，商品明细和小计保持原组合内容。PDF 超出第一页可用空间时把说明和收款码移到续页并加页码；图片版本导出为一张长图。
- PR-356-SALES-ORDER-PAYMENT-OVERLAY-MULTIPAGE：销售单预览组件渲染多页 PDF 时，收款文字框和收款码框不得固定按第一页定位；必须按预览 PDF 页数选择续页，并沿用后端 PDF 页边界规则保证拖拽框可见，保存后刷新预览仍能继续调整。
- PR-357-SALES-ORDER-PAYMENT-OVERLAY-CROSS-PAGE：PDF 预览拖拽组件必须支持带标记的收款布局框跨页移动；收款文字框/收款码框从第 2 页向上拖过页顶时应切到上一页，向下拖过页底时应切到下一页，且保存时保留当前页码直到刷新预览完成。
- PR-358-COMBINED-SALES-GROUP-ORDER-DATE：组合销售单 PDF/PNG 渲染必须复用同一个分组标题规则：每组第一行写“订单日期 2026-xx-xx”，订单号不出现在分组标题里。
- 公司名称统一在全局“公司设置”中维护；销售单设置不再维护公司名称。
- 销售单预览必须展示与 PDF 一致的收款码、公章、多行收款方式和多行说明；公章支持拖动位置和调整大小，并盖在公司名称附近；点击公章内部开始拖动时公章不得跳走；导出 PDF 不得拉伸公章图片。
- 销售单收款码上传只接受图片文件，不能上传 HTML 或脚本文件作为收款码；收款码图片超过 8MB 时必须拒绝，图片过大或格式不支持时接口返回无效请求；销售单收款码上传必须先填写标签，标签为空时不能写入收款码资产，操作员补齐标签后再上传。
- PR-328-SALES-ORDER-PAYMENT-CODE-SOFT-DISABLE：销售单设置点击收款码“停用”后，只能将该收款码置为 inactive 并从销售单预览、PDF/图片生成中隐藏；设置页必须继续展示停用状态并支持点击“启用”恢复；不得删除 `sales_order_payment_codes` 记录、`sales_order_assets` 素材记录或已上传图片文件，操作日志必须显示为停用/启用而不是删除。
- 销售单公章上传或去除背景失败时必须清理刚写入的公章资产，不会留下公开孤儿公章文件；操作员排除错误后重新上传公章。
- 销售单 PDF/图片生成失败时必须清理刚写入的文件，不会留下公开孤儿销售单文件；操作员排除错误后重新生成销售单 PDF 或图片。
- 销售单预览必须按下载 PNG/PDF 同一张 A4 页面比例显示，公章坐标从页面左上角计算，预览和下载中的公章位置、大小不得明显不一致。
- PR-277-DOCUMENT-PDF-PREVIEW-STAMPING：销售单预览必须使用后端渲染的 PDF 预览，页面和预览 PDF 内都显示“PREVIEW 预览版”；预览中拖动公章只保存设置，不新增正式版本，只有点击确认生成 PDF 或图片后才新增正式历史版本。
- PR-279-DOCUMENT-SEAL-ASPECT-SCALE：销售单、出库单和合同盖章必须按公章原图比例预览和写入 PDF，圆章不得被压成椭圆；预览页必须提供公章大小滑轨，调整后保存到后续新生成文件。
- 销售单和出库单预览页必须支持直接拖动公章并保存坐标，保存坐标不得覆盖销售单说明、收款方式等文本设置；后续重新生成销售单 PDF、PNG 图片或出库单 PDF 时必须使用最新公章坐标。
- 公章设置页只维护共享公章资产，必须支持上传公章、选择当前公章、对当前公章执行去除浅色背景；销售单、出库单和合同盖章必须共用这一套公章资产。
- 上传或处理销售单公章时必须自动裁掉明显白边/透明边；调整公章大小后必须自动保存，后续重新生成销售单 PDF 或 PNG 图片时使用最新尺寸。
- 公账收款信息统一在全局“公司设置”中维护，包含公司地址、纳税人识别号、户名、开户行和收款账号，并支持一键复制公账收款信息；销售单设置不再维护公账字段。
- 销售单预览和 PDF 中客户公司地址必须完整换行显示，不得被截断；收款码必须按数量自适应填充空白，单个收款码放大展示，多个收款码可竖向排列。
- 销售单结算区必须先展示订单备注，再在最后一行同排展示商品合计、优惠合计、运费和应收；销售单备注保存后在预览、PDF 和图片的结算倒数第二行展示。
- PR-307-SALES-ORDER-PAYMENT-LAYOUT：销售单收款码默认必须固定在第 1 页右侧并比旧版更大；销售单预览必须支持直接拖动和拉伸收款码区域，以及收款方式、个性化说明和公账收款文本框；销售单设置页不得要求操作员手填 A4 坐标；个性化说明必须优先显示在公账收款前面；预览 PDF、正式 PDF 和 PNG 图片必须使用相同布局设置。
- PR-308-SALES-DOC-PREVIEW-LAYOUT-AND-SEALS：销售单预览必须直接拖动/拉伸“文字位置和大小”“收款码位置和大小”；公章设置只保留上传公章、选择公章、去除背景，销售单、出库单和合同盖章共用同一套公章资产。
- 销售单必须支持分享到微信；分享 PDF 和图片时必须直接分享文件，不得把分享链接作为默认分享内容；浏览器不支持文件分享时提示下载后手动发送。
- 销售单生成的 PNG 分享图片必须使用高清画布，整体文字要比普通预览更清晰偏粗，收款二维码必须放大到微信可识别的尺寸。
- 销售单、出库单等资源对外分享必须使用同一套外部分享资源 API、token、公开文件访问和前端文件分享逻辑，不能各自复制一套分享实现。

### 3.5.1 合同盖章
- 订单销售菜单必须提供“合同盖章”入口，用于上传、预览、盖章和保存合同 PDF。
- 合同上传必须支持 PDF 和 DOCX；PDF 上传后直接进入盖章流程，DOCX 合同上传后先转换为 PDF，再进入盖章流程。
- 合同盖章必须复用共享公章资产和透明裁边处理结果，并提供公章选择；没有公章时提示先到公章设置维护公章。
- 合同 PDF 必须按页展示，操作员可以在多页拖动公章位置，每页位置独立保存到盖章版本记录。
- 合同盖章页必须支持通过公章大小滑轨统一缩放当前待盖章印章，预览和保存盖章 PDF 都必须按公章原图比例绘制。
- 点击“保存盖章PDF”后必须生成并保存盖章后的 PDF，历史盖章版本和最新版都能下载。

- PR-278-CONTRACT-WORKSPACE-SAVE-DELETE：合同盖章页必须提供合同标题和备注可保存，保存到数据库；删除合同执行软删除，从合同列表隐藏，但历史审计、源文件和盖章文件保留。

### 3.6 出库单维护与下载
- 订单列表中已发货订单必须提供“出库单”入口，并在当前订单列表中打开出库单抽屉。
- 出库单页面必须支持维护出库日期、出库仓库、发货方式、快递单号和备注。
- 出库单预览和 PDF 必须在对应商品行展示录单商品条目的条目备注，便于仓库按单个商品说明发货。
- 出库单必须先展示预览，操作员确认后才生成正式 PDF 版本；刷新预览不得新增历史版本。
- PR-277-DOCUMENT-PDF-PREVIEW-STAMPING：出库单预览必须使用后端渲染的 PDF 预览，页面和预览 PDF 内都显示“PREVIEW 预览版”；预览中拖动公章只保存设置，不新增正式版本，只有点击确认生成 PDF 后才新增正式历史版本。
- 出库单预览必须提供公章大小滑轨，调整后保存销售单公章尺寸；圆章在预览和后续生成 PDF 中不得显示为椭圆。
- 未发货订单不得生成出库单预览或正式出库单。
- PR-350-COMBINED-ORDER-DOCUMENTS：订单列表组合出库单入口只允许同一客户且均已发货的至少两个订单；组合出库单必须按订单分组展示单据日期、订单日期、出库日期、收件人、快递单号、出库仓和商品明细；生成组合出库单必须写入 `combined_delivery_note_document` 操作日志。
- PR-354-COMBINED-DOCUMENT-REUSE-SINGLE-UI：组合出库单入口不得打开另一套简化界面，必须打开出库单抽屉并传入所选订单；抽屉内继续显示刷新预览、下载最新版、公章设置、出库维护、预览和历史版本栏目，预览/生成/历史版本内容按组合订单接口读取。
- 出库单历史版本和最新版都必须支持下载，历史版本 PDF 下载 URL 必须正确解析文档 ID。
- 出库单必须支持分享到微信；分享的是已生成的出库单 PDF 文件，不得把分享链接作为默认分享内容。
- 出库单必须支持共享公章设置，公章上传、选择、去背景与销售单和合同使用同一套资产；预览可拖动公章并调整尺寸，后续新生成的出库单 PDF 必须使用最新公章位置。
- 出库单 PDF 生成失败时必须清理刚写入的文件，不会留下公开孤儿出库单文件；操作员排除错误后重新生成出库单 PDF。

### 3.7 发票申请与文件
- 订单列表必须提供“发票”入口，并在当前订单列表中打开发票抽屉。
- 发票抽屉必须支持对订单申请发票，并在订单列表显示未申请、已申请、已上传状态。
- 开票完成后必须支持上传发票文件，文件类型仅允许 PDF 和常见图片（PNG、JPG、GIF、WebP）。
- 上传后的发票文件必须能从发票抽屉和订单列表打开查看。
- 发票文件上传必须先确认订单存在；订单不存在时返回 order not found，不会写入发票资产文件。
- 发票文件保存失败时必须清理刚写入的发票资产文件，不会留下公开孤儿发票文件；操作员排除保存错误后重新上传发票。

- PR-374-COMPOSABLE-PRODUCT-PRICING：商品配置不得新增固定 `cost_model` 枚举或把产品类型写死为几种公式。产品价格必须由 SKU 分类、商品配置、单位模板、BOM 用料、阶梯价模板和价格表生成规则组合生成。速溶盒装这类产品可把原料按 `unit_per_box` 配置为“每盒 10 条、每条 10g”，成本核算按每报价单位汇总 BOM 成本，再按阶梯模板利润率生成 `元/盒` 等自定义单位价格；产品价格表、发布快照、录单阶梯和 PDF 都必须保留自定义展示单位，不能回退为磅或 100g。
- PR-375-PRODUCT-PRICE-BOM-OPERATION-WORKFLOW：产品价格表生成区和下方预览卡片必须按 SKU设置 的产品类型动态展示，不再按旧商用/零售/生豆/挂耳枚举固定卡片。商品配置的价格表生成规则支持填写固定单价和成本加成比例；固定单价按阶梯价模板单位直接生成价格，成本加成按 BOM 成本和工序成本加成。工序模板必须进入成本核算、生产开工、工单和生产成本：商品配置/产品子类型绑定的工序模板生成生产工单工序卡，工序成本计入产品价格和批次生产成本。客户复制公共商品配置模板时不得切回公共 SKU 视角，不得删除或污染公共模板，只在当前客户下新增客户模板。
- PR-376-PRODUCT-CONFIG-SPECIAL-KV-PRICE-LIST：历史阶段曾由商品配置模板维护“特殊 KV 定义”，SKU 填写 `special_attrs_json`，产品价格表、发布快照、公共页面和 PDF 携带已勾选展示的特殊 KV。PR-389 后新 UI 不再在 SKU/商品配置模板维护特殊属性，价格表展示优先读取 BOM 版本 `special_attrs_json`，旧 SKU 字段只作为 fallback。固定单价规则仍必须填写 `fixed_unit_price`，成本加成规则仍必须填写 `cost_plus_rate`，前后端都要拒绝空配置。客户复制公共商品配置模板必须幂等：同一客户复制同一公共模板只返回已有客户模板，不重复生成，不切回公共 SKU，不污染公共模板；复制后该客户模板列表隐藏已经派生过的公共原模板。
- PR-377-PRODUCT-CONFIG-KV-SKU-REFERENCE-LAYOUT：历史“产品信息字段（特殊属性KV）”入口已由 PR-389 收敛到 BOM 版本特殊属性。SKU 列表仍必须横向适配页面，产品类型、产品子类型、商品编号、商品名、归属等列保持一行展示，超出宽度通过横向滚动配置，不允许出现产品类型一个字一行。客户复制公共商品配置模板只复制商品配置模板，不再开启公共 SKU 引用；客户要复用 SKU 时按 PR-382 的“SKU复制”生成客户自己的 SKU。
- PR-378-PRODUCT-CONFIG-KV-OPTIONS-EDITOR：历史商品配置模板特殊 KV 下拉选项 helper 保留兼容，不能破坏旧 `special_attrs_json` 解析；PR-389 后新 UI 不再渲染商品配置模板下拉选项编辑器，字段定义和值改在 BOM 版本草稿中维护，已发布版本只读。
- PR-380-CUSTOMER-CATEGORY-PUBLIC-SKU-REFERENCE：历史方案为“复制公共分类后引用公共 SKU”，已由 PR-382 取代。新版复制公共分类只生成客户自己的分类结构和商品配置绑定，不再自动开启公共 SKU 引用；客户需要整套产品时通过“SKU复制”从公共 SKU 或其他客户复制，生成客户自己的 SKU 主档。
- PR-382-SKU-UNIFIED-CREATE-COPY：SKU 主流程统一为“新增SKU”和“SKU复制”。公共视图和客户视图都只有一个“新增SKU”，表单只填写 SKU 名称、备注、产品类型和产品子类型，归属由当前 SKU 视图决定，不再区分公共 SKU、客户 SKU、定制 SKU、基础产品或产品形态。SKU复制从 SKU 列表右上角进入，来源可选公共 SKU 或其他客户，交互按产品价格表的“选择分类和产品”分组选择，支持总复选框、全选、清空、产品类型/子类型/SKU 行勾选；同名同归属同分类时覆盖并保留目标 SKU ID，覆盖资料、特殊 KV、商品配置绑定、单位/工序覆盖、BOM 和价格阶梯，已发布价格表快照不回改。复制时目标没有对应产品类型/子类型，后端自动复制分类结构；BOM 成品组件和生豆绑定熟豆必须重写为目标客户同批复制或同名同分类 SKU，无法解析时拒绝复制，避免客户 SKU 引用来源客户 SKU；停用 SKU 不参与复制。商品分类维护从 SKU 列表低频入口移到“商品配置 → 商品分类管理”页签。
- SKU设置页必须给公共 SKU 和客户专属 SKU 增加“备注”字段；新增SKU抽屉和客户SKU列表行内编辑都能保存备注到 SKU 主档；备注列必须放在客户SKU列表最右侧。
- SKU设置页的客户SKU列表必须支持按搜索关键词、产品类型和产品子类型过滤；搜索关键词必须能匹配商品名称、商品编号、历史兼容类型标签和备注。
- PR-312-SKU-CATEGORY-RECREATE-AFTER-DELETE：SKU设置中删除客户自己的产品类型或产品子类型后，必须允许在同一客户归属下重新新增同名分类。软删除历史记录继续保留审计和追溯，但不得触发 `product_categories_customer_parent_name_uniq` 阻止同名重建。
- PR-313-CUSTOM-ROAST-NO-BASE：历史“定制烘焙度”创建表单已被 PR-382 的统一“新增SKU”取代。新版新增 SKU 不选择基础产品、不展示复制基础产品 BOM/价格梯度，也不提交 `base_product_id/custom_type/copy_bom/copy_price_tiers`；需要复用已有 SKU 时统一通过“SKU复制”复制成客户自己的 SKU。
- BOM配置 / BOM 配方维护页也必须按“SKU归属”过滤：默认公共SKU；选择客户SKU后，只展示该客户需要维护 BOM 的熟豆、挂耳等 SKU 的 BOM 列表和商品选择；已绑定熟豆 BOM 的生豆 SKU 不出现在 BOM 配方维护候选中，避免被误认为需要单独维护一个 BOM；客户选择列表只存在有可维护 BOM SKU 的客户。从 SKU设置点击“维护 BOM”进入时，BOM 页必须自动定位并过滤到该 SKU 的 BOM，同时提供“显示全部 BOM”恢复当前归属完整列表。
- 商品失效必须采用软失效：产品标记为 `active=false`，不再出现在录单、报价、成本候选等新业务选择中；历史订单、历史豆单、历史成本记录继续可追溯。
- 产品失效时，对应当前 BOM 必须同步标记为 BOM失效，不能删除 BOM 明细和历史版本。
- BOM 维护页的“删除当前 BOM”必须改为“失效当前 BOM”；BOM失效后保留配方明细，重新同步出品率、保存配方或启用历史版本后可恢复为有效 BOM。
- 成本核算读取到 BOM失效 的产品时，必须展示 “BOM已失效” 警示；发布价格策略或豆单前，操作员必须先确认或重新启用 BOM，系统不得静默忽略失效状态。

### 4.1 梯度模板与价格来源
- SKU设置页必须支持维护“梯度模板”：一个模板包含多个梯度档位，每档可自定义区间名称、按模板展示单位录入最小/最大数量，系统后台换算并保存克重区间用于匹配，并设置利润率。
- 一个梯度模板只能选择一个展示单位（元/磅、元/kg、元/227g、元/100g、元/250g），同一模板内不能混用展示单位；选择元/磅时 1 个单位按 454g 换算。
- 每个商品配置模板可绑定一个启用中的阶梯价模板，绑定该商品配置的产品子类型自动继承模板。商品配置模板的阶梯价下拉必须允许选择公共模板和当前客户自己的模板；阶梯价模板面板必须提供显式“复制为客户模板”入口，让客户先复制公共模板再改名、调整档位和利润率。复制后当前客户模板列表隐藏已经派生过的公共原模板，不影响公共模板和其他客户。
- SKU设置页的“客户SKU列表”必须支持公共 SKU 和客户自有/客户定制 SKU 的产品级利润率覆盖；产品行填写 `margin_rate_override` 后，成本试算和商用豆单预览使用该产品利润率覆盖产品子类型绑定的梯度模板利润率；清空后恢复继承产品子类型模板。客户上下文中的公共 SKU 引用仍只读，必须先复制为客户 SKU 后才能维护客户自己的覆盖利润率。
- 成本试算和商用批发豆单预览必须按产品所属产品子类型的梯度模板生成商用梯度价格；未绑定模板的分类继续使用系统默认商用梯度。
- 价格来源解释必须覆盖快速成本参数和模板参数，包括生豆成本、BOM/产品出成率、kg/lb 换算、生产成本、包装成本、损耗、税费、梯度利润率和最终价格。
- 价格来源解释中的生豆成本来自 BOM 物料的当前可用批次成本：按 `Σ(批次当前可用克重 × 批次单位成本) ÷ Σ(批次当前可用克重)` 计算加权平均；没有可用批次时才回退物料默认采购价。
- 产品价格表不提供独立价格试算工作区，但商用价格来源抽屉必须保留生豆成本、出成率和利润率的临时试算；临时试算不保存成本参数、BOM/产品出成率或梯度模板，交易价格仍需管理员重新发布豆单后才生效。
- 梯度模板或快速成本参数修改后，只影响未发布的成本试算和豆单预览；已发布豆单和交易价格必须保持发布时快照，只有管理员重新发布价格/豆单后才生效。

### 4.2 豆单发布
- 官方豆单用于棵凡对外公开链接。
- 客户豆单发布后必须锁定为客户自己的内容和价格快照，后续官方豆单更新不得自动改写客户已发布豆单。
- 客户生成豆单时可复制官方已发布豆单的报价、风味、特点和出品建议作为价格来源。
- 客户生成豆单的默认版本号必须从当前客户已发布版本或复制的官方价格源版本递增一小步，避免新客户豆单沿用来源编号；例如 `V1` 默认 `V1.01`，`V1.01` 默认 `V1.02`，`V3.0.5` 默认 `V3.0.6`。
- 生成豆单不再提供“复制已有豆单配置”。系统按当前 SKU、商品分类、梯度模板和本次抽屉设置直接生成；如果客户需要差异化 SKU 或分类，必须先在 SKU设置 中完成。
- 产品价格表页面的预览卡片必须按 SKU设置 中的产品类型动态生成并支持收起/展开，不再固定为商用批发、挂耳、零售、生豆四张旧卡片；生豆产品类型仍可直接修改每个档位销售价，生豆档位区间和输入/发布销售价都按模板单位展示与保存，KG 模板按元/KG 保存，并提供“保存生豆价格”入口，把当前页面豆单范围下的生豆价格保存为草稿；挂耳等产品类型通过生成抽屉中的产品类型选择生成，不再提供外层独立“生成挂耳豆单”按钮。
- PR-BEANLIST-VERSION-001：豆单发布必须形成版本列表；版本列表入口必须在产品价格表中直接可见，页面顶部豆单范围按单一归属展示“公共豆单”和每个履约客户（如岩师傅、用户A），选择某一项后只展示该归属的版本，并支持按豆单类型查看；每个发布版本的配置、内容和 PDF 资产按版本缓存，生成过一次后复用缓存，不重复渲染。
- PR-BEANLIST-VERSION-002：ERP 录单必须按熟豆、生豆、挂耳分别记录本单商品行使用的豆单版本。客户有专属豆单时各类型默认选最新专属版本并允许选择历史发布版本；客户没有专属豆单时对应类型自动使用公共豆单。
- PR-BEANLIST-VERSION-003：小程序默认展示当前客户最新可用豆单；客户首次按新版豆单下单前必须看到更新提示，提示包含新增、下架和调整摘要，确认后写入已读记录，后续不重复提示。
- PR-383-CUSTOMER-MANAGEMENT-PORTAL-WAREHOUSE：门户客户配置不再提供“豆单展示版本”开关；客户侧豆单按已发布客户专属豆单和公共兜底规则读取，历史报价通过价格发布版本和订单快照追溯。

### 4.3 生豆销售（PR-289-GREEN-BEAN-SALES）
- 生豆销售必须融合现有产品体系：SKU设置、录单、订单明细、豆单发布、履约客户订单和商城订单共用 `products` / `order_items` 底层，不新增一套孤立生豆商品逻辑。
- SKU设置必须支持产品形态：熟豆和生豆。生豆产品不要求烘焙度、BOM 出品率或销售价，但必须选择单品/拼配并绑定对应熟豆 BOM。
- 客户 SKU 列表默认公共 SKU，必须支持形态过滤、名称搜索、产品类型过滤和产品子类型过滤；公共 SKU 列表不得维护销售价。
- 生豆销售价格只能来自生豆豆单发布快照。生豆 SKU 绑定熟豆 SKU 后使用该熟豆的 BOM 作为成本来源，但不得继承熟豆销售价或熟豆阶梯价。
- 生豆豆单自动生成价只作为成本参考：拼配按绑定熟豆 BOM 中各生豆原料的 `unit_cost_snapshot` 加权计算，单品也取绑定熟豆 BOM 中对应原料成本快照；不读取原料库存批次的实时成本，不套用熟豆利润公式。
- 生豆豆单选择梯度模板后只带出档位区间，每个档位销售价按模板单位手工修改；KG 模板按元/KG 修改并发布，手工价只保存到本次豆单草稿/发布快照，不回写 SKU、BOM、物料档案或梯度模板。生豆 SKU 没有挂到带生豆模板的生豆分类时，产品价格表必须提示无法生成生豆价格，并引导到 SKU设置 调整分类。
- ERP 录单必须保留生豆 SKU 的 `green_bean` 产品形态；保存生豆订单时必须按所选生豆豆单版本匹配 `green_bean_sale_tiers`。缺少生豆豆单价格时必须拒绝保存并提示缺少生豆豆单价格，不能退回熟豆阶梯价，也不能保存 0 价。
- ERP 录单展示和自动匹配生豆 SKU 梯度时，必须读取当前客户默认/所选已发布生豆豆单快照中的 `green_bean_sale_tiers`；不得用 `product_price_tiers`、绑定熟豆 SKU 梯度或同名熟豆 SKU 梯度展示生豆价格。
- 产品价格表必须支持生豆豆单，导出 PDF 时展示生豆豆单标题、展示信息、最新通过生产质检信息和梯度模板生成的生豆销售报价。
- ERP 录单必须能选择生豆产品，规格可选择或直接输入自定义克数；保存订单时要在订单行记录产品形态快照；订单列表必须一眼区分生豆、熟豆和混合订单。
- 小程序履约客户的现货/代发/代加工目标产品选择器必须能展示当前客户可见的生豆产品，并按已发布生豆豆单价格写入 ERP 订单。
- 小程序商城必须能上架生豆产品，商品卡、购物车和 ERP 商城订单承接保留生豆产品形态。
- 原料入库必须支持产季、产地、产家风味描述；入库质检必须支持工厂风味描述、水分和密度。入库质检是仓库必要流程，不作为生豆豆单质检来源。

## 4.5 生产制造（Production）
- 生产管理必须提供“生产验收”入口，用于上线后快速检查仓库、原料、WIP、工单、生产日志、质检和成品追溯是否具备。
- 生产计划页面不再展示单独的“物料需求计划”；库存充足和库存不足必须分开展示。库存充足只提示，不进入生产计划；库存不足标题左侧提供唯一批量复选框，勾选即全选库存不足行、取消即全不选，单独勾选部分行时显示半选减号；生成计划后仍需在物料需求汇总中看到 WIP 可用和建议领到 WIP。
- 生产计划开工前如果 WIP 仓多个物料都不足，系统必须返回一条汇总错误并一次列出所有不足物料，不得只提示第一个不足项。
- 生产计划“烘焙建议”必须允许操作员手动修改推荐机器、每锅数量和锅数，修改后实时重算最终投料数用于开工。
- 生产计划“烘焙建议”在修改每锅数量或锅数后，必须实时计算并显示预计成品(kg)，计算口径为 `最终投料 × BOM出品率`。
- 生产计划“烘焙建议”损耗比展示必须与“生产计划（缺口 > 0）”BOM 出品率使用同一数值和同一精度规则（例如统一显示 81.50%）。
- 录单保存前如果成品库存批次足够，必须提示可用批次并让操作员选择是否使用；选择使用时订单生产状态改为“库存待发货”，选择不使用时记录为待生产，生产计划按库存不足处理。
- 库存充足但操作员不使用现有批次时，系统不得把物理库存扣掉或占掉；只记录订单库存决策为待生产，并在生产缺口中按该订单的完整需求量处理。
- 选择使用成品批次或历史库存余额时，保存订单只记录预留，不扣物理库存；回填快递单号并把订单标记为“已发货”时，系统必须扣减成品批次或 `finished_inventory`、写库存流水，并保证重复回填不会重复扣库存。
- 生产计划不得把已发货订单计入待生产需求；库存待发货但尚未发货的预留量必须占用可用成品库存，避免后续订单重复使用同一库存。
- 生产计划待生产汇总只纳入已绑定商品 SKU 的订单明细和代加工生产需求；历史订单明细 `product_id` 为空、无效或未绑定时不得导致生产计划接口报错，也不得生成无 SKU 工单。
- 生产中完工把订单推进到“生产完成”前，必须核对同一订单所有已绑定 SKU 明细都没有剩余生产缺口；多品项订单只完成其中一项时必须保持“生产中”，不能提前进入可发货状态。
- 订单列表“只看可发货”必须同时包含“生产完成”“无需生产”和“库存待发货”的订单。
- 生产工单必须展示 WIP 已占、已耗和剩余占用。
- 仓库库存必须能快速打开 WIP占用抽屉，按工单查询、调整占用量或释放废弃工单占用；调整/释放必须写入审计日志。
- 库存作业中的原料入库、WIP领退/转仓、成品转仓选择物料或成品时，必须在下拉框内支持名称/编号模糊搜索，不得额外放独立搜索框。
- 原料入库单价必须写入该入库批次的单位成本，不得通过修改物料档案价格来改历史库存成本；物料默认采购价只作为没有可用批次或补录未填成本时的兜底参考。
- 库存调整单必须支持“库存数量”和“批次成本”两类调整；批次成本调整只能选择当前可用原料批次，填写目标成本/千克后更新该批次成本，并记录调整前成本、调整后成本和库存价值变化，不产生数量流水。库存数量调整和批次成本调整都必须写入操作审计日志。
- 成本核算使用当前可用原料批次加权平均成本；冻结、待处理和不通过的批次不得参与可用库存加权平均。
- 原料数量补录生成新补录批次时，可以填写补录成本/千克；未填写时使用物料默认采购价，避免补录批次以 0 成本污染后续加权平均。
- 四个库存作业页面必须使用类似仓库库存的面板、网格和表格排版，输入框高度、列宽和间距保持对齐。
- 仓库库存批次追溯必须区分成品批次和原料批次：`FP-...` 展示成品到工单、生产日志、原料消耗的追溯链；`MB-...` / `LEGACY-MAT-...` 展示原料批次和当前仓库位置。`LEGACY-MAT-...` 必须说明是系统升级按旧物料库存生成的期初批次。
- 生产中完成生产时如果 WIP 仓库存不足，必须在当前页面右侧打开库存作业抽屉，并默认进入 WIP 领退/转仓以便补领原料。
- 生产质检必须支持记录原料、生产工单和成品批次的检查结果，结果包含通过、待处理/待定、不合格/不通过，并统一归一化保存。
- 生产质检页面必须采用仓库库存式工作台布局，支持从右侧抽屉选择质检对象；按钮必须按当前质检类型显示为“选择工单”“选择原料批次”或“选择产品批次”，抽屉打开后只展示当前类型对应的对象，并把选中的工单号或批次号回填到质检表单。
- 质检结果为待处理或不通过时，关联原料批次、WIP 批次或成品批次必须显示质检状态；冻结批次不得被领料、生产扣料或成品出库/转仓误用。
- 生产验收检查项点击“打开”时，仓库相关入口必须直接进入对应仓库和库存类型，而不是全部仓库。
- 生产流程用户手册必须作为新员工的一页式流程导航，同步说明生产验收、录单批次确认、库存待发货、拒绝使用批次进入生产计划、建议领到 WIP、WIP 占用处理、部分完工、生产质检和批次追溯操作。
- 只有管理员可以发布或撤回豆单；客户登录后只能保存自己的豆单修改并下载/打印 PDF。

## 5. 客户档案（Customers）
### 5.1 客户字段
- 客户至少包含：
  - 客户名（正式）
  - 客户类型：零售客户、批发客户、电商客户、渠道客户
  - 联系人（姓名）
  - 电话
  - 地址
  - 启用/停用（active）
  - 默认来源（default_source_id）
  - 默认订单类型（default_order_type_id）
  - 负责人（responsible_employee_id）：必填，只能选择启用的内部员工，不能选择外部客户账号或客户档案
  - 原始信息（raw_name，仅保留，不影响展示）

### 5.2 客户维护
- `/app/customers`：客户列表不再展示独立“编辑”操作列；点击客户名称打开右侧抽屉，在抽屉内查看详情、编辑字段、查看统计和维护客户附件，保存后写日志并刷新列表。
- 客户详情抽屉只展示当前客户的档案、统计和附件，不再在抽屉底部嵌套一个只含当前客户的二级列表或二级编辑界面。
- 客户类型、默认来源和默认订单类型为必填项；历史缺失客户保存前必须补齐，录单保存也会校验这三项。
- 客户档案只维护客户类型和“开通客户门户/工作台”开关；是否开通小程序商城、客户工作台或下单能力，由门户客户配置中绑定的能力模板决定，不能仅凭客户类型自动开通或自动绑定模板。
- 支持停用/“删除”：
  - 客户删除采用安全策略（不真删，改为停用）。
- 支持“一键复制发货地址”：复制格式固定为：
  - 姓名：xxx（联系人为空则用客户名）
  - 电话：xxx
  - 地址：xxx
- 客户档案附件用于维护标签正面、标签背面和客户 Logo 等图片；上传只接受 PNG/JPEG/WebP 图片，客户档案资产图片上传超过 8MB 时必须拒绝，由操作员压缩到 8MB 内后再上传；客户档案资产元数据保存失败时必须清理刚写入的文件，不会留下公开孤儿客户资产，操作员应重新打开客户档案确认附件列表。
- PR-327-CUSTOMER-RESPONSIBLE-EMPLOYEE：新增或保存客户资料时必须指定负责人；负责人候选只能来自员工维护中的启用内部员工。客户负责人变更必须写入操作日志，供“操作日志”追溯。

### 5.3 客户快速录入
- 客户新建/编辑页支持“快速粘贴”一整段文本，一键解析到：姓名/电话/地址。

### 5.4 客户联动录单
- 录单选择客户后：
  - 自动**覆盖**录单的“来源/订单类型”（来自客户档案默认值）
  - 自动带入客户资料中的负责人作为订单负责人快照
- 录单客户选择框：仅显示启用客户（active=true），支持客户名、拼音、首字母模糊搜索。
- 录单页不再提供订单负责人选择器；直接构造请求传入负责人或客户作为负责人时，后端必须忽略订单请求负责人并按客户资料负责人保存。客户资料未配置负责人时，录单保存必须失败并提示补全客户负责人。
- 录单页必须支持抽屉式新增客户，不跳转离开当前订单；新增客户时可粘贴收件信息自动识别姓名、电话和地址，并可手动选择客户来源、订单类型和负责人，默认来源为微信、默认订单类型为批发。
- PR-339-ORDER-ENTRY-KG-TIER-UNIT-VERSION-WARNING：录单和编辑订单的自动价必须以命中的豆单阶梯展示单位为准。KG 阶梯即使当前包装规格为 80g、100g 等小规格，也要显示元/kg、用总 kg 计算小计，并在小计处展示对应梯度单价；商品行必须显示当前豆单版本号，不能显示“未记录”。低于最低梯度时必须红字提示并按最低档价格试算，但不阻断保存。
- PR-341-ORDER-ENTRY-STALE-BEANLIST-AUTOLINE：录单和编辑订单中，商品行使用的豆单发布版本如果不是当前客户、当前豆单类型的最新已发布版本，豆单版本文字必须标红并显示感叹号；鼠标悬停或手机点击感叹号时提示“非新版本豆单”。商品明细的“新增明细”按钮必须放在明细列表下方；选择一个商品后系统自动补一个空明细行，但全列表最多只保留一个空明细，修改已选商品不能反复新增空行。
- PR-342-ORDER-ENTRY-PUBLIC-BEANLIST-VERSION-SELECT：客户没有某类型专属豆单时，录单和编辑订单该类型仍必须显示公共豆单的所有发布版本选项，并默认选中最新公共豆单；用户选择公共历史版本后，商品候选、价格梯度、行豆单版本和保存的 `bean_list_publication_id` 必须按所选公共豆单快照一致生效，不能强制回到最新版本。
- PR-351-ORDER-ENTRY-PUBLIC-BEANLIST-NO-CUSTOMER：新建录单未选客户时，商品明细标题区必须先用公共已发布豆单作为默认摘要；公共豆单在接口中必须有全局版本行，前端也必须去重兼容按客户复制的旧公共兜底数据。
- PR-352-ORDER-LIST-UNIFIED-SELECTION：订单列表中失效、发货和组合单据复用同一个选中集合。发货 Excel 只能在所选订单均可发货时生成；组合销售单和组合出库单沿用同一批选择做同客户/已发货校验；批量失效对同一批选择中的正常订单执行。
- PR-353-ORDER-ENTRY-HISTORICAL-BEANLIST-PRODUCT-TIERS：录单/编辑订单选择仍处于已发布状态的历史熟豆或生豆豆单版本时，商品候选和价格梯度必须来自该历史豆单快照；后端订单表单不得只返回最新发布版本的商品阶梯，导致历史熟豆版本选中后商品列表为空或只剩其他豆单类型商品。

### 5.5 客户门户小程序
- 客户门户小程序必须支持客户级主题配置。ERP 客户门户配置页可为每个客户选择三套内置主题之一：咖啡工厂专业风、清爽业务工具风、品牌会员高级风；小程序用户端不提供自行切换入口。
- 未配置主题或历史客户必须默认使用咖啡工厂专业风；非法主题值必须回退到默认主题。
- 小程序首页、服务页、订单查询、提交表单、指标卡和豆单外层容器必须跟随当前客户主题；豆单内部发布内容仍按 ERP 豆单发布配置展示。
- 客户门户必须支持按客户配置小程序首页模式：默认显示订单处理/服务入口；配置为商城时，客户登录后直接进入商城。
- `/api/mini/login`、`/api/mini/me`、`/api/mini/services/:key` 和切换当前客户后的会话上下文必须返回当前客户 profile 中保存的 `miniapp_entry_mode`；零售商城客户必须保持 `mall`，不能因重新登录、切换客户或从商城进入“我的订单”等服务页退回 `services`。
- 同一小程序用户绑定多个客户时，`/api/mini/current-customer` 只能切换到 approved 绑定客户；切换当前客户后，“我的订单”等服务页必须按新的 `current_customer_id` 重新查询，不能显示切换前客户的订单号、商品或金额。
- 同一小程序用户绑定多个客户时，小程序“个人中心”入口必须提供客户切换和退出登录；用户在“个人中心”选择其他客户后调用 `/api/mini/current-customer`，并回到首页重新加载当前客户能力。
- PR-276-MINIAPP-ERP-PASSWORD-LOGIN：小程序不再开放 openid 登录入口，登录页必须只展示 ERP账号密码登录；客户使用已启用登录且绑定客户门户的 ERP 渠道客户账号输入用户名/手机号和密码登录，内部员工账号、未绑定账号和登录禁用账号不能登录；账号操作集中到个人中心，支持切换用户和退出登录。
- PR-277-MINIAPP-PASSWORD-SKU-ALIAS：小程序 ERP 密码登录输入框必须用密码掩码显示；当前客户存在 `customer_only` 定制 SKU 且 `base_product_id` 指向公共基础款时，服务页商品选择器必须展示该客户定制 SKU 并隐藏被替代的公共基础款。
- 停用客户不能继续作为小程序当前客户；`/api/mini/current-customer` 只能切换到 approved 且客户档案 `active=true` 的绑定客户，旧绑定指向停用客户时不能切换进入。
- 商城能力作为客户门户能力之一，由 ERP 客户门户配置页启停；未启用商城能力的客户不得看到商城入口或访问商城 API。
- 客户门户配置页默认只展示客户档案中已打开“开通客户门户/工作台”的客户；未开通客户不出现在默认列表，运营可从客户档案打开开关，再回到门户客户配置选择能力模板。客户类型不再决定是否出现在门户配置页。
- 小程序登录必须支持微信手机号快速验证组件和手机号密码登录；通过微信验证的手机号或密码登录手机号必须匹配已启用登录的渠道客户 ERP 账号，并按该账号已绑定客户创建小程序会话；小程序 token 有效期必须拉到最大，不因固定天数自动过期。
- 系统用户产品边界只有内部用户和外部用户：内部用户通过员工维护、用户权限管理角色和后台登录；外部用户在客户门户配置页按客户管理，不在用户权限页配置内部角色。
- 客户门户配置页直接维护外部用户：支持按客户创建外部用户、设置或重置密码、启停登录，并维护客户 active 绑定；同一外部用户不能 active 绑定第二个客户。
- 客户 ERP 工作台外部用户必须是 `account_type='channel_customer'`、员工启用且登录未停用的账号；禁用登录的外部用户不能继续进入客户工作台或客户履约选择器。
- 零售商城客户不绑定 ERP 工作台账号；零售商城模板不能保存 ERP 工作台字段，误填 ERP 权限或 ERP 视图时 ERP 工作台字段会被拒绝，避免自定义模板绕过工作台边界。
- ERP 工作台账号绑定必须要求客户门户能力模板暴露 ERP 工作台；零售商城、其他不暴露 ERP 工作台或非空但无法识别的模板不能通过客户门户配置页或客户履约内部 API 绑定 ERP 工作台账号，错误返回 `ERP workbench unavailable for capability template`。
- 客户档案修改客户类型时，系统不得仅因类型变化自动改写能力模板或删除历史绑定；是否进入商城、工作台或履约候选由“开通客户门户/工作台”开关和门户客户配置中的能力模板决定。需要关闭工作台时应关闭开关或在门户配置中改为不暴露 ERP 工作台的模板，并写入操作日志。
- 客户门户配置保存能力模板时，空模板 key 才代表手工能力配置；非空但无法识别的 `capability_template_key` 必须返回无效请求，不能静默降级为手工配置。
- 客户门户配置页加载历史未知能力模板 key 时必须显式显示“未知能力模板”并禁止静默保存；客户门户配置列表和详情 API 必须保留非空未知 key 供页面提示和排查，前端不得把未知 key 归一化为空，运营必须重新选择系统模板或明确清空并停用门户。
- 能力模板必须包含“公共 SKU 小批量代发”模板：启用现货下单、代发、物流查询和结算能力，并内置 `<14lb` 使用 `15-28lb` 档的小批量价格规则。公共 SKU 小批量客户通过小程序服务页提交现货/代发订单且未手填单价时，后端必须复用该小批量规则；非 454g 规格也要按豆单重量档折算到当前规格，不能因为找不到同规格价格档而回退产品默认价。
- 代发批次不能为空：公共 SKU 代发或代加工客户通过小程序提交代发批次时，订单行数必须大于 0；不能提交空代发批次，避免 ERP 工作台出现没有业务内容的待处理批次。

- PR-390-PRODUCT-PRODUCTION-CONFIG-OVERHAUL：PR-389 的特殊属性/损耗落在 BOM 版本中的口径被新口径收敛为“商品生产配置”。BOM 只做独立配方库，维护分组、BOM 档案、版本和配方明细，不再承载预期损耗率、预期产出率或特殊属性。每个商品档案通过 `product_production_configs` 绑定一个生产 BOM 版本、一个可选工艺路线和一个 `expected_loss_rate`；商品生产设定字段保存在 `product_production_config_fields`，可控制是否展示到产品价格表。商品与配方菜单拆为“商品档案、客户商品名、商品配置模板、生产 BOM、产品价格表、行业字段模板”，不再使用一个“商品管理”三 tab 页面。商品配置模板维护模板规则、单位模板、阶梯价模板和分类模板；分类模板作为页面级分类视图使用，不是商品档案字段。生产 BOM 分组是纯交互归类，默认分组固定存在，分组只支持新增、改名、删除和排序；删除分组只把 BOM 移回默认分组。成本核算、产品价格表、录单、生产计划和工单必须优先读取商品生产配置；需要内部产出因子时临时使用 `1 - expected_loss_rate`，不再把预期产出率作为用户字段。价格表、订单行和工单必须冻结商品生产配置快照；旧 `yield_rate`、BOM 版本特殊属性和 SKU 特殊属性仅作 legacy fallback，不回改历史订单、价格表、BOM、工单或生产日志。
- 客户履约账户内部概览 API 必须返回当前客户已启用能力；运营台导入类型、提交操作面板和数据列表必须严格按能力模板展示。公共 SKU 小批量批发/代发客户如果未启用 `processing`，不得显示代加工工单导入、提交加工工单或加工工单列表；表格布局必须固定列宽和对齐，长文件名、长地址不能撑乱页面。
- 客户履约运营台最底部必须展示当前客户的“履约客户订单”全宽列表，字段参考 ERP 订单列表，至少包含订单号、日期、客户/类型、收件信息、订单费用、快递信息、订单状态和操作；订单费用要展示商品金额、运费、优惠和应收。点击订单号后可查看明细、商品行和费用，并可打开销售单与出库单，支持下载最新版、微信分享销售单、微信分享出库单。
- 具备 `customer_processing.read` 的客户工作台账号必须可以读取自己绑定客户的履约订单详情，不要求 ERP 内部 `orders.write` 权限；详情接口必须按绑定员工、客户和订单 ID 限定范围，不能读取其他客户订单。
- 客户履约账户生成月结必须要求客户已开通结算能力；未开通结算能力的客户不能生成结算批次，不能留下空结算批次或改写未结算费用。

### 5.6 全局消息中心（Message Center）
- 系统必须将全局通知抽象为消息中心底座，统一保存消息事件、渠道投递和 ERP 已读状态，不能把顶部通知写死在订单页面逻辑中。
- 消息中心第一阶段必须支持 ERP 平台内通知；架构上预留小程序推送、客户短信推送、ERP 平台推送等多渠道扩展。
- 新订单事件必须通过消息中心发布，投递给具备订单读取权限的 ERP 用户；用户点击顶部通知后进入订单列表并高亮对应订单。
- 通知中心必须支持可配置规则：按事件类型、主题、来源类型、Payload 条件、接收人类型和通道生成投递，业务代码不得写死微信服务号。
- 通知通道必须保持 IM 中立，外部 IM 通过 adapter/outbox 字段扩展，后续可接微信服务号、企业微信、短信或其他 IM。
- 订单下单、生产完成、已发货必须发布统一订单事件，默认规则可通知烘焙师、销售或订单相关接收人。

## 6. 操作审计日志（Audit）
- 原则：**所有用户触发的业务写操作都必须留痕**；新增、修改、删除、提交、导入、发布、作废、调整、转仓、上传和状态变更不能只有业务数据变化而没有操作日志。
- 查询页面：按日期范围 + 关键字 + 类型查询。
- 展示要求：
  - old/new 尽可能翻译为人可读内容
  - 对象要显示可读名称并可跳转（如订单号、商品名、客户名）

## 7. 用户权限与账号（Auth）
- 手机从 `/app` 入口登录时，只需一次外层 `order` BasicAuth 和一次系统账号登录。
- 登录页提交、登录成功回跳、Vue/Vite API 请求和退出回登录必须保留 `/app` 前缀，不能跳到站点根导致重复认证。
- API 请求或 Bearer token 失效时，后端只能返回 JSON 401，不能带 `WWW-Authenticate` 触发浏览器原生 `order` 密码框；只有真正打开受保护页面时才允许出现外层 BasicAuth 提示。
- 系统用户只分内部用户和外部用户；历史员工账号默认内部用户。
- 员工维护和用户权限页只给内部用户配置角色、可见功能、登录启停和密码，不展示账号类型切换，也不展示“公共SKU代发客户”或“代加工客户”等客户业务角色。
- 外部用户不在用户权限页维护；客户可见能力由客户门户配置模板决定，外部用户账号、密码、登录启停和客户绑定由客户门户配置页维护。
- PR-299-CUSTOMER-ACCOUNT-HIDE-FULFILLMENT：设置菜单必须提供“全局设置”，管理员可配置“客户账户模式隐藏履约运营台”。默认开启隐藏；开启时客户账户模式不显示内部 `customerFulfillment` 履约运营台入口，关闭后该入口按原权限显示。该功能只隐藏菜单入口，不删除履约运营台页面、客户侧工作台、履约导入/订单 API 或客户门户模板能力；保存开关必须写入操作日志/审计记录。
- PR-278-MINIAPP-MAIN-TABS：客户小程序发布版必须先进入可自恢复的启动页，不能出现只有左上角主页图标的空白首屏；登录后底部固定四个大入口：首页、订单中心、费用中心、个人中心。首页保留原服务入口但不重复展示订单/费用入口，订单中心专门查看订单明细、销售单、出库单和物流信息，费用中心专门查看账目汇总、订单账单、费用明细和结算单，个人中心专门放退出登录、切换用户和未来个人配置。
- PR-287-MINIAPP-BILLING-ORDER-RECEIVABLES：客户小程序底部“费用中心”入口必须展示当前客户订单应收；当客户已有订单但尚未生成 `customer_fee_items` 或 `customer_settlement_batches` 时，费用中心不能显示空白，且不能泄露其他客户订单。
- PR-288-MINIAPP-ACCOUNTING-BILLS：客户小程序账单页必须侧重账目，默认按订单日期展示本月账期，可切换本周、本月、本年或自定义时间段；顶部展示应收总额、未付款金额、未付款订单数和已付款金额；账单列表只展示订单号、订单日期、应收金额、付款状态和收款方式，支持订单号跳转订单页，不在账单页重复展示收件人、商品明细、物流、销售单或出库单。

## 8. 财务月结（Finance）
- 财务模块一期面向咖啡烘焙厂、咖啡贸易商、咖啡壳豆加工厂和综合咖啡工厂，不只服务当前单一业务。
- 财务首页按月份展示收入、成本、费用、毛利、净利和税费估算。
- 历史订单只有 `total_amount` 且 `grand_total` 为默认 0 时，财务收入和来源明细必须按 `total_amount` 计入；全额折扣等明确产生 0 `grand_total` 的订单仍按 0 计入，作废订单不计入收入。
- 财务设置支持小规模纳税人和一般纳税人，税费估算包含增值税、进项/销项、附加税、企业所得税和小微优惠估算。
- 费用管理支持按日期录入期间费用或主营成本；费用只能关联员工中的在职员工，停用员工不能作为新费用经办人写入账目；列表点击员工名后可过滤该员工相关费用；费用类别和付款方式提供可模糊搜索的常用候选列表，并允许自定义输入。
- 费用管理必须支持订单、客户、商品、批次号和维度说明等多维归集字段，用于咖啡烘焙厂、咖啡贸易商和壳豆加工厂按业务对象复盘费用；填写订单、客户或商品维度时，对应业务对象必须存在；同一费用同时填写订单和客户时，客户必须与订单归属客户一致；同时填写订单和商品时，商品必须属于该订单明细，否则不能写入费用。
- 月度结账必须提供月结前检查，至少覆盖来源异常、报表来源明细、票税台账、成本配比异常和会计交接导出准备情况。
- 月度经营报告关键数字必须能钻取来源明细，按收入、主营成本、期间费用和票税来源展示来源单据、往来方和金额。
- 订单收入来源明细必须带出订单收款方式；会计交接 Excel 的来源明细工作表必须包含收款方式列，便于核对微信、支付宝、银行转账、现金等收款渠道。
- 财务模块必须提供票税台账，用于记录销售发票、采购发票、税款缴纳和其他票税事项，支持月度查询和新增；同类型非空发票号或凭证号不能重复写入台账。
- 报告必须提供会计交接 Excel，包含经营汇总、月结前检查、来源明细、票税台账和凭证草稿。
- 月度结账默认强锁账；结账后来源费用和票税台账不能直接改写，只允许结账后金额调整。
- 已有结账后金额调整的月份必须保持已调整状态；重复结账只允许重算快照，不会降回已结账。
- 强锁账/轻确认切换入口仅对白名单用户开放，后端必须校验并审计。
- 月度经营报告提供老板简报、明细表、PDF 导出和 Excel 导出。

## 9. 操作手册强制治理（PR-DOCS-001）
- 开发时只要改变用户操作流程、入口、字段、权限、导入导出或异常处理，必须同步更新操作手册。
- 单个大功能必须有一个独立操作手册，命名为 `orderapp-remote/docs/OP_MANUAL_<FEATURE>.md` 或沿用该大功能现有用户手册。
- 小改动更新所属大功能手册，不能把多个大功能混写在一个长文档里。
- 每次触碰功能时，要检查现有手册是否缺入口、缺字段、缺步骤、缺权限说明、缺导入导出说明、缺排障说明。
- 需求审核证据必须包含手册文件路径或前端手册入口。
- 操作手册只维护 `orderapp-remote/docs` 一份；根目录不得恢复 `OPERATION_MANUALS.md` 或 `OP_MANUAL_*.md` 副本。
- 部署时线上 `/docs` 必须来自 `orderapp-remote/docs/`，不再从根目录同步手册副本。
- 操作手册入口必须直接放入对应大功能菜单，例如订单销售手册放在订单销售，生产手册放在生产管理，不能单独做一个“手册”菜单。
- 被大功能手册覆盖的旧 `*-user-manual.md` 和旧单独 Vue 手册组件必须删除，避免操作人员看到两套手册。
- Vue/Vite 手册页必须通过通用手册视图读取对应 `OP_MANUAL_*.md?raw=1`，保证 `orderapp-remote/docs` 源文件、部署 docs 和界面内容一致。
- 所有大功能 `orderapp-remote/docs/OP_MANUAL_*.md` 必须包含 `## 流程图` 和 Mermaid `flowchart` 图示，不能只写文字步骤。
- Vue/Vite 手册页必须把 Mermaid 流程图渲染成节点和箭头图示；无法识别的图示代码必须保留为代码块，不能让手册空白。

## 10. 商品配置、分类模板与商品价格表（PR-395-PRODUCT-PRICE-CLASSIFICATION）
- 商品与配方菜单必须拆为：商品档案、客户商品名、商品配置和分类模板、阶梯价模板、单位模板、生产 BOM、商品价格表、行业字段模板等独立功能。
- 商品配置和分类模板页面只维护商品配置模板和商品分类模板；阶梯价模板、单位模板必须作为独立功能菜单进入。
- 商品分类模板和分类项可引用阶梯价模板、单位模板；商品配置模板也可引用阶梯价模板、单位模板。不提供隐式继承开关；两边不一致时前端即时提示。
- 商品档案和客户商品名都采用单归类模型：同一对象只能有一条有效分类归属。已归类对象要改分类，必须先移出当前分类；前端提示，后端拒绝重复归类。
- 商品档案和客户商品名的“全部”Tab 必须展示当前归类：`分类模板 / 分类项`；分类模板 Tab 只显示已归入该模板分类项的对象，未归类统一在全部 Tab 中显示为“未分类”。
- 客户商品名列表不允许编辑生产数据，不显示无效编辑按钮，不显示 BOM 或生产 BOM 操作入口。
- 产品价格表必须更名为商品价格表；商品类型来自商品档案或客户商品名当前归属的分类模板名称，未归类统一为“其他”。生成抽屉的分类和商品选择来自当前分类项。
- 商品价格表发布快照必须冻结分类模板、分类项、商品配置模板、阶梯价模板、单位模板、客户商品名和商品档案快照；旧 `bean_list_publications` API 路径保留兼容。
