# orderapp 业务需求（精简版）

> 范围：描述“要做什么”和业务规则；不记录修 bug 的过程。

## 1. 目标与范围
- 建一个轻量的订单/档案/审计系统（Web）。
- 核心模块：
  - 录单
  - 订单列表、订单详情
  - 作废/恢复（代替删除）
  - 商品档案 + 阶梯价
  - 客户档案（含默认值、快速录入、复制地址）
  - 操作审计日志（全量留痕）

## 2. 计价与单位（关键业务规则）
### 2.1 阶梯价
- 阶梯价单位：**元/磅（lb）**。
- 换算：**1lb = 454g**。
- 阶梯匹配：按“**单行**”的折算磅数匹配阶梯档位。

### 2.2 录单明细输入（规格 + 件数）
- 每一行明细代表“一个商品 + 一个规格”。
- 输入字段：
  - **规格(g)**：下拉（常用规格）；选择商品后默认使用该商品第一个价格梯度的规格；常用规格包含 **36g、80g、100g、227g、454g、500g、1000g、2.5kg**。
  - **数量(件)**：只能输入整数（不允许小数）。
- 计算：
  - 总重量(g) = 规格(g) × 数量(件)
  - 总重量(lb) = 总重量(g) ÷ 454

### 2.3 行小计与合计
- 单价：默认来自自动匹配的阶梯价（元/磅）。
- 商品选中后必须直接展示该商品所有梯度价格，便于对照规格、数量区间和单价。
- 行小计：`line_total = unit_price(元/磅) × 总重量(lb)`
- 低于最低档：
  - 必须提示（非阻断）
  - 仍允许下单
  - 默认按“最低档单价”计算
  - 操作员可切换“手动单价（元/磅）”覆盖

## 3. 订单（Orders）
### 3.1 页面
- 录单：`/app/order`
- 订单列表：`/app/orders`
- 订单详情：`/app/orders/:id`
- 新录订单默认付款状态为 **已付款**，发货状态为 **未发货**。

### 3.2 删除/作废规则
- 订单不允许真删除。
- 通过“作废/恢复”实现撤销：
  - 作废后列表默认不显示
  - 可筛选查看作废/全部

### 3.3 列表快速编辑
- 订单列表支持快速修改：收款状态、发货状态、备注。
- 所有修改必须写入审计日志。

### 3.4 订单列表快递录单 Excel
- 录单保存只负责订单本身，不得触发快递录单 Excel 生成。
- 订单列表提供快递处理入口，选择生产完成的订单后，系统使用服务器快递模板生成快递录单 Excel。
- 模板文件来自服务器 `/data/ship_temp.xlsx`，部署时同步到应用持久化目录供容器使用。
- 单订单 Excel 文件名包含订单日期、客户姓名和订单号；批量生成时文件名包含日期和订单数量。
- 收件人信息来自客户档案；寄件人姓名、电话、地址、公司和业务类型来自系统“发货人设置”的默认寄件人。
- 发货人设置支持维护多个寄件人，并指定一个默认寄件人；订单列表生成快递录单时可先选择本次默认寄件人，也可对部分已勾选订单单独选择寄件人。
- 订单列表展示列必须收敛，快递信息必须合并展示寄件人和快递单号，订单状态必须合并展示收款、发货、生产和发票状态。
- 点击订单号打开订单抽屉后必须可直接编辑订单并保存；订单列表和订单抽屉不得再提供独立“编辑”跳转入口。
- 单个订单快递单号必须在订单抽屉内回填，不再在订单列表顶部展示本批次单号输入框。
- 包裹件数固定为 1，托寄物默认 **茶叶**，重量固定为 **0.1kg**。
- 备注填写本次订单明细，包含订单号、商品名、规格和数量，不写入单价和小计。
- 生成快递录单 Excel 必须创建发货批次；回填快递单号后，对应订单发货状态自动变为 **已发货**，订单列表展示快递单号。
- 订单列表支持上传顺丰寄件列表回传 Excel，系统读取 `运单号` 和 `备注/备注订单号/订单号` 列，从备注中的 `SO...` 订单号匹配订单并回填快递单号。

## 4. 采购入库（Purchase）
- 采购入库在 Vue/Vite 前端提供统一页面。
- 支持维护供应商档案：名称、联系人、电话、地址、启用状态。
- 支持创建采购单：供应商、物料、采购数量(g)、采购单价、备注。
- 支持对采购单执行收货入库；收货必须复用库存原料入库能力，生成原料批次、库存批次、原料仓库存和库存流水。
- 收货成功后，物料档案采购价更新为本次收货单价。
- 原料入库页面选择物料时必须在下拉框内支持按物料名称和编号模糊搜索，不得额外放独立搜索框，且不把包装物料作为原料入库选项。
- 库存作业中的 WIP领退/转仓和成品转仓选择物料或成品时，也必须在下拉框内支持名称/编号模糊搜索。
- 四个库存作业页面必须使用类似仓库库存的面板、网格和表格排版，输入框高度、列宽和间距保持对齐。

## 4.5 生产制造（Production）
- 生产管理必须提供“生产验收”入口，用于上线后快速检查仓库、原料、WIP、工单、生产日志、质检和成品追溯是否具备。
- 生产计划必须能按已选商品和 BOM 生成物料需求计划，展示需求、WIP 库存、已被工单占用的 WIP、原料仓库存、缺料量和采购建议。
- 物料需求计划必须展示 `WIP可用(g)` 和 `建议领到WIP(g)`，帮助生产前把原料从原料仓领到 WIP。
- 开始生产时必须冻结 BOM/原料快照，并建立 WIP 软占用；占用库存不能被其他工单重复使用。
- 生产工单必须展示 WIP 已占、已耗和剩余占用。
- 仓库库存必须能快速打开 WIP占用抽屉，按工单查询、调整占用量或释放废弃工单占用；调整/释放必须写入审计日志。
- 仓库库存批次追溯必须区分成品批次和原料批次：`FP-...` 展示成品到工单、生产日志、原料消耗的追溯链；`MB-...` / `LEGACY-MAT-...` 展示原料批次和当前仓库位置。`LEGACY-MAT-...` 必须说明是系统升级按旧物料库存生成的期初批次。
- 生产完工必须从 WIP 在制仓扣料，不能直接消耗原料仓。
- 生产中必须把投料数、成品件数/余料和实际出品率放在同一条生产数据中；生成计划时给出默认投料和成品数，生产中可修改，修改后实际出品率实时更新，未修改时显示 BOM 出品率。
- 生产中完成生产时如果 WIP 仓库存不足，必须在当前页面右侧打开库存作业抽屉，并默认进入 WIP 领退/转仓以便补领原料。
- 生产中必须支持部分完工，并明确说明部分完工会让本次产出入成品仓、本次消耗投料从 WIP 扣减，剩余工单继续保留。
- 生产质检必须支持记录原料、生产工单和成品批次的检查结果，结果包含通过、待处理/待定、不合格/不通过，并统一归一化保存。
- 生产质检页面必须采用仓库库存式工作台布局，支持从右侧抽屉选择质检对象；按钮必须按当前质检类型显示为“选择工单”“选择原料批次”或“选择产品批次”，抽屉打开后只展示当前类型对应的对象，并把选中的工单号或批次号回填到质检表单。
- 质检结果为待处理或不通过时，关联原料批次、WIP 批次或成品批次必须显示质检状态；冻结批次不得被领料、生产扣料或成品出库/转仓误用。
- 生产验收检查项点击“打开”时，仓库相关入口必须直接进入对应仓库和库存类型，而不是全部仓库。
- 生产流程用户手册必须同步说明生产验收、物料需求计划、WIP 占用处理、部分完工、生产质检和批次追溯操作。

## 5. 商品档案（Products）
- 维护商品与阶梯价，用于录单自动计价。
- 录单商品选择框必须支持直接输入过滤、点击选择、拼音/首字母匹配；不得再额外放一个独立商品搜索框。
- 支持打印/导出报价（PDF）。

## 5.5 豆单发布（Bean Lists）
- 官方豆单用于棵凡对外公开链接。
- 客户豆单发布后必须锁定为客户自己的内容和价格快照，后续官方豆单更新不得自动改写客户已发布豆单。
- 客户生成豆单时可复制官方已发布豆单的报价、风味、特点和出品建议作为价格来源。
- 客户生成豆单时可复制自己历史豆单的样式配置，并在新版本中继续调整后发布。
- 只有管理员可以发布或撤回豆单；客户登录后只能保存自己的豆单修改并下载/打印 PDF。

## 6. 客户档案（Customers）
### 6.1 客户字段
- 客户至少包含：
  - 客户名（正式）
  - 客户公司名称（销售单公司名；为空时默认使用客户名）
  - 客户公司地址
  - 客户联系电话
  - 联系人（姓名）
  - 电话
  - 地址
  - 启用/停用（active）
  - 默认来源（default_source_id）
  - 默认订单类型（default_order_type_id）
  - 原始信息（raw_name，仅保留，不影响展示）

### 6.2 客户维护
- `/app/customers`：列表内可直接编辑并保存（写日志）。
- 客户录入和编辑必须支持维护客户公司名称、公司地址、客户联系电话；客户公司名称为空时，销售单按客户名作为公司名。
- 支持停用/“删除”：
  - 客户删除采用安全策略（不真删，改为停用）。
- 支持“一键复制发货地址”：复制格式固定为：
  - 姓名：xxx（联系人为空则用客户名）
  - 电话：xxx
  - 地址：xxx

### 6.3 客户快速录入
- 客户新建/编辑页支持“快速粘贴”一整段文本，一键解析到：姓名/电话/地址。

### 6.4 客户联动录单
- 录单选择客户后：
  - 自动**覆盖**录单的“来源/订单类型”（来自客户档案默认值）
- 录单客户选择框：仅显示启用客户（active=true），支持客户名、拼音、首字母模糊搜索。
- 录单页必须支持抽屉式新增客户，不跳转离开当前订单；新增客户时可粘贴收件信息自动识别姓名、电话和地址，并可手动选择客户来源和订单类型，默认来源为微信、默认订单类型为批发。

### 6.5 销售单客户信息
- 订单列表每行“销售单”必须在当前订单列表内打开销售单抽屉，保留订单列表筛选和分页上下文。
- 销售单抽屉内必须提供“销售单设置”按钮，可打开销售单设置抽屉维护说明、收款方式、收款码和公章。
- 订单销售单页面必须能从右侧抽屉编辑当前订单客户的公司名称、公司地址、联系电话、联系人、收货电话和收货地址。
- 系统必须提供全局公司设置；生成销售单 PDF 时，公司名称优先来自全局公司设置，其次兼容历史销售单设置公司名，再兜底客户公司名称和客户名，避免因未设置公司名导致生成失败。
- 生成销售单前必须先展示销售单预览，操作员确认后才创建正式 PDF 版本；预览不得新增销售单版本号。
- 销售单历史版本和最新版都必须可下载，历史版本下载 URL 必须正确解析 PDF 文档 ID。
- 销售单预览必须与下载 PDF 的关键信息和版式一致，包含收款码图片、公章图片、多行收款方式和多行个性化说明。
- 销售单公章应覆盖在公司名称附近，支持在销售单设置和销售单预览中拖动调整位置，并支持在销售单设置中调整公章大小；导出 PDF 必须按公章原图比例等比显示，不得横向拉伸；拖动公章时点击在公章内部不得导致公章跳走，保存坐标时不得覆盖销售单说明和收款方式。
- 销售单设置页拖动公章松手后必须自动保存坐标；后续重新生成销售单 PDF 或 PNG 图片时必须使用最新公章坐标。
- 销售单设置页必须支持对当前公章去除浅色背景，生成透明 PNG 并设为当前公章。
- 公账收款信息统一在全局“公司设置”中维护，包含公司地址、纳税人识别号、户名、开户行和收款账号，并支持一键复制公账收款信息；销售单设置不再维护公账字段。
- 销售单预览和 PDF 中客户公司地址必须完整换行显示，不得被截断；收款码必须按数量自适应填充空白，单个收款码放大展示，多个收款码可竖向排列。
- 销售单必须支持按当前预览生成 PNG 图片版本；图片版本和 PDF 版本独立递增、独立标记最新版，历史图片和最新版图片下载必须返回 `image/png`。
- 销售单 PNG 图片字体必须按像素画布正确缩放，文字高度不得大于行高；订单信息、商品表、收款说明、公账信息和二维码不得互相重叠或明显越界。
- 销售单 PNG 图片必须按高清画布生成，分享给微信后仍能保持文字清晰偏粗；收款二维码必须明显放大，单码和多码场景都要达到可识别尺寸。
- 销售单必须支持分享到微信；分享 PDF 和图片时必须直接分享文件，不得把分享链接作为默认分享内容；浏览器不支持文件分享时提示下载后手动发送。
- 销售单、出库单等资源对外分享必须使用同一套外部分享资源 API、token、公开文件访问和前端文件分享逻辑，不能各自复制一套分享实现。

### 6.6 出库单维护与下载
- 订单列表中已发货订单必须提供“出库单”入口，并在当前订单列表内打开出库单抽屉。
- 出库单抽屉必须支持维护出库日期、出库仓库、发货方式、快递单号和备注。
- 生成出库单前必须先展示出库单预览，操作员确认后才创建正式 PDF 版本；预览不得新增出库单版本号。
- 未发货订单不得生成出库单预览或正式出库单。
- 出库单历史版本和最新版都必须可下载，历史版本下载 URL 必须正确解析 PDF 文档 ID。
- 出库单必须支持分享到微信；分享的是已生成的出库单 PDF 文件，不得把分享链接作为默认分享内容。
- 出库单必须支持公章设置，公章上传、去背景、坐标和尺寸与销售单使用同一套设置；预览可拖动公章，后续新生成的出库单 PDF 必须使用最新公章位置。

### 6.7 发票申请与文件
- 订单列表每行必须提供“发票”入口，并在当前订单列表内打开发票抽屉。
- 发票抽屉必须支持对订单申请发票；申请后订单列表显示“已申请”，未申请订单显示“未申请”。
- 开票完成后必须支持上传发票文件，文件类型仅允许 PDF 和常见图片（PNG、JPG、GIF、WebP），不得接受文本或 SVG 等其他文件。
- 上传后的发票文件必须能从发票抽屉和订单列表打开查看；订单列表发票状态显示为“已上传”。

## 7. 用户权限与账号（Auth）
- 用户权限页必须支持角色分配、账号启停和管理员设置/重置密码。
- 用户权限页必须区分密码状态：未设置密码的员工显示“设置密码”，已有密码的员工显示“重置密码”，避免把首次创建密码误认为重置操作。
- 密码登录必须支持“用户名或手机号 + 密码”；短信登录仅支持手机号。
- 账号停用后，员工不能使用密码或短信登录；已有 Bearer 会话也不能继续解析为有效员工。
- 手机号密码登录成功后，Vue/Vite 前端必须自动携带 Bearer token 访问 API。
- 密码登录成功后的首次进入必须按默认菜单展开，不能因为上一次空权限或折叠菜单状态导致首屏看不到功能入口。
- 手机从 `/app` 入口登录时，登录页提交、成功回跳、Vue API 请求和退出回登录都必须保留 `/app` 前缀，不能跳到站点根导致重复 BasicAuth 或重复系统登录。
- admin 角色账号必须获得全权限菜单和 API 权限。
- 系统顶部必须提供退出登录入口，退出后清除本机 token 并注销当前会话；没有本机 token 时 Vue 工作台必须回到登录页，不能被浏览器 BasicAuth 缓存绕过。
- 账号启停、密码重置和角色分配必须写入操作日志。

## 8. 操作审计日志（Audit）
- 原则：**所有关键操作都必须留痕**。
- 查询页面：按日期范围 + 关键字 + 类型查询。
- 展示要求：
  - old/new 尽可能翻译为人可读内容
  - 对象要显示可读名称并可跳转（如订单号、商品名、客户名）

## 9. 财务月结（Finance）
- 财务模块一期面向不同咖啡 ERP 企业，不只服务当前业务：咖啡烘焙厂、咖啡贸易商、咖啡壳豆加工厂和综合咖啡工厂都必须能选择企业类型；未来可扩展到同类鲜果加工厂。
- 财务首页必须按月份展示收入、主营成本、期间费用、毛利、毛利率、经营净利和税费估算。
- 财务设置必须支持小规模纳税人和一般纳税人，税费估算至少包含增值税、进项/销项税、附加税、企业所得税和小微企业所得税优惠估算。
- 第一版税费结果用于经营管理估算，不作为正式纳税申报；页面和导出报告必须保留估算提示。
- 费用管理必须支持按日期录入费用，可归集为期间费用或主营成本；费用可选关联员工，列表点击员工名后可过滤该员工相关费用；费用类别和付款方式应提供可模糊搜索的常用候选列表，并允许自定义输入。
- 月度结账默认使用 **强锁账**：月份结账后，财务费用等来源单据不得继续直接改写；确需修正时走结账后金额调整。
- 锁账模式允许强锁账和轻确认两种模式，但切换入口必须隐藏在高级/受控区域，只有白名单用户可切换；后端必须再次校验并留审计。
- 月度经营报告必须同时提供老板简报和明细表，系统视图是主体验；报告支持 PDF 和 Excel 导出。
- 结账后调整第一版只做金额调整，不强制关联原始单据；调整必须记录月份、类型、金额、原因、备注和操作人。
- 财务功能必须录入产品需求表、开发需求表、单元测试表、API 测试表和需求审核表，并保留自动化验收证据。
