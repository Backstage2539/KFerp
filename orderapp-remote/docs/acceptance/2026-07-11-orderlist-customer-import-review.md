# PR-524 历史客户二次提炼与导入审核表验收记录

## 范围
- 继续使用 PR-523 的 `/data/orderlist.xlsx` 只读副本，处理范围和来源文件 SHA256 不变。
- 读取生产 ERP 客户、客户类型、来源、订单类型、负责人和能力模板的只读快照，用于生成导入候选字段。
- 本需求只生成 `customer_import_review.csv` 和更新后的审核工作簿，不修改临时库订单客户键，不执行正式客户导入。

## RED / GREEN
- RED：新增跨号码客户、最新号码、生产 ERP 全字段和审核 Sheet 合同测试后，因 `BuildCustomerImportRows`、`CustomerImportRow` 和 `客户导入审核` 不存在而失败。
- 数据质量 RED：无手机号的“自提/送货说明”曾按同名合并，收货人标签曾残留在客户名；修复后无手机号记录保持来源级候选，收货人标签和姓名中的手机号被清理。
- GREEN：`go test ./internal/migration/orderliststaging ./cmd/orderlist-staging -count=1` 通过；支持合同测试覆盖 PR/DEV、需求、验收和手册标记。

## 数据与工作簿证据
- 原客户候选 1,321 条；二次提炼后客户导入审核候选 1,289 条。
- 22 个候选保留多个历史手机号，最多 4 个；主电话按最近订单中的唯一有效号码选择。
- 38 组短姓名或高风险同名跨号码记录未自动合并，记录 `customer_cross_phone_name_unsafe` 待审核问题。
- 424 个候选没有可自动确认的主手机号，继续保持 `needs_review`；新客户的客户类型不自动猜测。
- 工作簿包含 12 个 Sheet；`客户导入审核` 覆盖客户 API 全字段，并包含历史号码、历史名称、首末单日期、来源订单键、待审核原因和审核结论。
- artifact_tool 完成工作簿 inspect、公式错误扫描和全部 Sheet 渲染；公式错误为 0。

## 隔离证据
- 生产 ERP 查询只用于导出 6 条正式客户及有效下拉选项的只读快照。
- 本流程没有对生产 `nocodb` 执行 INSERT、UPDATE 或 DELETE；正式客户表零写入，客户总数保持 6。
- 含客户个人信息的源快照、CSV、JSON、渲染图和审核工作簿均保存在 git 外受保护目录，文件权限为 600。

## 结论
- 客户多号码提炼、最近号码选择、ERP 全字段映射和审核工作簿已完成。所有候选仍待人工审核，未创建或更新正式客户。
