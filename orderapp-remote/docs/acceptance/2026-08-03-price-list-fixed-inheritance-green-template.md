## 用户复现

1. 价格表层级选择固定价、商品或下级分类选择继承时，用户看不到明确的具体 SKU 固定价录入位置，最终价格可能显示为 0。
2. “黄波旁水洗生豆”提示“未挂到带生豆模板的分类，无法生成生豆价格”，但当前分类模型已经不再挂生豆模板。
3. “小菠萝生豆”提示“未设置计价方式”，但其父类已经设置计价方式。

这三类现象统一按当前通用价格表合同修复：计价方式和模板沿完整祖先链解析；固定价金额按具体 SKU 维护；生豆不再依赖旧分类模板；已经解析到方式时只提示真实缺项。

## DEV 合同

### DEV-574-ANCESTOR-PRICING-INHERITANCE

- 计价解析顺序固定为 `商品 > 当前分类 > 逐级祖先分类（由近到远） > 价格表`。
- 商品或某层分类选择继承时继续向上查找，不得只读取直接父类；最近的有效计价方式、阶梯模板或价格计算模板优先。
- 只要任一级解析到计价方式，就不显示 `未设置计价方式`。方式为固定价但金额缺失时在对应规格行显示 `未填写固定价`；模板方式参数缺失时显示对应模板缺项。
- 缺项可以保留在当前可编辑草稿，但必须阻止其成为可发布行或以 0 元正式发布，不得回填旧发布价或其他来源价格绕过。

### DEV-574-SKU-FIXED-PRICE-MIGRATION

- 固定价方式可以来自价格表默认或任意祖先分类；固定金额只属于具体 SKU。
- 商品计价只用于选择或继承本层计价方式/模板；每个已勾选规格行旁直接提供独立固定价输入，227g、454g、1kg 等兄弟规格不得共用、覆盖或推断彼此价格。
- 恢复当前可编辑配置时，旧平铺固定价键只有精确符合 `${sku_id}:fixed_price` 且能解析到当前具体 SKU 时，才一对一回填同一 SKU。
- 该 SKU 已有正数 `fixed_unit_price` 时保留现值。无精确 SKU、重复冲突、父商品键、名称键或规格文本键均不迁移，也不把一个旧值复制给其他规格。
- 该恢复只影响当前可编辑配置，不改写旧草稿原始证据或任何已发布快照。

### DEV-574-GREEN-BEAN-GENERIC-PRICING

- 生豆使用通用商品价格表的 `按阶梯模板计算`、`按价格计算模板计算` 和 `固定价`，与其他商品共用选品、继承、平铺价格行和发布校验。
- 商品或分类不要求挂载旧“生豆模板”。缺少该旧关系不得隐藏商品、阻止生成或显示“未挂到带生豆模板的分类”。
- 没有旧生豆模板元数据、但具体 SKU、通用计价参数、正数最终价、单位、换算和快照完整的生豆草稿/发布请求必须通过现有 API 合同。
- 固定价为 0、最终价非正数、缺单位/换算或价格行不完整时继续拒绝，不因取消旧模板限制而放宽价格完整性。

### DEV-574-DOCS-ACCEPTANCE

- 用户操作同步到 `OP_MANUAL_COSTING.md` 与 `OP_MANUAL_GREEN_BEAN_SALES.md`；不恢复根目录手册副本。
