# PR-610 价格表发布父 SKU 平铺行身份修复

## 问题

旧价格表快照可能把父商品同时写入 `product_id` 和 `sku_id`。当生成区已选择该父商品唯一的具体规格时，发布接口会把旧行误判为“SKU 未在规格选择中”，例如“第 1 行 SKU 7 未在规格选择中”。

## 修复口径

- 前端生成/恢复价格表时，将可唯一确定的父 SKU 行归一为已选具体子 SKU。
- 后端保存草稿和发布再次执行相同的窄范围归一，保证旧草稿也能安全发布。
- 只有同一父商品恰好一个 legacy 子规格被选中才自动修正；多规格、BOM 专属规格和真正未选择规格继续严格阻断。
- 发布快照、价格试算和小程序录单均使用具体规格身份，历史快照不回写。

## 自动化证据

- Go targeted：`TestBeanListConcreteSelectionsNormalizeStaleParentRowsToSingleSelectedSKU`（先 RED，再 GREEN），并与严格未选择 SKU、父 SKU 失效校验一起通过。
- Vue targeted：`product-price-list-selection.test.js`、`costing-bean-list-version-ui.test.js`，67/67 GREEN。
- 生产数据未修改；部署前后需分别通过开发和生产发布门禁，并用只读接口确认发布价格表和录单规格身份。

## 验收步骤

1. 在商品价格表生成区选择一个商品的唯一规格，确认平铺行显示该具体规格而不是父 SKU。
2. 保存草稿后重新进入并发布，确认不再出现“SKU 7 未在规格选择中”，每个规格的最终价均大于 0。
3. 在小程序录单选择同一商品规格，确认命中刚发布价格表的发布版本、具体规格、价格单位和成交价。
4. 选择同一商品多个规格或输入未勾选 SKU，确认系统仍按行显示明确阻断原因，不会静默猜测。
