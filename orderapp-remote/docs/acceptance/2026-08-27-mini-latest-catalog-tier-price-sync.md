# 小程序最新豆单与阶梯价格同步验收（PR-613）

## 现场问题与只读证据

- production 最新工厂供货豆单为 `V3.0.11`，发布时间 2026-08-27 09:56，内容只有商品“曲奇”和 4 个价格档；上一版 `V3.0.10` 有 19 个商品。
- 服务端已能把 `V3.0.11` 标为当前发布，但员工小程序录单页只在首次进入或切换客户时加载商品目录。页面停留或从后台返回后继续保留旧商品候选，商品选择前也不主动核对新发布。
- 数量输入原先通过双向绑定先写入订单行，再重算价格。若数量没有价格档，数量已经改变而价格变成 0 或保留旧显示，不能满足数量和价格一致提交。

## TDD 证据

- RED：小程序页面合同缺少前台恢复和选品前刷新；阶梯规格选择立即带默认数量；无价数量仍先写入；订单表单响应没有 `Cache-Control: no-store`。
- GREEN：页面前台恢复和打开商品选择器前均重新取当前客户目录；服务端明确禁止缓存。阶梯规格选择后数量/单价为空，曲奇数量 14 同步匹配 14-23 件档位 `111 元/袋`。
- 原子回退：两位数输入的未完成前缀只作为临时文本并隐藏旧单价；完整数量匹配成功后同时提交数量和价格。失焦仍无价格时删除临时文本，恢复原数量/原单价并提示。
