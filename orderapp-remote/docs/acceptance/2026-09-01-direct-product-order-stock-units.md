# PR-621 直接商品订单按商品单位预占与发货验收

## 现场复现

- 单一产出商品已有直接商品成品库存，例如盒装商品 `1盒`、批发商品 `1000袋`。
- 录单库存预览仍按旧 SKU 路径要求规格克重，返回 `spec required`；构造克重后又读取不到商品单位库存，显示可用量为 0。
- 放开预览入口后，订单保存仍调用旧生产规格解析并提示缺少销售规格或库存单位换算，无法进入发货。

## 修复合同

- 每次预览、保存、预占和发货都从商品迁移状态解析当前身份，不信任客户端补出的规格或克重。
- `spec_identity_mode=product` 统一规范为 `product_id` 加零 BOM 规格、零克重，需求量、可用量、预占量和扣减量全部使用商品单位。
- 成品库存没有可追溯批次行时使用 `PRODUCT-FP-<product_id>` 聚合批次；存在批次时继续按 FIFO 和质量状态选择。
- `legacy_sku` 保持克数合同，`bom_spec` 保持精确规格单位合同；库存不足、身份不合法或数据库错误整笔失败。

## TDD 证据

- RED：`TestOrderAPIDirectProductStockUsesInventoryUnitsThroughShipment` 首先得到 HTTP 400 `spec required`；第一次实现预览后，保存继续以“缺少销售规格或库存单位换算字段”失败。
- GREEN：同一真实 PostgreSQL API 测试完成 `3盒 -> 预占2盒 -> 发货余1盒 -> 无预占兜底发货余0盒`，并断言订单预占、扣减和库存流水均为商品单位，BOM 规格与克数字段为 0。
- 回归：旧 SKU FIFO 克数、旧成品库存聚合、保存预占和 BOM 规格单位扣减四条真实 PostgreSQL API 测试与直接商品用例同时通过。
