# PR-620 录单客户商品引用与专属价格匹配

## 现场复现

- 商品档案中已有有效客户引用，客户专属工厂供货价格表也已发布。
- `/api/order/form?customer_id=<id>` 只生成公共商品行，`customer_id=0`；客户专属发布查询因此没有客户作用域键，商品阶梯价为空，录单搜索不到可售商品。

## 修复合同

- 有效 `product_customer_references` 投影为客户作用域录单商品，携带客户显示名、客户货号、原商品单位、规格家族及商品规格身份。
- 客户专属已发布工厂供货价格表继续作为唯一取价来源，客户引用本身不提供价格。
- 同客户、同商品家族存在旧客户商品别名时保持旧别名优先；客户引用与公共商品行均不重复。
- 无效引用、失效商品和其他客户引用不进入当前客户目录；历史订单与价格快照不改写。

## TDD 证据

- RED：`TestOrderAPIFormUsesProductCustomerReferenceForCustomerPublicationTiers` 返回公共商品身份 `customer_id=0`，未得到客户引用身份与价格阶梯。
- GREEN：同一真实 PostgreSQL API 测试返回唯一客户商品行，客户显示名、客户货号、订单单位、发布 ID 和阶梯价格正确；补入旧别名后仍只返回一行且旧别名优先。

## 发布与生产验收

- 开发和生产发布前均运行仓库发布门禁，部署精确的已推送提交并保留回滚证据。
- 部署后先只读核对目标客户的订单表单商品与价格表发布来源；业务写入只在当前已授权的挂耳全流程目标中继续执行，并逐项核对订单、库存、发货和操作日志。
