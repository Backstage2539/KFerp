# PR-625 手工商品 BOM 发布与录单件数档位修复验收记录

## 范围

- 允许完整的手工商品 BOM 规格组在没有模板来源时发布，同时保留模板来源完整性校验。
- 修复 ERP 录单对价格表接口 `min_qty/max_qty` 的读取，并按 BOM 规格库存单位展示件数档位。
- 合入 `develop/main`，部署开发和生产；部署后由 Van 执行业务页面验收。

## 复现与 RED

- 生产 BOM `商品-速溶-黑咖` 为手工维护的盒装/条装规格组，模板来源和规格主体物料均为空；旧发布校验返回 `product BOM version requires a specification group copied from a published specification template with an active main input material`。
- 生产公共价格表 V3.0.17 中，曜石2.0 454g 袋装包含 2–13、14–23、24–47、48+ 四个件数档，最终价依次为 59、56、50、47 元/袋；ERP 前端读取不存在的 `min/max`，50 袋错误命中首档，阶梯标签显示 `0g 全部数量`。
- PostgreSQL 回归在修复前以相同英文模板错误失败；Vue 回归在修复前把 50 袋解析为首档 59 元/袋。

## 实现与 GREEN

- 手工规格组的模板来源版本和主体物料都为空时跳过来源校验；只有一项存在时拒绝；两项都存在时继续验证模板发布历史和物料有效状态。
- ERP 阶梯匹配兼容 `min_qty/max_qty` 和旧 `min/max`；销售规格件数阶梯省略重量前缀，并从有效 BOM 规格读取袋、盒等库存单位。
- Vue `order-entry.test.js` 全部 134 项通过；真实 PostgreSQL 的手工发布、默认绑定、部分来源拒绝、历史已发布模板兼容等 5 项回归通过。
- 在生产数据的隔离副本中，用曜石2.0、454g、50 袋和 V3.0.17 走小程序下单接口返回 201，并选用 47 元/袋；隔离副本随后销毁，生产业务数据未写入。

## 发布边界

- 代码部署不发布或修改业务 BOM、价格表与订单，也不回算历史快照。
- 容器、入口和受保护接口健康检查由自动发布验证完成；ERP 与小程序页面的最终业务验收由 Van 执行。
