# PR-659 小程序分享入口与范围设置验收记录

## 问题与结论

生产环境使用的小程序包没有注册页面级 `onShareAppMessage` 和 `onShareTimeline`，微信不会向页面提供右上角转发入口。该缺口同时存在于修复前的 `main` 与 `develop` 源码，单独重启 ERP 服务不能恢复。

本次为所有页面注册统一分享回调，并新增服务端分享范围。默认范围为“员工可以分享”；员工管理员可在个人中心改为“管理员可以分享”或“所有人可以分享”。分享卡片固定进入 `/pages/index/index`，不携带订单、客户或当前业务页面参数。

## 自动验证

- 后端策略：覆盖默认值、游客、客户、普通员工、管理员、三档范围、非法值和保存权限。
- 操作日志：首次保存的旧值按“员工可以分享”记录；旧新值使用中文范围，配置与日志沿用同一事务。
- 小程序：覆盖允许时同时显示转发与朋友圈、拒绝时同时隐藏、匿名与带令牌接口调用、管理员保存参数，以及个人中心三档文案。
- 工程检查：后端全包、miniapp 245/245、类型检查和 production 环境构建通过；构建产物包含全局分享回调和三档设置文案。

## 发布边界

本次可把源码合入 `develop`，但不上传或发布微信正式版。ERP development/production 服务部署与微信小程序上传是两条独立链路；只有 production 包经微信平台上传、审核并发布后，生产用户才会看到本次变化。

## 真机验收

1. 管理员进入个人中心，依次保存三档范围，核对成功提示和操作日志。
2. 分别用管理员、普通员工、客户和未登录访客进入任一页面，核对右上角“转发”和“分享到朋友圈”与设置一致。
3. 接收分享卡片，确认进入小程序首页；卡片路径不含订单号、客户编号或业务页面参数。
4. 断网后重新显示页面，确认未知策略不会意外开放分享；恢复网络后重新进入页面可恢复。

业务验收负责人：Van。正式微信版本号、上传时间、审核结果与回滚版本在明确发布后补录。
