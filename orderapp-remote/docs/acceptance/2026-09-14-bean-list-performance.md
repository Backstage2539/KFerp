# PR-662 商品价格表接口性能优化验收证据

## 问题复现与根因

- 生产旧版本公网请求复现：客户 450 首字节约 20.89 秒，公共表首字节约 6.87 秒。
- 客户主查询 `EXPLAIN ANALYZE` 为 12.27 秒，其中 PostgreSQL JIT 生成、优化和发射约 12.23 秒。
- 公共主查询关闭 JIT 后仍约 8.13 秒；`bom_unit_cost` 被执行计划内联并重复计算。

## RED / GREEN

- RED：新增回归测试后，成本仓储缺少 `queryCostingReadRows`，测试包编译失败。
- GREEN：主查询进入短只读事务并执行 `SET LOCAL jit = off`；`bom_unit_cost AS MATERIALIZED`；规格补充使用实际父商品 ID。
- 真实 PostgreSQL：单连接池连续请求、会话 JIT 恢复、失败、取消及 6 路并发全部通过。
- 真实 PostgreSQL 性能回归强制覆盖自定义执行计划与通用执行计划；每组均包含首次请求和连续请求，并校验完整响应摘要一致。
- 隔离临时表分别构造与生产公共表商品数同量级和十倍数据，使用执行计划确认物化 BOM 汇总节点 `Actual Loops = 1`，并记录耗时增长。
- 相关包：成本仓储、成本应用服务和成本 HTTP API 测试全部通过。

## 生产数据只读性能与一致性

- 修改后代码直接连接生产数据库只读执行，各 20 次：
  - 客户 450：最小 28.81 ms，中位 29.47 ms，P95 107.34 ms，最大 192.96 ms。
  - 公共表：最小 184.28 ms，中位 188.86 ms，P95 243.61 ms，最大 250.61 ms。
- 强制执行计划复测，各场景 20 次并核对完整响应摘要：
  - 自定义计划：首次客户 193.44 ms、公共 335.50 ms；P95 客户 126.85 ms、公共 385.64 ms。
  - 通用计划：首次客户 186.87 ms、公共 190.22 ms；P95 客户 34.59 ms、公共 214.82 ms。
- 隔离库物化汇总：31,400 行耗时 9.28 ms，314,000 行耗时 125.04 ms（13.48 倍）；两种规模聚合节点均仅执行 1 次。
- SQL 优化前后完整输出字段摘要一致；客户 450 返回 9 项且均为“曲奇”，公共表返回 314 项。
- 生产部署前 API 基线：客户 450 为 9 项、公共表为 314 项，“曲奇”两者均为 9 条规格；部署后再次比对完整响应摘要。
