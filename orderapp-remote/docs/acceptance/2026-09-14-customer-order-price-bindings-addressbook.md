# PR-664 客户下单价格表统一配置与地址簿验收记录

## 交付范围

- 一件代发和商品下单按客户、商品类型、入口绑定具体价格表发布记录；客户入口不再回退公共表或自动切到新版。
- 商品价格表客户视图维护两个入口的指定版本，门户客户配置删除旧选表入口；绑定版本禁止归档和永久删除。
- 小程序和 ERP 客户工作台统一“商品下单”，使用多商品、规格、地址、服务端报价和正常 ERP 订单链路。
- ERP 客户档案和小程序个人中心维护同一客户地址簿，支持解析、搜索、默认、并发控制及操作日志。

## RED / GREEN

1. 新增销售应用测试后，旧选表逻辑仍会把公共默认表补入客户目录，RED。改为只接受当前客户明确绑定的 publication ID 后 GREEN；同一类型传两张表、公共表或其他客户表均拒绝。
2. 新增真实 PostgreSQL 测试后，首次运行发现客户 ID 直接绑定文本字段会触发参数编码错误，RED。把客户 ID 显式转换为 bigint 后再比较文本 owner key，价格表绑定和地址簿事务场景均 GREEN。
3. 旧 ERP 和小程序界面测试仍要求“适用于一件代发”、现货下单选表和历史收件人聚合，RED。更新为价格表页指定、商品下单通用面板与客户地址簿后，ERP 前端 1242 项、小程序 250 项全部 GREEN。

## 业务验收步骤

1. 进入“商品 → 商品价格表”，选择客户陈丹燕和对应商品类型，把“一件代发”指定为“陈丹燕价一件代发格表 · V3.0.41”。确认商品下单可独立保持未指定或指定同一表。
2. 登录陈丹燕小程序，一件代发只能搜索到 V3.0.41 中三个商品。尝试表外商品请求应被拒绝；发布新版后仍显示 V3.0.41，直到 ERP 重新指定。
3. 打开商品下单，确认首屏为收件信息、商品明细、金额摘要、备注和提交，无价格表选择器；多商品提交后 ERP 只出现一张正常订单。
4. 在客户档案新增地址并设为默认，小程序“个人中心 → 收件地址”应同步显示；小程序新增或修改后 ERP 同步。临时修改本次地址不新增地址簿记录，历史订单收件信息保持不变。
