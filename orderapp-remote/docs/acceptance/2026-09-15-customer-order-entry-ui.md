# PR-665 客户端录单界面重构验收证据

## 实现结果

- 一件代发和现货下单共用 `CustomerDirectShipPanel`，页面顺序与员工录单一致；商品仍使用共享搜索/分类弹层，规格改为独立列表并显示全部真实名称、默认项和排序。
- 收件客户从主录单页移出。已有地址在底部选择器搜索，新建和编辑进入独立页；可仅写入本单快照或保存到当前客户共用地址簿。Pinia 草稿按客户和用途隔离，页面往返保留录单。
- 当前绑定价格表新增独立只读预览页和 `GET /api/mini/order-price-tables/preview`。服务端只接受用途，客户身份来自登录上下文；返回内容来自同一指定发布版本。
- 客户订单新增可选 `order_date`，空值按上海当天。共享 ERP 订单的订单日期和单据日期使用该值，幂等内容包含日期。
- 客户页面不提供单价、运费、优惠或选表；数量变化自动预览服务端价格，提交时继续重新核价并校验报价签名。

## RED / GREEN

- RED：应用测试因缺少发布 BOM 规格映射、价格表预览模型和 `order_date` 编译失败；小程序测试因缺少草稿 store、收件客户工具和两个新页面失败。
- GREEN：相关应用、API、PostgreSQL 和 HTTP support 包通过；`scripts/verify_kferp.sh backend` 全量 Go 测试通过。
- GREEN：小程序 42 个测试文件、255 个测试全部通过；TypeScript 类型检查和 development 微信构建通过。
- GREEN：员工端 Vue 1242 个测试和 production 构建通过；`scripts/verify_kferp.sh changed` 通过。
- 390px 小屏渲染检查覆盖代发录单、收件客户选择层、规格选择层和只读价格表。主界面与两个弹层无横向溢出；价格表仅在表格容器内横向滚动，页面无选择和下单控件。现货下单复用同一组件，只替换标题、用途、价格绑定和提交接口。
