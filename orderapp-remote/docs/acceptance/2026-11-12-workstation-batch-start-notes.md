# 工位批次、补料、多工单开工与订单工序备注（PR-766）

## 范围与进度

- 截图中的 156 工单现已完成；正式数据仅只读排查，不代用户操作。批次预览从冻结安排读取；旧任务预览不初始化或扣料。
- 实际开工缺口按当前投入计算，补料生成草稿并在工位确认入 WIP。超缺口部分保留为自由 WIP，已固定批次不可静默替换。
- 工位逐工单选择，可跨规格、跨客户统一开工；工单独立扣料、记成本，合并完成入库继续受原规格约束。
- ERP 与客户网页商品行保存结构化工序备注；依据制造节点、规格及工序身份冻结，历史快照不被覆盖。已有供应工单无法执行新备注时阻止静默复用。

## 开发验证

- 定向 RED/GREEN：旧补料漏掉实际投入超原预留缺口；跨规格统一开工被错误拒绝；旧客户端快照恢复缺少新字段；跨工单切换沿用旧预览；客户账号越权读取 ERP 工序候选。
- 隔离测试覆盖 65.384 kg 在 WIP、65.625 kg 实际需求、补料 0.241 kg 及多调、库存变化、固定批次保护、幂等和多仓回滚。
- 跨规格接口测试覆盖整组回滚、逐工单用料及幂等；商城真实 HTTP 到数据库保存和规格版本冲突；订单备注冻结至上游与包装、历史快照保留及在产供应校验。
- 页面本地模拟桌面/390px：逐单开工、工序备注、规格切换输入保留、409 后刷新核对；截图与脚本 `/tmp/kferp-operation-notes-ui/`。
- 前端全量 2009 项、构建及无业务库 Go 全量通过。隔离旧客户端真实 HTTP 编辑验证重建后保留备注、显式清空和操作日志。
- 不同客户、真实不同 BOM 规格/版本、不同包装材料与同一半成品批次的合并开工 API 验证各单扣料及成本、错误整体回滚、重复提交不重复扣料。
- 正式发布及用户业务验收待完成；后端无数据库全量测试中数据库用例按现有规则跳过，隔离用例证据不等同正式业务操作。
