# 工位开工区域精简

需求：`PR-WORKSTATION-START-SIMPLIFY-20261113`；待用户业务验收。

- 删除工位卡“确认本批开工用料”区域。点击任务标题只读展开逐批计划；点击“开工”先读取计划和实时可用库存，再以该计划投入提交开工。已有后续逐批录入及合并开工入口保留。
- 若有真实缺口，打开当前页补料窗口，不执行开工；转仓后由操作人员重新点击开工。按来源批次、货主、质检、库存、工序状态和权限继续校验。历史不完整 BOM 需采用更新版本时，列出版本和物料并先征求确认。
- 开工请求保存在当前浏览器会话；结果不明时同一员工可重试原次请求，避免重复扣料。后端仅对确认尚未提交的失败标记 `not_committed`；事务提交结果不明或原请求标识冲突继续保留原请求。
- RED：删除区域的渲染断言、单击开工能力及 BOM 更新确认测试在实现前失败；版本冲突的隔离 HTTP 测试原先没有返回明确的未提交状态。
- GREEN：隔离 PostgreSQL/HTTP 覆盖首道工序扣料及逐批结转、零库存补料、库存来源、称量精度、质检、货主、过期版本、并发幂等、日志失败和回滚。Vue 全量测试、生产构建及无业务数据库 Go 测试通过。
- 1440×900 与 390×844 的隔离模拟页面显示批次预览且不再显示用料表单；窄屏无横向溢出，模拟开工后状态更新。生产手册同步更新。
- 本次验证没有对正式环境工单、库存或报工作写操作；发布后仍须由现场人员验收。
