# 服务号订单通知自动识别验收

需求 PR-WECHAT-AUTOBIND-20261122。目标为客户和销售登录后选择服务号通知，系统识别微信关注身份，并在发货后按订单权限发送。

## 待验收

- 同一开放平台绑定服务号和小程序后，新关注、历史关注、先登录后关注、退关及重关注分别完成真机验证。
- 客户及销售分别使用隔离测试订单验证服务号送达、内容和订单详情跳转。
- 分批发货须确认每个运单对应的商品及数量。现有发货记录未保存逐运单商品明细，不能从整单明细推断本批内容。
- 下单、生产开始、生产完成、取消模板和生产群验收沿用原待办。

本记录在实施期间保留待验收状态，实际测试结果、部署版本及限制由交付时补充。

## 本地验证记录

- 微信关注者分页和资料批量读取使用模拟微信接口验证。
- 小程序全量测试 564 项通过，类型检查与开发版构建通过。
- 消息中心、通知接口及服务号接口在隔离 PostgreSQL 定向测试通过；实际 portal 客户和员工的关注后身份匹配集成测试通过。
- 后端全量 `go test ./...` 通过。启用隔离 PostgreSQL 对完整 appmain 和 customerportal 包运行时，出现物流重量、生产路线及测试数据库表缺失等失败；尚未逐一定位。
- 部分发货缺少可信本次商品明细时记录失败，旧待发任务同样拦截。发货入口未记录本批数量，仍需补齐该流程。
- 新旧发货事件同一订单同一事务去重，隔离数据库测试覆盖并发及旧用户回退。
- ERP 前端全量测试 2044 项及构建通过。
- 开发部署与微信真机验收尚未完成。
