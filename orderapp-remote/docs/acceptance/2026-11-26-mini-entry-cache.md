# PR-775 员工录单与选商品验收

## 开发者工具计时

微信开发者工具 2.02.2607271，模拟器基础库 3.17.6。使用同一台 Mac 和本机隔离的 PostgreSQL，目录包含 120 个商品。模拟器通过自动化连接调用实际 ERP 只读接口，使用专用测试员工和合成客户。生产反馈的约 3 秒没有作为基线样本。每个场景采集 20 次，P95 取排序后的第 19 个值。

在两版小程序的实际点击回调记录起点，使用微信原生布局回调确认控件显示、选择完成。两版采用相同的测试员工、数据、界面步骤和计时方式，各重复 20 次。

| 原生界面计时 | 旧版 P95 | 生产候选 P95 | 目标 |
| --- | ---: | ---: | --- |
| 重复进入录单，可打开客户搜索 | 1010 ms | 2353 ms | ≤1000 ms，未达标 |
| 打开商品选择器，可输入关键词 | 594 ms | 255 ms | ≤300 ms，达标 |
| 点选商品到完成核对并关闭选择器 | 133 ms | 588 ms | 单独记录 |

另一组在开发者工具自动化端计时，含工具发出点击及观察界面的开销。两组均保留全部样本。

前三行使用从录单实际返回首页的操作路径，计时包含开发者工具自动化调用和界面观察。冷启动以每次小程序 JS 实例重新启动为起点，经过员工首页进入录单。旧版冷启动 P95 为 11936 ms。两个冷启动结果都包含自动化工具重新连通隔离接口的耗时。清除录单内存缓存与重启小程序的样本分别列出。

旧版重复打开商品选择器 20 次，请求完整表单 20 次。生产候选重复打开并选用 20 次，完整目录 0 次，轻量核对 40 次。旧版从重新进入首页开始的对照组，重复录单 P95 为 1194 ms，选品 P95 为 667 ms，点选回填 P95 为 118 ms。旧版点选回填没有新版的选用前价格核对。

## 接口与正确性

- 生产候选构建的本机 HTTP 测试中，完整目录为 513071 字节，同版本响应为 65 字节。目录版本核对 P95 为 15.1 ms，基础资料版本核对 P95 为 17.9 ms。旧版完整表单接口继续返回客户、商品与价格。
- 首次 RED 复现了新接口 404 和缺少客户端缓存。后续 RED 复现了同一员工重新登录后复用收件资料版本，以及默认表、显式选表和偏好选表同时读取时执行三次完整读取。修正后等价选择共用一次完整读取，并通过 Go race 检测。
- 隔离 PostgreSQL 测试验证了版本发布、撤回、事务回滚、客户隔离、收件资料变更以及停用客户。客户端测试覆盖缓存命中、并发核对、失效会话、草稿恢复以及历史订单冻结价格。
- 开发提交 `ed65d4a6` 已部署，外网登录页返回 HTTP 200，开发分支通过 2083 项 Vue 测试和 586 项小程序测试。生产候选通过 580 项小程序测试、类型检查、生产构建及全量 Go 测试。
- 员工操作说明见[员工小程序 ERP 手册](../OP_MANUAL_MINIAPP_EMPLOYEE_ERP.md)。本次测速没有创建、提交或修改生产业务单据。
