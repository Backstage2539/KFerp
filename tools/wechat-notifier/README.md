# KFerp 专用 Mac 微信群发送端（待现场适配）

当前电脑微信没有可用的聊天控件树，且测试过程中曾要求重新登录。没有已验证的控件配置；本发送端不得作为已通过真实微信验收的成品启用。它不注入微信进程，不读取微信数据库，不使用坐标或键盘盲输，不绕过安全提示。

## 构建与验证

运行 `./build.sh`，使用 macOS 开发工具编译程序和独立守卫测试。输出位于 `.build/`。此步骤不会启动微信或发送消息。若系统开发工具遗留了重复的 SwiftBridging 模块声明，构建脚本仅在临时编译文件视图中排除重复声明，不修改系统文件。若系统 SDK 与编译器不匹配，构建会失败；需先修复本机开发工具，不能把源码检查当成编译通过。

## 连接（真实微信适配完成后）

ERP 设置 → 通知配置 → 连接专用 Mac，填写设备名及唯一群名。使用 `.build/WeChatNotifier pair development`，交互输入一次性凭据，保存到当前 Mac 钥匙串。生产环境参数为 `production`，应与服务器的配对记录对应。凭据不通过命令行参数或日志输出。

发送进程为 `.build/WeChatNotifier run development /absolute/path/verified.profile.json`。保持微信当前目标群在前台且电脑解锁；存在草稿、错误目标、控件不可读或版本变化时暂停。没有默认控件配置，不能编造控件名称填入以绕过校验。须通过受支持的界面检查获得真实、唯一的 AXIdentifier，并验证这些控件在当前版本确实表示相应语义。

配置字段：`version` 为微信 CFBundleVersion；`titleID` 群标题、`groupIndicatorID` 和 `groupIndicatorValue` 确认群聊、`composerID` 输入框、`sendButtonID` 发送按钮、`historyID` 当前聊天记录容器、`sentMessageID` 已发送成功记录的可读控件标识。最后一项必须能区别待发送和失败气泡，不能仅凭输入框清空判断发送成功。只有唯一匹配才可动作。Mac 辅助功能权限由用户在系统设置中授予。

程序先向服务器领取一次性租约，设置并读回完整草稿，再核对当前群，最后执行发送按钮；读取成功消息后上报相同全文。发送后结果不明不自动重发，服务器租约过期也会进入未知状态并暂停群队列。配对令牌可在 ERP 撤销。程序二进制与配置的摘要随心跳上报，变化后原六类验证失效。

上线前必须在指定测试群逐项发送六类标注测试的虚拟订单、检查群名、内容、无重复，并演练锁屏、断网、退出、窗口切换、草稿及进程中断；随后从隔离订单状态变更触发验证。不使用真实业务订单做状态写入。当前没有任何真实微信群送达通过记录。
